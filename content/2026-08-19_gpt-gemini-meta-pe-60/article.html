在過去十年的雲端與移動互聯網時代，華爾街評估科技巨頭的黃金法很簡單：自由現金流收益率（FCF Yield）。

軟體與平台具備高毛利與規模經濟，科技巨頭能將 60% 到 80% 的淨利轉化為自由現金流，並透過巨額回購推升股價。

它們是名副其實的「印鈔機」。

但到了 2026 年，這個方法失效了，巨頭們的自由現金流消失了。

第零章 | AI的四層價值鏈與估值重構

自由現金流的公式極其簡單：FCF = 營運現金流 - 資本支出 (CapEx)。

當資本支出大幅增加，計算出的自由現金流自然迅速收縮，甚至轉為負值。

看看 2026 年第二季的數據：

  • Alphabet： 單季砸下 449 億美元 CapEx，導致單季 FCF 首度轉負（-59 億美元）。

  • Meta： 單季 CapEx 達 311 億美元，FCF 暴跌 91%，僅剩 7.84 億美元。

  • 亞馬遜與微軟： 同樣承受巨大的資本壓力，部分季度 FCF 承壓或必須依賴會計手段（如拉長折舊年限）來維持帳面正數。

如果你拿著傳統的 FCF Yield 模型去衡量這四家公司，得出的結論只有一個：它們正在毀滅價值，股票應該全部賣出。

0.1 四層價值鏈

但 CapEx 其實有兩種。

有些 CapEx 是維持現有業務的「維護性消耗」，這種花費無法帶來額外增長。四大巨頭大部分的 CapEx，屬於「成長性投資」，理論上這些支出在未來會帶來回報。

問題在於：公司說是「成長性投資」，就真的算成長性投資嗎？

因此，我們需要一個框架。而在評價巨頭時，我認為有四層重點，決定了CapEx 的品質。

因此我們需要一個檢驗框架。在評價巨頭時，我認為有四個關鍵收費站，決定了 CapEx 的最終品質：

  • 矽（Silicon）： 誰能控制單位 Token 的成本底線？在 Token 價格長期走低的環境下，擁有自研晶片（如 TPU、Trainium）是防守毛利率的唯一護城河。

  • 模型（Model）： 誰掌握了前沿能力？是自研突破、深度綁定合作夥伴，還是到處花錢租用？這直接決定了議價權與對外依賴度。

  • 分發（Distribution）： 誰擁有無法流失的原生需求？搜尋、社交等自有流量永遠不會取消訂單，這是營收確定性的終極保證。

  • 變現形式（Monetization）： 收費模式是軟體席次費、算力消耗量，還是廣告費？這決定了營收的可預測性與現金流品質。

看懂這四個收費站，我們就能明白，為什麼同樣是砸錢蓋資料中心，四家公司的回報路徑卻有著天壤之別。

0.2 估值框架的重構：PE 與 SOTP 的匹配原則

既然四家公司的商業本質與風險特徵截然不同，我們就絕對不能用同一套尺去衡量它們。

散戶最喜歡犯的錯誤，就是把它們放進同一個 P/E 表格裡直接比較，然後得出結論：Meta最便宜所以買入，亞馬遜最貴所以不值。

面對這四家公司，我會拆分為兩種估值方法：

  1. 業務高度交織：標準化 P/E（整體估值法） 如果一家公司的各業務線共享底層基礎設施、產品互相捆綁銷售，強行把它切開估值只是循環論證。微軟和 Meta 屬於這一種。

  2. 業務高度獨立：SOTP（分部加總估值法） 如果各業務線的風險特徵完全不同、利潤率差異巨大，把它們攪在一起算平均數會掩蓋真實價值。亞馬遜和 Google 屬於這一種。

框架已經建立。接下來的四章，我將會極為深入地和大家分析每個巨頭在做甚麼、背後的投資邏輯，以及現在的估值究竟包含了甚麼：

  • 微軟： 探討當「獨家代理權」退化為「最好的通路」時，如何用標準化 P/E 定價。

  • 亞馬遜與 Google： 這將是一場 SOTP 的實戰演練，切開它們龐大的身軀，找回被掩蓋的利潤引擎。

  • Meta： 展開一場關於廣告營收曲線與折舊曲線「誰跑得快」的終極博弈。

第一章 | Microsoft：從「獨家代理」到「最好的通路」

打開微軟的財報，官方在架構上清晰地劃分為三大業務板塊：「智慧雲端」（Intelligent Cloud）、「生產力與商業流程」（Productivity and Business Processes），以及「更多個人計算」（More Personal Computing）。

「更多個人計算」，其實就是Xbox遊戲、Surface消費性硬體與部分搜尋廣告。

很明顯，這塊業務既不與當前的 AI週期正相關，佔整體營業利益的比重也很低，因此我們不需要浪費時間處理這部份。

因此，我們將目光放到「智慧雲端」和「生產力與商業流程」。

1.1 商業本質：高度交織的兩個部門

「生產力與商業流程」，本質是「應用層 SaaS」。

它包含了全球企業日常運作離不開的 Microsoft 365（Word、Excel、PowerPoint、Teams、Outlook）、企業資源規劃與客戶關係管理軟體 Dynamics 365，以及專業職場社群 LinkedIn。

這塊業務的商業模式主要以「按人頭計費的訂閱制」（Per-seat Subscription）為主。

而「智慧雲端」，本質是「底層基礎設施與平台（IaaS / PaaS）」。

其最核心的增長引擎是 Azure 公有雲，同時涵蓋 Windows Server、SQL Server 等伺服器產品，以及開發者平台 GitHub。

這塊業務的商業模式以「用多少付多少的算力與儲存消耗制」（Consumption-based）為主。

當然，我們可以將兩者分開，對「生產力」套用純 SaaS 軟體的倍數，對「智慧雲端」套用純雲端基礎設施的倍數。

但在真實的商業運作中，這兩大分部根本切不開，因為它們在底層高度交織、互為表裡：

1. 共用算力骨幹與 CapEx 黑盒子

微軟每年投入數百億甚至上千億美元的資本支出（CapEx）採購 GPU、興建超大規模資料中心與鋪設全球光纖，這些成本在底層是完全共享的。

當企業員工在 M365（生產力板塊） 裡點擊 Copilot 生成一份簡報或摘要郵件時，背後每一次 AI 推理消耗的，全都是 Azure（智慧雲端板塊） 的算力叢集。

你無法在財務報表上乾淨地切分：哪一張 GPU 是用來賺取 Azure 的雲端租賃收入，哪一張是為了支撐 M365 的軟體後端運作。

強行切分兩者的成本與折舊，只會得出失真的分部毛利率。

2. GTM（業務拓展）與企業級鐵三角的捆綁銷售

微軟的銷售團隊拜訪跨國企業 CIO 時，談判桌上擺的永遠是標準的捆綁式銷售。

企業簽署微軟企業協議（Enterprise Agreement）時，通常是一攬子打包了 Azure 雲端承諾消費額、M365 辦公套件席次、GitHub 代碼平台，以及橫跨全端點的 Entra ID / Defender 企業安全防護。

客戶之所以願意在 Azure 上擴大支出，是因為他們的員工每天都在 M365 上辦公，兩者在數據流通與身份權限管理上天生無縫。

反之，企業大規模採購 M365 Copilot，又會反向鎖定 Azure 作為企業內部唯一的數據與模型底座。

3. 業務相關性趨近於 1，SOTP 失去增量資訊

在市場上，你找不到任何一家「只賣雲端算力卻不賣任何軟體與身份驗證」的純對標公司，也找不到一家「只做辦公軟體卻擁有全球頂級資料中心與自研晶片」的獨立 SaaS 巨頭。

「智慧雲端」與「生產力與商業流程」的相關性趨近於 1：

  • AI 週期順風時： 企業既加購 M365 Copilot 席次（生產力分部），又在 Azure 上調用更多模型 API（智慧雲端分部），兩者同步加速。

  • 企業縮減 IT 預算時： 企業會同時精簡軟體授權席次並減少雲端資源消耗，兩者同步承壓。

強行用 SOTP 將這兩個官方分部切開並分別給予乘數，只是把市場早已隱含的綜合估值人工拆散再加總，毫無增量資訊。

因此對於微軟，我們直接使用整體標準化的 Forward P/E 來評估，才是最符合其商業本質且最誠實的估值方式。

1.2 戰略重構：從「獨家代理」到「成本-產出」的毛利防守戰

在財報會議上，CEO Satya Nadella 用一句話定調了微軟的 AI 戰略：

「我們正在推進成本-產出曲線的前沿，確保每個客戶都能將 Token 轉化為商業成果。」

過去兩年，市場聚焦的是「模型到底能多聰明」，但在真實的企業市場裡，決定 AI 能否普及的關鍵是 ROI。

對企業來說，Token 就像是電費，如果調用大模型的成本高於它節省的人工工時，技術就無法大規模落地。

微軟所定義的「前沿」，是如何把解決具體商業問題的「每單位 Token 履約成本」壓到最低，而非無上限地燒錢追求 Benchmark 跑分。

這解釋了微軟近期的三大戰略動作：

1. 利潤流向反轉與資本解放

根據 4/27 修訂案，微軟停止向 OpenAI 支付營收分潤，改由 OpenAI 定期向微軟付款至 2030 年，但加上了總額上限。

同時，OpenAI 開始轉向 AWS 或 Oracle 採購算力，等於讓競爭對手替微軟分攤了高風險的訓練算力投資。

CFO Amy Hood 強調，微軟全年超過 2,140 億美元的雲端營收中，近 90% 來自前沿模型實驗室以外的實體企業客戶。

2. 議價權反轉與「企業級路由器」

如果市場上只有一家 OpenAI，微軟只是被綁定的經銷商。

但如今微軟雲端平台上架了超過 11,000 個模型，Nadella 指出「使用多供應商模型的客戶數自年初以來成長 5 倍」。

當各家模型在 Azure 上互相競爭，微軟便握有了壓低採購成本的議價空間。

未來的關鍵是一套能自動分流的「企業級路由器」：

約 90% 的常規需求（摘要郵件、基礎代碼），直接由成本極低的自研小模型（MAI）搭配自研晶片（Maia）處理；不到 10% 的複雜邏輯，才調用外部昂貴的前沿大模型。

在固定價格的訂閱制下，一旦模型品質跨過企業日常辦公「夠用」的門檻，模型能力再強 10%，微軟的席次收入也不會增加一毛錢。

但如果能把單次推理成本降低 80%，省下的錢直接落到營業利潤。

這就是微軟不必贏模型戰的全部理由。

3. 自研矽的實戰數學

在底層硬體上，微軟推出了 3nm 製程的自研晶片 Maia 200，走「推理優先」路線。

這套「固定收入（30美元/月訂閱）、變動成本（推理算力）」的商業數學，已在實戰中展現威力：

  • PowerPoint 圖像生成： 透過自研模型，GPU 成本降低最多 84%。

  • GitHub Copilot（MAI-Code-1-Flash）： 程式碼採納率較 GPT-5.4 Mini / Claude Haiku 4.5 高約 10%，中位 token 用量少 10%。Amy Hood 明確證實，Azure 超預期的部分原因，正是歸功於 GitHub Copilot 商業模式變更後、消耗量強於預期。

現實檢驗：毛利型護城河是中期論點

這套以極致成本為核心的模式，是微軟的長期目標。事實上，當季財報尚未反映這一成果。

目前微軟仍處於重資本投入期：Microsoft Cloud 毛利率降至 65%，Azure 毛利率約 47.5%。單季資本支出達 410 億美元（年增 70%）。

自研小模型與晶片帶來的成本效益，目前仍難以完全抵消 AI 伺服器折舊帶來的短期毛利壓力。

這份成本紅利，要在資本支出週期見頂回穩後，才會真正反映在未來的利潤率上。

1.3 估值濾鏡：盯緊 60 億美元的「真帳單」

因為持有 OpenAI 約 27%的複雜股權，每當 OpenAI 進行重組或融資，微軟帳面上就會憑空多出幾十億美元的「紙上收益」；而當 OpenAI 擴大研發虧損，微軟又得在帳面上按規則認列一部分損失。

因此，面對微軟，看官方提供的 「調整後非 GAAP 營運 EPS」（Adjusted EPS） 會更為準確。

真正值得我們認真看待的，是財報附註裡首次揭露的兩筆真實商業帳：

營收集中度（比想像中健康）：

FY26 全年，微軟從 OpenAI 身上收取的商業協議與雲端分潤共 241 億美元。

對比 3,318 億美元的總營收，佔比僅約 7.3%；對比 2,140 億美元的雲端業務，佔比也只有 11%。

這證明微軟的雲端底座並不是靠 OpenAI 一家在充場面。

應收帳款（真正的信用底線）：

截至 2026 年 6 月底，微軟帳上對 OpenAI 的應收帳款高達 60 億美元。

這意味著微軟已經交付了 60 億美元的高級算力，但這筆真金白銀還沒全數落袋。

OpenAI 是否具備足夠的造血能力按時清償，才是微軟資產負債表上真正承受的信用風險。

1.4 估值邏輯：大道至簡的 P/E

既然我們確立了微軟不適合用 SOTP 拆解，那麼它的估值公式其實非常簡單：

合理股價 = 合理的 P/E 倍數 × 調整後的非 GAAP EPS

但這裡的關鍵是：市場願意給微軟多少倍的 P/E，完全取決於它認為這場「成本戰」的勝率有多高。

當前華爾街共識的 FY27 調整後 EPS 大約在 $19-20 左右，然後你可以根據以下三種情境，填入你對未來 12 個月 EPS 的判斷，再乘上你認為合理的 P/E 倍數，就能得出自己的估值區間：

牛市情境（戰略兌現）：自研成本紅利爆發

如果 Copilot 滲透率超預期，且自研小模型（MAI）與自研晶片（Maia）成功大幅降低履約成本，讓雲端毛利率在資本支出見頂後快速擴張。

此時，EPS 將面臨顯著的向上修訂，且市場會因為「成本護城河」的確立而給予更高的 P/E 溢價（28 至 30 倍）。

基準情境（平穩過渡）：成本紅利尚未完全顯現

AI 平穩落地，Azure 增速因產能追上需求而自然回落。雖然營收穩健，但毛利率短期內仍受 AI 基礎設施折舊影響而小幅下滑。

此時，EPS 的增長主要來自常規的業務擴張與回購，P/E 倍數則維持在歷史中樞（22 至 25 倍）。

熊市情境（戰略落空）：被迫調用昂貴模型，毛利失守

如果企業客戶對 Copilot 的滿意度下降，微軟被迫重新大量採購昂貴的外部前沿模型，導致毛利率大幅承壓。

此時，EPS 面臨下修風險，且市場會因為其「成本優勢」邏輯破滅而壓縮其 P/E 倍數（18 至 20 倍）。

1.5 評估微軟的三個關鍵信號

微軟的整個投資邏輯能否兌現，本質上取決於一個清晰的推進過程：

首先確認企業端有真實需求，其次觀察大規模交付時的成本防守，最後等待資本支出見頂、利潤全面轉化為自由現金流。

這對應著以下三個依序發生的追蹤信號：

訊號一：需求端的真實動能——從概念驗證走向日常黏著

首先，我們要觀察企業端究竟是在跟風嘗試，還是已經將 AI 深度融入日常營運。

微軟雖然擁有 OpenAI 的獨家雲端合作，但要建立長期的企業平台價值，底層的算力消耗不能只仰賴單一合作夥伴，而必須看到廣大企業客戶的實質採用。

我們要觀察什麼：

  • Copilot 的實質活躍度： 在微軟約 4.5 億的 M365 商業席次中，即便帳面簽約達到 3,000 萬席（名義滲透率約 6.7%），若每週活躍使用率（WAU）落在 30% 至 55% 區間，實質活躍滲透率其實僅約 2% 到 3.7%。真實的日常使用頻率，比單純的簽約席次更能反映企業續約意願。

  • 排除單一夥伴的訂單動能： 觀察剔除 OpenAI 之後的「剩餘履約義務（RPO）」年增率（目前約 25%）與「商業合約總額（Bookings）」年增率（目前約 18%）。

信號解讀： 若實質活躍率持續低迷，且排除 OpenAI 後的合約增速回落至 15% 以下，意味著企業端的推進不如預期；反之，若合約增速維持在 20% 以上且活躍度穩步爬升，代表第一階段的「真實需求」順利過關。

訊號二：成本端的防守能力——自研架構能否守住利潤率？

第二個問題，交付這些推理服務的成本有多高？

在 AI 商業化過程中，微軟的定位是企業履約平台，其核心競爭力不在於永遠領先的前沿模型參數，而在於能否以最低的單位成本提供服務。

我們要觀察什麼：

  • 雲端毛利率的防守： 目前 Microsoft Cloud 整體毛利率約 65%，Azure 毛利率約 47.5%。微軟一方面面臨新增伺服器與資料中心的高額折舊，另一方面正嘗試導入自研小模型（SLM，如 MAI 系列）與自研晶片（Maia），試圖以更低廉的架構替代昂貴的大模型調用。

  • 內部工作負載的替換進度： 觀察管理層是否在 GitHub Copilot 或 M365 Copilot 中，實質擴大自研小模型處理日常任務的比例。

信號解讀： 若 Azure 毛利率跌破 45% 且自研架構滲透緩慢，代表微軟仍被迫依賴高昂的外部算力與模型授權，獲利空間將受到擠壓；若毛利率在資本支出高峰期能維持在 47% 以上甚至小幅改善，代表第二階段的「成本護城河」開始發揮效益。

訊號三：CapEx 拐點出現——資本開支向現金流的實質兌現

當需求與成本結構都獲得驗證後，最後一塊拼圖則是投資週期的收斂。

在擴張期，為了搶佔基礎設施先機，微軟每年投入數百億美元興建算力中心，巨額的資本開支自然會壓抑帳面上的自由現金流與短期利潤。

我們要觀察什麼：

  • 現金資本支出與雲端營收的增速差： 剔除延長折舊年限等會計口徑的影響，直接觀察「現金資本支出（Cash CapEx）」的年增率何時開始實質低於「雲端業務營收」的年增率。

信號解讀： 只要現金 CapEx 的擴張速度持續高於營收成長，折舊與現金消耗就會持續對 EPS 與現金流造成壓制；一旦出現增速反轉的拐點，意味著前期重資產投入已跨過擴建峰值、開始進入產能收穫期。

這時折舊佔營收比重將趨於穩定，自由現金流顯著回升，微軟的獲利能力與估值體系才會迎來最紮實的擴張。

第二章 | Amazon：所有模型必經的計費層

在過去十多年裡，AWS 一直坐在全球雲端運算王座上，定義了現代互聯網的底層架構。

但在生成式 AI 風暴初期，市場曾經質疑，亞馬遜是否掉隊了？

我們先直接看最新一季的數字。

2.1 數據說話

Q2 2026，亞馬遜創下首個單季營收突破 2,000 億美元的里程碑：

  • AWS 營收年增 36.7%，創近 18 季最快增速；Backlog 膨脹至 4,960 億美元。

  • AWS 單季營業利潤率回升至 39.4%（剔除約 6 億美元能源合約利得後，年增約 520 個基點）。

  • 自研矽晶片業務年化營收達 250 億美元，保持三位數增長。

這組數字清楚證明了一件事：亞馬遜並沒有在這場 AI競賽中落後。

但真正值得探討的是，驅動這波反彈的底層邏輯是什麼？這套模式又具備多少延續性？

2.2 Amazon 的核心定位：水平整合的收費站

作為雲端運算的既有霸主，亞馬遜在 AI 時代的第一目標非常務實：

守住既有客戶，確保企業不會因為想用 AI就轉投微軟或 Google 的懷抱。

微軟最初的打法是強推 OpenAI；而亞馬遜選擇了一條完全不同的路：它的策略是把 AWS 打造為「所有模型都能上架的計費櫃台」。

誰的模型最強，與它無關。

無論企業想用 Anthropic 的 Claude、Meta 的開源模型 Llama，還是歐洲的 Mistral，全都能在 AWS 的 Bedrock 平台上直接調用。

對亞馬遜來說，模型是誰做的不重要，重要的是客戶繼續留在 AWS 的系統裡，所有調用算力的帳單都由 AWS 開立。

但這套「水電收費模式」面臨一個問題：

  • 微軟賣的是「門票」： 微軟擁有 Windows 和 Office，可以把 AI 包進每位員工每個月的固定訂閱費（例如一人每月 30 美元）。不管員工用多用少，只要公司繼續營運，微軟就能穩穩收錢，甚至具備未來漲價的空間。

  • 亞馬遜賣的是「度數」： 亞馬遜沒有壟斷性的終端辦公軟體，只能像水電表一樣，按照客戶調用了多少文字與運算量（Token）來跳錶收費。

問題在於，隨著技術進步與晶片效率提升，每度電（Token）的單價長期必定會越來越便宜。

這意味著，亞馬遜要維持雲端帝國的成長，不能靠提高單價，唯一的活路是「薄利多銷」。

他們必須讓企業對在AWS上的 AI的總用量不斷增加，用「暴增的用量」去跑贏「不斷下跌的單價」，同時把每一次運算的硬體成本壓到極致。

為了守住這個獲利公式，亞馬遜在供給、需求與商務端各有準備：

  • 供給端： 靠自研晶片 Trainium 壓低每一次運算的硬體成本。

  • 需求端： 靠 Bedrock 平台聚攏各家頂尖模型，滿足企業客戶的多樣需求。

  • 商務端： 靠大企業既有的長期承諾合約（EDP），將模型用量直接鎖進 AWS 的計費體系。

接下來的三節，我們逐一拆解。

2.3 Trainium：現在是「省錢工具」，未來是「賣錢期權」

AWS 的營業利潤率在走出低谷後一路走高：從 2025 年 Q2的 32.9%，隨後幾季接連攀升至 35.0% → 37.7% → 39.4%。

這條利潤率的 U 型反轉，正是雲端基建的經典週期：

  • 前期痛苦： 大量採購昂貴的第三方 GPU（如輝達），伴隨龐大資本支出與折舊，直接壓垮利潤。

  • 後期收割： 大規模部署自研晶片 Trainium 後，每一次運算的成本大幅驟降，雲端利潤迅速修復。

這項底氣，來自亞馬遜早在 2015 年就收購的 Annapurna Labs。

目前 Trainium 的定位非常明確：它是 AWS 內部的「成本調控閥」，專門用來壓低每一次運算的硬體成本。

它的價值體現在取代高價外購晶片、直接拉高 AWS 的利潤空間與降價底氣，而非單獨的晶片營收。

但 CEO Jassy 在 2026 年中多次暗示，由於市場算力嚴重吃緊，亞馬遜未來很可能將整櫃的 Trainium 伺服器直接外售（例如賣給要求資料嚴格在地的歐洲「主權 AI」客戶）。

他甚至估算：如果晶片業務獨立對外營運，年化營收潛力將從目前的內部規模 250 億美元暴增至 500 億美元，直接躋身全球前三大資料中心晶片巨頭。

不過，這 500 億美元目前只能算是一張「尚未兌現的選擇權」：

  • 雲端的本質是「收租」： 租算力給客戶，能持續連帶收取儲存、網路、資訊安全與監控等高毛利週邊費用。

  • 賣晶片的本質是「賣斷」： 雖然一次性營收龐大，卻會稀釋長期的雲端單位效益。

加上亞馬遜內部對自研晶片的需求仍然供不應求，我們暫時應將外售視為潛在的「估值加分期權」，而非確定的獲利來源。

（我們將在第七章 Alphabet 的 TPU 單元中，回頭對照這兩家自研晶片的策略差異。）

2.4 Bedrock：不賣獨家，打造最中立的「AI 軍火大賣場」

Trainium 解決了硬體的「成本端」，但在軟體與大模型的「需求端」，亞馬遜靠的是 Bedrock。

回顧 2023 年初，微軟挾 OpenAI 搶盡風頭，Google 手握 DeepMind，亞馬遜在頂級大模型領域幾乎交了白卷。

為了打破「掉隊」的質疑，亞馬遜打出了一套組合拳：

  • 重押 Anthropic： 巨額投資這家 OpenAI 最強對手，並要求 Anthropic 將 AWS 作為主要雲端、深度採用 Trainium 晶片。這不僅直接為 AWS 帶來龐大算力消耗，更讓頂尖實驗室為自家晶片做了最強背書。

  • 開設中立大賣場： 亞馬遜深知多數企業不想被單一模型綁架。因此，Bedrock 平台定位為中立超市，Anthropic 的 Claude 是吸引頂級客戶的「旗艦招牌」，同時架上擺滿了 Meta 的開源 Llama、歐洲的 Mistral 以及自研的 Nova 模型。

這再次體現了亞馬遜的收費站策略：亞馬遜不需要打造世上最強的模型，只要頂尖企業調用任何模型時，都必須經過它的櫃台結帳。

2.5 EDP 預算池與資料重力：把用量鎖進長期合約

有了 Trainium 壓成本、Bedrock 聚需求，最後一塊拼圖是：

如何確保企業的用量永遠留在 AWS，不被微軟或 Google 搶走？

亞馬遜靠的是三大通路機制：

  1. 現成預算池（EDP 合約）

全球大企業通常已與 AWS 簽署多年期承諾合約（EDP），預先鎖定了數千萬甚至數億美元的額度。

企業想導入 Claude 模型時，可以直接從這筆既有預算中扣抵，省去繁瑣的採購審查與額外預算申請。

這讓 AWS 近 5,000 億美元的在手訂單，直接變成所有模型廠商搶著分食的現成預算池。

  1. 生態聚合（導流回自家帳單）

AWS 是首個直接託管 Anthropic 原生平台（Claude Platform on AWS）的雲端商。

即便客戶習慣使用 Anthropic 的原生開發介面，費用依然會自動併入 AWS 帳單，成功將外部頂尖實驗室的直銷流量轉化為自己的雲端營收。

  1. 資料重力（搬遷成本極高）

全球企業的大量營運數據早已存放在 AWS（S3）。若將海量數據搬到其他雲端跑 AI，得負擔昂貴的跨雲傳輸費與延遲。

因此，「讓模型主動靠近既有數據」成為最經濟省事的選擇。

這三個機制疊加在一起，構成了收費站的完整閉環：Trainium 壓低成本 → Bedrock 聚合需求 → EDP 與資料重力鎖定用量。

只要用量成長的速度跑贏 Token 單價下跌的速度，這座收費站就能持續印鈔。

2.6 估值：為什麼 P/E 徹底失真

靜態 P/E 在亞馬遜身上會產生雙重扭曲：

第一，業務屬性極度分裂。

低利潤零售、高利潤廣告、高 CapEx 基建混在一個淨利裡，產生「看似很貴」的錯覺。

第二，534 億美元的紙上富貴。

Q2 2026 淨利 626 億（年增 245%），但其中 534 億來自對 Anthropic 持股的帳面增值，佔稅前利潤的 66%。這不是賣商品或算力賺來的真金白銀。

有趣的是，微軟投資 OpenAI 採用 HLBV 法，估值波動不進損益表。

亞馬遜採用公允價值法，Anthropic 每完成一輪融資，帳面增值立刻認列為當季淨利。同樣的資產，一個把波動關在門外，一個請進損益表正中央。

雖然即使扣除這 534 億，亞馬遜本業依然扎實。但投資人絕不能將帳面浮盈當作常態獲利能力。

因此，評估亞馬遜必須揚棄傳統 P/E，改採以下三種工具：

  • 核心營業本益比（Core Operating P/E）： 剔除一切非營運的投資評價損益，還原本業真實獲利。

  • EV / EBIT： 乾淨拆開外部股權投資與核心營運資產。

  • SOTP（分部加總估值法）： 將各業務拆開單獨給予合理乘數的終極分析工具（將於下一節展開）。

2.7 SOTP 估值拆解：四家獨立公司加起來值多少錢？

若把亞馬遜看成一整家公司，很難看清獲利體質。

最實用的評估方式是拆解成四個獨立業務、個別估值後再相加（分部加總估值法，SOTP）。

【先聲明：本節的核心前提與假設】

亞馬遜在官方財報中，從未單獨公開「廣告業務的利潤」以及「AWS 雲端的獨立財務結構」。

因此，本節所有的數字，都是我們基於公開數據與合理邏輯所做的「框架性估算」。

這裡的目的很單純：把「黑盒子」拆開，讓大家看清楚市場到底在為什麼付錢。

讀這段的重點在於掌握「拆解的邏輯」，而不是死記某個單一數字。

本文利潤以最新 Q2 乘 4 靜態推算。AWS 目前維持逾 36% 年增長，若成長持續，未來的動態遠期倍數（Forward P/E）會更低。

拆解前的關鍵觀念：電商與廣告，其實是「同一個資金池」

在亞馬遜的官方財報中，「零售（電商物流）」與「廣告」是合併在一起披露的。

如果我們拿出最新的單季數據，扣除掉一筆 6 億美元的關稅退款（這是一次性的意外之財，不代表常態表現）後，兩者合計的營業利益（也就是扣除成本後，真正賺到的錢）大約是 102 億美元。

如果把這個數字乘以 4，換算成一整年的常態表現（簡稱年化），大約是 410 億美元。

這 410 億美元是一塊「固定大小的餅」，我們必須把它切成兩份：

第一份：廣告賺了多少？

亞馬遜單季的廣告收入是 198 億美元（年化約 790 億）。我們參考 Meta（Facebook 母公司）等廣告同業的獲利水準，給予合理的 40% 利潤率。

由此推算，廣告業務一年大約幫亞馬遜賺進 320 億美元。

第二份：純電商物流剩下多少？

既然總共是 410 億，扣掉廣告賺的 320 億，剩下的就是純電商物流賺的了：大約是 90 億美元。

核心邏輯是，這兩者存在著「此消彼長」的關係。我們把廣告估得越賺錢，電商看起來就越薄利；但無論你怎麼切，兩者加起來的總和（410 億美元）是固定不變的。

四大區塊價值估算

    我們用總市值 2.82 兆，扣除 Anthropic 持股（約 1,330 億），再扣除電商與廣告的中位數價值（合計約 7,700 億），剩下的價值大約是 1.90 兆 – 1.95 兆美元。

    這剩餘的價值裡，其實還包含了亞馬遜的其他投資，例如：Amazon Leo（Globalstar 衛星計畫）、Zoox（無人駕駛）、各種硬體裝置（Echo 音箱等）以及 Rivian 電動車股權。如果我們給這些資產 500 億 – 1,000 億美元的價值，那麼 AWS 的實際估值倍數還需要再往下修 1 到 1.5 倍。

    對應 AWS 一年賺 641 億美元的實力，反推出來，目前市場給予 AWS 的估值倍數大約是 28.5 倍（即相當於用其年利潤的 28.5 倍價格來收購）。

2.8 實戰追蹤：亞馬遜 AI 能否賺大錢？盯緊這 4 個關鍵訊號

微軟賣 AI 軟體，可以按人頭每個月多收訂閱費；但亞馬遜的雲端（AWS）就像「水電瓦斯行」。

客戶用多少，亞馬遜就收多少錢。

在 AI 時代，運算技術進步得非常快，單次運算的價格只會越來越便宜（面臨技術通縮）。

因此，亞馬遜唯一的賺錢方式就是：「讓客戶使用 AI 的總量成長速度，遠遠超越單價下跌的速度」，同時依靠自己研發的省錢晶片（Trainium）來壓低機房的運作成本。

這套商業邏輯未來 1 到 2 年能否成功？我會最關心以下 4 個驗證訊號：

訊號 1：自研晶片到底有沒有幫忙省到錢？

  • 觀察指標：AWS 過去一整年的營業利益率（利潤率）能否守住 35%。

  • 蓋 AI 機房非常耗電，而且設備折舊非常昂貴。如果 AWS 的利潤率跌破了 35%，就代表亞馬遜自己研發的晶片省下來的成本，已經擋不住龐大的建置與維護開銷。這將是一個利潤被侵蝕的警訊。

訊號 2：大客戶簽約的速度，有沒有追上蓋機房的速度？

  • 觀察指標：建置投資額（CapEx 2,200 億）與手頭大合約訂單（Backlog 5,000 億）的成長速度是否匹配。

  • 亞馬遜現在正砸大錢瘋狂蓋新的資料中心（這叫 CapEx 資本支出）。如果「砸錢蓋廠」的速度，遠遠快於「大客戶簽長期合約」的速度，就代表產能蓋得太多、客戶需求卻跟不上，未來可能面臨供過於求、設備閒置的風險。

訊號 3：瘋狂花錢蓋機房的階段，何時才會慢下來？

  • 觀察指標：投資支出成長率（目前年增 64%）何時會降到營收成長率（雲端約 37%、廣告約 26%）之下。

  • 因為現在買晶片、蓋機房花錢花得太兇，亞馬遜過去一年的「自由現金流」（也就是公司賺進來的錢，扣掉所有必須投資的支出後，真正能放進口袋的現金）已經變成了 負 76 億美元。

    投資人都在等待亞馬遜「踩煞車」的那一天。只要投資的成長速度慢於賺錢（營收）的成長速度，大筆的真金白銀就會重新流回亞馬遜的口袋裡。

訊號 4：自研晶片有沒有機會變成「額外的賺錢金雞母」？

  • 觀察指標：是否開始有外部知名大客戶（例如歐洲國家級主權 AI 計畫）正式宣布採購亞馬遜的 Trainium 晶片，或財報開始單獨列出晶片營收。

  • 目前市場只把這顆晶片當成亞馬遜自己省錢的工具。一旦有外部客戶願意大批購買，這項晶片業務就相當於一張價值 500 億美元的「額外樂透彩券（期權）」，能為亞馬遜帶來額外的估值加分。

核心總結

這 4 個訊號本質上都在回答同一個問題：亞馬遜這種「靠基礎建設收過路費」的 AI 模式，是在加速兌現獲利，還是正在面臨阻力？

如果 4 個訊號全亮綠燈：前面算出的 AWS 高估值（28.5 倍）就完全站得住腳，甚至有不少上升空間。

只要有訊號轉為紅燈：市場給予亞馬遜的身價倍數，就需要重新打折審視。

第三章 | Alphabet：Gemini 和 TPU 的真實角色

當我們翻開 Alphabet 官方財報的時候，會看到其業務由三大部門構成：

  • Google Services（搜尋、YouTube、廣告聯盟、Play 商店、硬體與訂閱）

  • Google Cloud（GCP 雲端基礎設施與 Workspace 企業協同工具）

  • Other Bets（Waymo 自動駕駛、Verily 生命科學等前瞻研發項目）

先看第三塊。

Other Bets（Waymo、Verily 等）每季虧損約 15 至 18 億美元，營收貢獻極低。

但隨著 Waymo 在近期融資中獲得 1,260 億美元的投後估值，它已經具備了清晰的市場定價參照。

它更像是一張有底層價值的長期期權，暫不直接左右本業的獲利模型。

因此，評估 Alphabet 核心內在價值的焦點，完全落在另外兩台引擎上：支撐全公司龐大現金流的 Google Services，以及近年迎來獲利質變的 Google Cloud。

3.1 Google Services：從核心業務的顛覆疑慮，到搜尋變現的再驗證

Google Services 是 Alphabet 的絕對營收支柱，佔集團近 80% 的營收與絕大部分營業利潤，營益率長期維持在 40% 左右。

它的運作邏輯很單純：Google 透過搜尋、YouTube、Google Maps、Android 和 Chrome 等免費工具，深入全球數十億人的日常生活。

接著，再將這些龐大且高頻率的資訊檢索與觀看行為，轉化為精準的數位廣告版位與訂閱收入。

然而，2022 年底生成式 AI 的興起，對這套運轉二十年的模式帶來了本質上的質疑。

市場開始擔心使用者的檢索習慣會發生根本轉變，如果大家習慣直接向對話機器人要答案，不再點進傳統的搜尋結果頁，那麼 Google 賴以維生的廣告點擊是否會受到結構性侵蝕？

這種不確定性，讓市場在 2023 至 2024 年間給予 Services 部門相當保守的估值倍數（本益比約 12 至 15 倍）。

但過去幾季的營運走向給出了答案。Google 將 AI Overviews 逐步整合至搜尋首頁後，整體搜尋營收年增率從先前的個位數回升到 17%，Services的營益率也微幅擴張至 41.8%，AI Overviews 的月活用戶則突破 25億人。

大家終於發現，AI 摘要並沒有消滅搜尋，反而擴展了搜尋的邊界。

許多過去難以用一兩個關鍵字表達的複雜問題，現在使用者更願意在 Google 上提問，進而帶出更多具有商業意圖的檢索場景。

Google 憑藉既有的全球分發優勢，順利將新技術轉化為既有產品的延伸，穩住了核心業務的變現能力。

3.2 Google Cloud：從長期落後，到 TPU 帶來的利潤率拐點

相較於穩定的 Services，Google Cloud 的發展經歷了一段更曲折的過程。

早在十多年前，Google 就明白自己不能只當一家廣告公司，一方面需要擺脫單一營收來源的景氣風險，另一方面，為了支撐全球搜尋與影音流量，Google 早已打造出全球最頂尖的分散式運算架構。

將這套強大的基礎設施開放給企業使用，原本是再自然不過的商業選擇。

然而在雲端發展的前期，Google 卻落後於 AWS 與微軟 Azure，部門長期處於虧損狀態。

問題的根源在於企業基因的差異，Google 的技術本身早已到位。

Google 本質上是一家由工程師驅動的消費端產品公司，最初抱持著「只要技術架構夠好，客戶自然會買單」的思維。

但企業級 IT 市場買的是長期的合規保障、量身訂製的導入支援，以及業務團隊深厚的信任關係，這恰好是微軟與 AWS 長年深耕的領域。

轉折發生在兩件事的交會。

首先，Google 近年重新整頓了企業銷售（B2B）體系，補齊了過去在客戶服務與通路上的短板；接著，AI 浪潮全面引爆了市場對算力與推理成本的敏感度。

這時，Google 十年前開始投入自研張量處理器（TPU）的效益開始顯現。

當同業在擴建 AI 基礎設施時，大多必須承受外部晶片供應商高昂的採購成本與毛利抽成，Google 卻能依靠自研 TPU 顯著壓低單位運算成本，提供更具性價比的雲端服務。

這套優勢反映在近期財務數據上：

Google Cloud 的營收年增率連續加速，從 48% 一路推升至 63% 與 82%，在手合約（Backlog）累積至 5,140 億美元，部門營益率更從一年前的 20.7% 提升至 35.6%，快速拉近了與領先者的獲利差距。

3.3 Gemini 的定位：從「AI 輸家」到「雙重重估」的催化劑

真正令 Google 的評價從兩年前的「AI 輸家」，變成現在的「AI 贏家」，其實是 Gemini 的異軍突起。

當時市場最大的恐懼是「AI 會顛覆搜尋」，Google 在輿論與資本市場眼中一度被貼上反應遲緩、處於被動防守的標籤。

轉折點來自 Gemini 3 的推出。

這款模型在推理能力、多模態處理以及基準測試上的強勢表現，讓市場第一次意識到 Google 在基礎模型領域具備與頂尖對手正面競爭的實力。

市場對 Google 的認知，也從「被顛覆者」迅速轉向「有能力定義規則的領跑者」，進而引發了一場跨業務的雙重價值重估：

一方面是 Services（搜尋業務）的重估。

Gemini 3 證實了 Google 能把前沿大模型無縫整合進核心產品。

AI Overviews 不僅沒有侵蝕傳統搜尋，反而推動了搜尋量的增長與廣告變現，營業利益率維持穩健。這個進展消除了市場對搜尋業務衰退的極端恐懼，讓 Services 的估值倍數逐步自低點修復至 18 到 20 倍以上。

另一方面則是 Cloud（雲端業務）的重估。

過去市場主要將 Google Cloud 視為提供運算與儲存的基礎設施廠商。

然而，當 Google 擁有頂級的自研大模型，並結合底層的 TPU 算力時，Cloud 展現了完整的全端整合能力。

企業客戶開始為了調用 Gemini 而進駐 GCP，推動 Cloud 的利潤率在一年內從 20.7% 上升至 35.6%，也帶動了市場對 Cloud 業務成長溢價的重估。

因此，在我看來，Gemini 的價值，在於直接決定 Services 與 Cloud 這兩大分部的估值倍數與獲利預期。

3.4 不再前沿的 Gemini

在大模型這場軍備競賽中，風向變得很慢，但有時也快得令人措手不及。

就在半年前，市場還在爭論 Gemini 能否與 GPT、Claude 一決高下。

然而近幾個月的現實卻有些殘酷：Gemini 似乎正與「前沿模型」這個頂尖俱樂部漸行漸遠。

它不僅沒能縮短與領頭羊的差距，甚至在面對一眾中國開源模型的步步進逼時，也顯得有些吃力。

在過去半年裡，Google 一口氣推出了四個以效率、輕量著稱的 Flash 版本，卻遲遲不見新的旗艦 Pro 模型登場。

在近期的財報會議上，管理層也坦承，在 Agentic Coding（智慧代理編碼）等高階任務上，他們與頂尖對手確實存在差距。

再加上幾位頂尖研究人員的流失，更讓市場開始懷疑：Google 過去引以為傲的前沿研究突破能力，是否正在面臨瓶頸？

這就引出了一個最核心問題：

當 Gemini 不再是市場上最聰明的模型時，我們該如何看待 Google 的估值？

要回答這個問題，我認為，我們需要將 Services 與 Cloud 分開來看。

1. Services（搜尋業務）

先說結論：Gemini 的退步，對 Google 搜尋業務的影響其實微乎其微。

模型在跑分測試中拿第一名固然重要，但真正決定這門生意成敗的，始終是「分發通路與成本效率的極致結合」。

以 AI Overviews（AI 搜尋總結）為例，這項功能之所以能迅速觸及全球數十億用戶，關鍵在於 Google 手中握著全球無可取代的搜尋入口，以及他們能把「每一次查詢成本」壓到極低的強大基礎設施。

至於背後的模型是否驚世駭俗，反而退居其次。

對於絕大多數普通用戶來說，只要 AI 給出的答案「夠好用」、且反應夠快，他們就沒有理由離開。

只要能維持在這個成本與體驗的甜蜜點，Google 就能牢牢守住用戶，而市場給予 Services 部門 18 到 20 倍的估值倍數，也就有了最堅實的底氣。

2. Cloud（雲端業務）

但換到 Cloud（雲端業務），情況就完全不同了。

在這裡，Gemini 是否處於技術頂點，直接決定了 Google 雲端未來的獲利含金量，以及市場願意給它多高的想像空間。

我們可以把雲端的商業模式分成兩層來看：

「賣模型」：

如果企業客戶指名調用 Gemini，Google 能賺取最完整的模型高毛利，這時候市場會願意給 Cloud 部門 30 到 35 倍的頂級軟體倍數。

「做代管」：

如果客戶嫌 Gemini 不夠聰明，只想在 Google 的 Vertex AI 平台上調用對手 Anthropic 的 Claude 模型呢？

這時，大頭的模型利潤會被 Anthropic 拿走，Google 賺到的只是幫忙代管、提供基礎設施與算力的「過路費」。

利潤率被稀釋後，估值倍數就會降到 20 到 30 倍，與傳統的 AWS 或 Azure 無異。

以 Google Cloud 目前的獲利規模來算，35 倍與 20 倍的估值倍數差距，背後對應的是數千億美元的市值波動。

所以說，「Gemini 是否處於前沿」，對雲端來說或許不會影響營收太多，但卻會影響估值倍數的天花板。

那麼，面對模型競爭力的下滑，Google 會坐以待斃嗎？

現實中，Google 建立了一套很務實的商業避險機制。

「你想用最強的 Claude？沒問題，我們在 Vertex AI 上幫你代管。」
「競爭對手需要龐大算力？可以，我們賣 TPU 基礎設施給你。」

這套務實的策略確保了：只要整個 AI 市場還在成長，不論最後是誰勝出，Google 雲端的營收大盤依然能跟著水漲船高。

但這種避險策略，同時也帶來了一個微妙的內部資源博弈。

當 Google 為了眼前的商業利益與獲利防禦，選擇把大量寶貴、稀缺的 TPU 算力優先交付給外部大客戶時，自家 DeepMind 團隊在研發下一代前沿模型時，可能就得面臨「內部算力排隊」的窘境。

這種為了短期利益所做的妥協，反而可能在無形中，拖慢了自家模型追趕前沿技術的步伐。

總結來說：Gemini 3 當初成功化解了市場對 Google「被顛覆」的恐懼，也完成了核心業務的估值修復。

但現在，Google Cloud 能否守住高估值倍數，將取決於 Google 能否在算力分配與前沿技術的競賽中，重新奪回話語權。

3.5 戰略骨架：用利潤換地盤的「三次 Android 劇本」

要理解 Google 現在在做的事，最簡單的方法就是回頭看當年的 Android。

Google 有一套極其強大、而且屢試不爽的商業劇本：

「我不靠這個產品直接賺錢，我把它免費或壓到極低價送給你，換取所有人都在我的地盤上，最後我靠旁邊的業務賺大錢。」

這套劇本，Google 在不同時代、不同層次上，其實整整演了三次：

第一層：作業系統（2008 年的 Android）

當年微軟賣作業系統要收昂貴的授權費，Google 卻把 Android 完全免費開源。

Google 賺到作業系統的錢了嗎？幾乎沒有。

但它換來了全球數十億支手機的市佔率，並把 Google 搜尋變成預設首頁，最後在搜尋廣告上賺得盆滿缽滿。

第二層：模型（現在的 Gemini Flash）

當對手在爭奪「地表最強模型」並收取高額 API 費用時，Google 選擇主打超低成本、超快速度的 Flash 版本。

他們放棄了模型本身的暴利，換來的是 10 億人以上的月活躍用戶，把大家牢牢鎖在 Google 生態系裡。

第三層：自研晶片（現在的 TPU 晶片外售）

現在這套打法甚至延伸到了最底層的硬體晶片。Nvidia 賣晶片享有 80% 的驚人暴利，但 Google 賣自己的 TPU 系統給客戶時，據毛利卻只有約 20 - 30% 的利潤(官方沒有公佈，據推算。

為什麼要少賺？因為只要客戶的機房裝了 TPU，就必須用 Google 的軟體生態（JAX/XLA），進而把 Nvidia 擋在門外。

這三次操作的本質完全一樣：在財務報表上，你看不到這些產品本身賺了多少錢，但它們卻成了 Google 最強大的護城河。

不過，前兩層送出去的東西（Android 授權、Gemini Flash 模型），邊際成本接近零，可以無限複製，送出去不會傷到自己。

但第三層送出去的 TPU，是實體硬體，有真實的 COGS，也有產能的機會成本。

3.6 TPU 的變現

要看懂 TPU 對 Google 估值的真正影響，我們不能把它當成一般的硬體生意來看。

在算力有限的情況下，Google 每產出一塊 TPU，就必須面臨一個「四選一」的單選題：

通道 ①：留給自家用（搜尋、Gemini、DeepMind）

自己用最划算，能幫 Google 省下買 Nvidia 晶片的龐大成本，省下來的錢直接體現在搜尋與雲端的高利潤率裡。

通道 ②：放在自己的雲端（GCP）租給客戶

客戶每個月付租金調用算力，這是穩定的長期現金流（像包租公收租），市場最喜歡這種軟體訂閱模式，願意給予高估值。

通道 ③：整台 TPU 伺服器打包，直接賣給客戶搬回家

一手交錢一手交貨，硬體毛利只有微薄的約 20%，而且只賺這一次。這種傳統賣硬體的生意，市場會給較低的硬體倍數。

通道 ④：合資模式（JV / 用別人的錢建機房）

由合作夥伴（如 Blackstone）出大筆資金蓋機房，Google 只出 TPU 晶片與軟體技術並收取服務費，藉此減輕自己的財務負擔。

當 Google 開啟通道 ③ 和 ④（外售或合資）時，我們要清楚的重點是：營收規模變大了，但綜合毛利率會被拉低。

舉個簡單的例子：

如果 Google Cloud 營收達到 1,400 億美元，其中有 300 億美元是靠賣 TPU 硬體（毛利約 20%）貢獻的，其餘 1,100 億美元是純雲端服務（高毛利）。

  • 帳面上的總營收成長率看起來非常亮眼。

  • 但因為混入了 300 億美元的低毛利硬體，整體的綜合毛利率與自由現金流轉換率自然會被稀釋。

賣 TPU 硬體能帶來實質營收與現金，但不能把整包營收都當成高毛利的軟體服務來給予估值溢價。

對比上一章的Trainium，我們可以清楚看到分別：

TPU 已經在四個通道上同時運營，Google 面對的是「每一瓦矽分配到哪個通道」的機會成本問題。

Trainium 目前只在通道 ② 上，它面對的是「什麼時候從 ② 擴展到 ③」的期權問題。

兩家自研矽的變現階段不同，估值邏輯也完全不同。

那麼，既然通道 ① 和 ② 的利潤率更高，為什麼 Google 還願意將部分 TPU 拿去外售或合資？

動機一：生態系綁定

Google 外售 TPU 的首要目的，是推廣自家的 JAX / XLA 軟體棧，硬體差價只是附帶收益。

只要外部大型企業（如 Meta）或研究機構在自己的機房裡部署了 TPU，工程師就必須習慣 Google 的軟體生態，進而降低對 Nvidia CUDA 生態的單一依賴。

動機二：突破「機房與電力」瓶頸（ROIC 的角度）

當前 AI 算力擴張的實質瓶頸，是變壓器、土地、電網配額與機房建設週期。

Alphabet 先前已在電話會中提及會向第三方租用算力，這反映出 Google 現階段也面臨機房與電力的擴建速度限制。

在這種情況下，通道 ③ 與 ④ 的邏輯就變得合理：

  • 通道 ②（GCP 雲端出租）： Google 必須自己出資買地、牽電、蓋機房，並承擔後續數年的折舊負擔。

  • 通道 ③ 與 ④（外售或合資）： 由客戶或合夥人自己出電、出機房、承擔 CapEx 與折舊。 從毛利率來看，20% 確實不如雲端服務；但從投入資本回報率（ROIC）來看，這是一筆不佔用 Google 稀缺電力配額、不增加自身機房負擔、直接收現的生意。

動機三：資本結構優化

儘管 Google 帳上現金充裕（手握超過 2,400 億美元現金與流動資產），但全球 AI 基礎設施的資本支出極為龐大。透過部分外售與合資模式，能讓 Google 在擴張算力版圖的同時，適度平衡自身的資本支出強度。

簡單來說，TPU外售對 Alphabet 的內在價值幾乎確定是加分的。它真正製造的問題在於辨識度，大家可能看不出它同時在做兩種生意。

3.7 估值：直接拆解兩台引擎

Alphabet 的 GAAP EPS 被約 980 億美元的非營運未實現利得嚴重污染（主要來自 SpaceX 與 Anthropic 股權的帳面增值）。

這與第六章亞馬遜的處理邏輯完全相同：帳面上的股價波動不是生意賺來的錢，剔除後我們只看核心營運獲利。

估值口徑與方法論也沿用第六章（EV/EBIT，剔除投資收益，Q2×4 靜態年化），此處不再重複。

簡化 SOTP 框架

目前市值約 4.2兆美元，落在上述區間的最上緣。

反向推算：市場目前給 Google Cloud 多少倍？

和亞馬遜的做法同樣，我們也可以嘗試反推。

以企業價值約 4.06 兆為起點，扣掉 Services 在 20x 下的 3.16 兆，剩下約 0.9 兆。僅此一步，隱含 Cloud 已被給到約25x。

若進一步把被資本化的總部成本加回、並扣除 SpaceX／Anthropic 等股權投資組合的價值，隱含倍數會推升至約 37x。

（股權投資組合的公允價值須自 10-Q 取值；此處為示意假設，它會直接左右反推出的倍數。）

這個 37 倍合理嗎？對照 AWS 的隱含 28.5 倍（第六章），Google Cloud 的增速更快（82% vs 37%）、利潤率斜率更陡（一年 +15 個百分點）、Backlog 覆蓋率更高（5.2x vs 2.9x）。

這些都支持溢價。但 Backlog 中 Anthropic 佔超過 40%(根據媒體推算)，且這筆錢有一部分是 Google 自己投資出去的，合約能見度與客戶集中度是同一枚硬幣的兩面。

同時，Google Cloud的Backlog中也混入了TPU銷售。我們前面也提過，TPU會拉低利潤率，因此Backlog的質素可能也需要打個折扣。

於是下一個問題是：市場已經願意給 Cloud 明顯高於 AWS 的倍數了，那麼接下來要靠什麼，才能讓它給得更高？

我同樣把拆解邏輯與隱含倍數攤開，讓大家用自己的假設去填。

3.8 實戰追蹤：怎麼驗證本章的判斷？

對於Google，我會持續追蹤以下五個訊號：

訊號一：Cloud 到底是「賣模型」還是「做代管」？

這是決定 Cloud 估值倍數的核心。如果企業指名調用 Gemini，Google 能賺取完整的軟體模型毛利，享有較高倍數；如果客戶只是在 Vertex 上調用 Claude 等第三方模型，Google 就只賺取算力過路費，估值倍數自然會回落。

  • 追蹤方法： 觀察管理層是否願意在財報或電話會中，具體拆分 Vertex 上 Gemini 與第三方模型的營收比例。若持續不揭露，通常代表代管與過路費的佔比仍然居多。

訊號二：TPU 銷售對營收組成的稀釋程度

當 TPU 硬體銷售混入 Cloud 營收時，帳面成長率看起來很高，但實際上會拉低綜合毛利率。市場最大的誤判，是把賣硬體的成長誤當成高毛利軟體的成長。

  • 追蹤方法： 翻閱 10-Q 的營收拆分細項（Revenue Disaggregation），確認產品硬體銷售那一行，將「純雲端」與「賣硬體」分開看待；同時觀察存貨與待履行合約（Backlog）的變化。

訊號三：Gemini 能否重回前沿水準？

Gemini 處於前沿與否，對搜尋業務的影響有限（搜尋更依賴通路分發與成本效率），但對 Cloud 能否拿到高估值倍數至關重要。

  • 追蹤方法： 觀察高階 Pro 模型的更新頻率，以及內部研發的算力分配。如果外售晶片排擠了 DeepMind 的研發算力，導致模型競爭力落後，Cloud 就會更依賴代管與基礎算力租賃，壓低估值空間。

訊號四：TPU 內外分配的品質

Google 每產出一塊 TPU，都必須在自用、雲端出租、外售與合資之間做取捨。

  • 追蹤方法： 觀察合資機房的建設進度，以及外售客戶的體質。如果買家自帶電力與機房（如 Meta），屬於正面加分；如果買家的資金多半來自 Google 自身的股權投資，合約品質就需適度扣除循環交易的影響。

訊號五：CapEx 增速與自由現金流（FCF）拐點

AI 基礎設施投入龐大，在營收成長追上資本支出之前，自由現金流仍會持續承壓。

  • 追蹤方法： 觀察管理層何時釋出「資本支出增速開始低於營收增速」的訊號。在此之前，也要留意 Google 是否持續向第三方租賃算力，這會是短期壓縮利潤率的變數。

本節小結：

Gemini 支撐著搜尋業務的成本底盤，也決定了 Cloud 估值倍數的天花板；TPU 則是透過利潤取捨，換取生態滲透與資本效率。

我們要看清 Cloud 營收中究竟有多少來自「模型」、多少來自「代管」、多少來自「賣硬體」，就能客觀評估 Google 的真實價值。

第四章 | Meta：34 億用戶的廣告帝國，與折舊浪的賽跑

在四大 AI 巨頭中，Meta 的商業結構最為特殊。

它沒有雲端業務，沒有 Backlog，沒有 RPO。

Meta 的營收結構極度集中，FoA (Family of Apps，包含 Facebook、Instagram、WhatsApp、Messenger) 貢獻了超過 97% 的營收。

Reality Labs 每季虧損約 46 億美元，在估值模型中，不給個負數已經算是十分仁慈。

因此，Meta和微軟一樣，也是一間「切不開」，也沒有需要切開的公司。

但兩者的戰場焦點不同：微軟的 P/E 戰場在「P」（倍數，取決於成本-產出曲線的毛利防守）；而 Meta 的 P/E 戰場在「E」（EPS，取決於廣告營收能否跑贏折舊浪）。

理解 Meta，必須從廣告開始。

4.1 商業本質：廣告是唯一已驗證的印鈔機

Meta生意的底層邏輯，是將 34 億用戶的注意力，精準轉化為廣告主願意掏錢的曝光。

AI 在這個過程中扮演的角色，是讓廣告變得更精準、更便宜、更有效。

  • 內容推薦算法： 提高黏著度與停留時長，擴大曝光池。

  • Advantage+自動化投放： 精準預測轉化率，降低廣告主的獲客成本（CAC），促使廣告主提高預算。

廣告營收成長 ＝ 曝光量（Volume） × 單次廣告均價（Price）

以 2026 年 Q2 為例，廣告營收的成長約有一半來自曝光量（年增 14%），另一半來自均價提升（年增 12%）。

這個量價拆分揭示了 Meta 的潛在脆弱點：

  • 「量」有天花板： 用戶的日常時間有限，廣告載入率（Ad Load）過高會破壞體驗；若各國監管限制青少年使用時長，首當其衝的就是曝光量這個「量」的分子。

  • 「價」靠 AI 撐腰： 當「量」的擴張放緩，未來的成長只能依賴 AI 提升轉化率，帶動單價（Price）上漲。

4.2 Meta 的雙面刃

微軟、亞馬遜與 Google 投資 AI，需要經過漫長的基建部署、企業簽約與營收認列週期；Meta的變現則是即時反饋。

推薦模型每一次迭代，廣告主的 ROI 當天就能改善，Meta的營收當週就會增加。

但這種「直接融入廣告」的特性也帶來了市場估值上的困境：

  • 雲端巨頭每季都要公佈雲端增速，AI 的投入回報有明確的財務指標可供市場驗證。

  • Meta 沒有獨立的 AI 業務分部，市場無法拆出「AI 究竟單獨貢獻了多少營收」。

因為短期 ROI 無法被精確拆解證偽，資本市場對 Meta 的 AI 信心往往處於「信仰模式」，估值乘數難以大幅拉開。

這也解釋了為什麼 Meta 的股價對「資本支出與費用指引」的敏感度，遠高於營收本身。

在營收難以拆解的情況下，激增的折舊與費用是市場唯一能精確計算的硬成本。

4.3 AI 資本支出的兩個去向：守護基本盤 vs. 構建數據飛輪

Meta 每年數百億美元的資本支出，本質上流向了兩個邏輯完全不同的領域：

去向一：核心廣告與推薦基礎設施（確定性投資）

這是資本支出的主力，主要採購 GPU 與自研 MTIA 晶片，專門用於訓練萬億參數的推薦系統與 Advantage+ 廣告模型。

這筆投資的邏輯非常透明：只要 FoA 部門的營收年增率能持續維持在 15%~20% 以上，就證明算力投資成功轉化為實質利潤，屬於高 ROI 的確定性防守。

去向二：前沿智能與模型生態（長線賭注：從開源 Llama 到閉源 Muse）

這部分包含了 Meta 超級智能實驗室（MSL）、前沿基礎大模型的訓練叢集，以及近期推出的 Muse 模型與 Model API。

這筆投資短期內無法帶來巨額利潤，但它代表了 Meta 戰略身份的重大轉折。

如果大家有留意Meta的AI戰略的話，會發現他們從一開始的開源 Llama，轉向現在的閉源 Muse。

為甚麼他們要這樣做？

過去 Meta 堅持 Llama 的開源路線，是希望透過免費釋出頂級開源模型，破壞 OpenAI 與 Google 企圖在模型層建立的專屬護城河，同時吸引全球開源社群幫 Meta 優化底層代碼。

然而，隨著 AI 演進到 Reasoning（推理解題）與 Agentic（自主代理）階段，Meta 發現了開源模式的盲點：

  • Meta 擁有全世界最強的「C 端注意力數據」（短影音滑動、點讚、社群互動）。

  • Meta 卻極度匱乏「B 端推理與任務執行數據」（複雜邏輯編程、企業級多步驟決策、工具調用軌跡）。

OpenAI 與 Anthropic 透過封閉的 API 與企業訂閱，每天都在吸收全球最頂尖工程師與企業的高價值互動數據，藉此持續反哺下一代模型；而 Llama 是被用戶下載到本地運行，Meta 完全收集不到這些黃金數據。

這正是 Meta 推出閉源模型 Muse Spark 並提供Model API 的主要原因：

  1. 從「生態慈善家」轉向「數據捕獲者」：

Muse 採用按 Token 計費（如輸入 $1.25 / 百萬 Token，輸出 $4.25 / 百萬 Token），正面迎擊 Claude 與 GPT。

Meta 的真正目標，是建立一個能與企業開發者直接互動的接觸點；賣 Token 本身只是手段。

  1. 複製經典的「補貼換數據」劇本：

在 Model API 中，Meta 設計了Contributor（貢獻者）層級。為企業提供大幅折扣的 API 定價，條件是允許 Meta 使用其 Prompt（提示詞）與輸出結果來訓練未來的模型。

正如Mark Zuckerburg在法說會上強調：「可持續的長期優勢，來自數據飛輪（Data Flywheel）。」

4.4 MTIA：進度偏慢但定位明確的內部算力卡

在自研 AI 晶片這條賽道上，Meta 起步較晚，整體的迭代節奏也明顯落後於對手。

Google 早在 2015 年就投入 TPU 研發，如今已發展到第六代；Amazon 當年收購 Annapurna Labs 後，Trainium與 Inferentia也已深植 AWS 產品線。

相較之下，Meta的自研晶片 MTIA（Meta Training and Inference Accelerator）起步較晚，目前依然處於相對早期的落地階段。

Meta 對 MTIA 的分工設定十分務實：

  • 前沿模型訓練： 門檻極高且架構變化太快，Meta 選擇全部交給 Nvidia 最新的旗艦 GPU 叢集。

  • 廣告與推薦推理： 演算法相對成熟、調用次數龐大，Meta 逐步導入 MTIA，負責支撐 Instagram 與 Facebook 的動態牆推薦。

4.5 算力出租：資本對沖、去化庫存，還是第四大雲？

2026 年中，市場傳出 Meta 內部啟動「Meta Compute」計畫，打算把手上多餘的算力與資料中心租給外部客戶。

這究竟是 Meta 資本支出衝太猛、內部消化不良的警訊，還是活化沉沒資產、拉高資本報酬率（ROIC）的神來之筆？我們可以從三個面向來看：

1. 動機：為「超前部署」買張保險

資料中心和電力都是以「吉瓦（GW）」為單位的重資產，從簽約到上線動輒數年。

Mark Zuckerburg的態度很明確：AI 競賽裡，算力不夠會直接淘汰，建太多頂多只是資金壓力。

當 Meta 為了訓練下一代前沿模型砸錢搶下龐大電力與硬體，在新舊模型交替的空檔，必然會出現暫時閒置的 GPU。

把這些機器租出去，等於讓外部客戶幫忙分攤折舊費用，既能維持最頂級的算力儲備，又幫財務裝上了安全氣囊。

2. 模式：做「算力軍火商」，不做複雜企業雲

Meta 沒有 AWS 或 Azure 那樣龐大的 B2B 銷售團隊與企業軟體生態，因此它最可能選擇兩條輕量路線：

  • 大規模批發裸金屬（Bare-Metal）： 像 CoreWeave 一樣，直接把整座資料中心大批發給大型 AI 機構或主權 AI。靠著極致的硬體採購規模變現，省去維護軟體服務的麻煩。

  • 輕量級模型 API： 類似 AWS Bedrock，按 Token 收費提供推論服務，順便收集企業端的應用反饋。

3. 財務：舒緩現金流，但拉低毛利

機構估算，每出租 1 GW 的算力，每年能帶來 100 億至 150 億美元營收。這對即將迎來巨額折舊的 Meta 來說，是一筆能安撫股東的穩定現金流。

不過，算力租賃本質上更像公用事業，毛利率無法跟 Meta 本業近 80% 的廣告業務相比。

租賃營收拉高會稀釋整體毛利率，而且一旦算力被長約鎖定，內部研發若突然需要緊急擴容，調度彈性也會受限。

4.6 為什麼 Meta 的估值倍數會較低？

對比另外三家巨頭，Meta的估值倍數明顯低上一截。

你可能會覺得，這不太合理呀。

讓我們把時間拉回 2021 年秋天。

Zuckerburg高調宣示押注「元宇宙」（Metaverse），將公司改名為 Meta。

隨後幾年，專門研發元宇宙的 Reality Labs 燒掉了數百億美元。即便華爾街一片哀號、股價一度跳水，也沒有任何董事會成員或機構法人能阻止他。

原因很簡單：Zuckerburg透過 Class B 雙重股權結構，穩穩握有約六成的投票權。

簡單來說，Meta是Zuckerburg的一言堂，而市場並不相信他的判斷力。

微軟或亞馬遜採購 GPU，是為了轉售給雲端客戶，因此價格上限受制於客戶的付費意願。

但 Meta 買 GPU 主要是供內部研發使用，沒有市場售價來約束上限，投資回報完全由內部自己算。

而無法直接對外變現的算力，在財務模型裡終究要打個折扣。

4.7 財務工程：從「自己掏錢買」轉向「高級表外操作」

隨著 AI 軍備競賽白熱化，直接砸錢買設備已經跟不上Meta的擴建速度。

Meta 的融資策略開始出現質變：把算力「隱形化」。

  • 找金主合資（JV）： 2026 年 7 月，Meta 宣布與貝萊德（BlackRock）合作開發德州 140 億美元的資料中心。巧妙的是，Meta 只出資 20%，讓貝萊德扛下 80% 的建設成本。豪宅主要由 Meta 用，但地基與房貸大多在別人名下。

  • 簽下龐大的「預售合約」： 到 2026 年中，Meta 簽下的「未開始租賃承諾」高達 數千億美元。這些機器還沒交付，因此不必立刻列入資產負債表，只隱藏在財報附註裡。

  • 保證底價與包下產能： 為了讓合作夥伴安心出錢，Meta 提供了高達兩百多億美元的「殘值保證」，並向 CoreWeave 等算力商簽下 210 億美元「不論用不用都得付錢（Take-or-pay）」的長約。

  • 同時補強表內流動性： 除了表外操作，Meta 還在 2026 年 5 月直接發行 250 億美元無擔保債券，使長期債務衝上 836 億美元，幾乎吃光了帳上 903 億美元的現金。

另外三巨頭不是沒有表外操作，但相比之下，Meta 的手法顯然更為激進。

這意味著，投資人如果只看財報上的「CapEx（資本支出）」指引，已經無法看清全貌。Meta 真正的資本承諾，早已散落在租賃、合資與條約的細節裡。

而這，其實會更進一步壓縮它的估值。

4.8 估值：現價反映了甚麼？

2026 年 8 月，Meta 股價跌到 544 美元附近，從年初的高點算起，市值足足蒸發了約三成。

市場之所以大甩賣，是因為第二季財報揭露了一個令人焦慮的現實：雖然 Meta 的廣告營收依舊強勁（年增 28% 達到 608 億美元），但 Zuckerberg 買 AI 設備花錢毫不手軟。

龐大的資本支出直接吃掉了帳面上的現金，自由現金流從去年同期的 85.5 億美元，直接暴跌到只剩 7.84 億美元。

華爾街顯然被嚇到了，但核心問題是：跌到 544 美元的 Meta，到底把多悲觀的情境給算進去了？

核心問題一：華爾街對未來的獲利預估，會不會太樂觀？

華爾街分析師目前預測，Meta 每股盈餘（EPS）要從 2026 年的約 28.5 美元，成長到 2027 年的約 31.6 美元（成長約 11%）。分析師共識目標價約 750 美元。

我們用白話算這筆帳：

  • 要達標的目標： EPS 增加約 3.1 美元，代表 Meta 稅後得多賺約 78 億美元。

  • 要克服的逆風（折舊）： 過去兩年買了幾百億美元的 GPU 與資料中心，這些設備明年開始要在帳面上大量認列設備折舊，每年會吃掉大約 174 億美元的稅後利潤。

  • 加總的挑戰： 也就是說，Meta 明年必須在稅前額外多創造大約 310 億美元的營業利潤，才能同時抵消設備折舊、並達成分析師設定的目標。

扣除掉今年一次性裁員與官司費用的自然回血，Meta 明年的營收至少要維持約 22% 的成長，才撐得起 31.6 美元的 EPS。

核心問題二：現價 544 美元，市場到底在怕什麼？

那麼，既然分析師的預期已經下修了一輪，股價跌到 544 美元合理嗎？

我們反過來推算：544 美元的股價，背後隱含的是什麼樣的市場預期？

以下 EPS 為我們自建模型（FY2026 基期營收 2,520 億、營業利益 850 億；加回一次性費用；扣除 210 億新增折舊；增量營業利益率 50%；稅率 17%；股數 25.3 億）：

劇本 A（樂觀）： 營收年增 25% 以上，加上華爾街給予正常 23 至 24 倍本益比，股價約 750 美元。

這正是分析師共識目標價的由來，成長不減速和倍數回到歷史水位，兩件事都必須看對。

劇本 B（現況）： 現價 544 美元對應的隱含條件，等於兩個可能性：

  1. 20%增速，以及18x PE左右

  2. 15%增速，20x PE左右

市場假設的 15% 至 20% 成長，低於公司當期實績（Q2 廣告年增 27%）與自家指引。

(還是同樣，這裡只是讓大家清楚估價背後的邏輯，至於合理的數字和倍數應該是甚麼，大家可以自行代入和判斷。)

如果用這個邏輯的話去看現在的Meta，代表我們根本不需要去賭 AI 大模型能賺多少錢。

你只需要相信兩件事：核心廣告業務沒有崩盤(比20%增速要高)，以及龐大的硬體採購終究有見頂的一天(市場給出20x PE以上)。

至於未來額外長出來的算力出租（Meta Compute）、模型 API 或是訂閱服務，它們的票錢其實已經付了。

那 1,300 億至 1,450 億美元的資本支出，正是自由現金流只剩 7.84 億的原因。成本已經反映在被壓縮的 FCF 與新增折舊裡，市場目前給這些新業務的估值是零。

所以如果它們中獎，純屬上檔。但這句話有一個前提：不再加購。

而這個前提，恰恰就是下面第二個地雷。

4.9 真正的隱藏地雷（不在財務報表裡）

如果算式如此樂觀，投資人真正需要提防的風險是什麼？

反壟斷與青少年保護的法律重擊：

第二季認列的 24 億美元罰款可能只是前菜。

全美 29 州的聯合訴訟正在進行，若面臨極端判決，不僅賠償金可能高達數百億甚至千億級別，更危險的是法院若強制修改 Instagram 和 Facebook 的推薦演算法與產品架構，將直接傷及廣告本業的根基。

Zuckerburg的「無限軍備競賽」：

上述所有回報的前提，都是「資本支出終究會收斂」。

但如果管理階層在 2028 年後依然堅持擴軍、每年硬體支出衝破 1,500 億美元且完全不見頂，那麼現金流回血的劇本就必須全盤重算。

4.10 實戰追蹤：怎麼驗證本章的判斷？

本章的核心論點是：Meta 的估值取決於廣告營收曲線能否跑贏折舊曲線，而這場賽跑的結果由三個變數決定（4.3 的資本支出去向、4.5 的算力出租、4.6 的資本紀律）。

這三個變數，可以變成六個指標：

訊號一：廣告的量價結構

FoA 營收增速能否守住 20% 以上？更重要的是，增長是靠「量」（曝光量）還是靠「價」（單次廣告均價）？

如果量的佔比持續上升，要警惕用戶時長天花板與監管風險。這是 4.1 中量價拆分框架的實戰應用。

訊號二：CapEx 指引與 FCF 拐點

Susan Li 已明確表示「我們目前不提供 2027 年資本支出的具體展望」。

Q3 財報（預估 2026 年 10 月下旬）是否給出 2027 CapEx 數字，本身就是一個事件。給了且低於 1,800 億，可能觸發 re-rating。

繼續不給，折價延續。這是 4.8 中「CapEx 見頂後 FCF 噴發」劇本的行權條件。

訊號三：算力出租的商業化進度

Meta Compute 是否從傳聞變成公開的商業行為？如果出租伴隨明確的企業客戶名單與長期合約，這是正面的。

如果更像是短期去化閒置產能，需要警惕 4.5 中提到的「自己用不完」警訊。

訊號四：Muse 與 Contributor Tier 的數據飛輪

追蹤 Meta 是否繼續用 Muse 替代外部模型授權，以及 Contributor 層級是否成功吸引企業級 agentic 使用數據。

這決定了 4.3 中「從開源到閉源」的戰略轉向能否真正補上 B 端數據的缺口。

訊號五：表外資本承諾的規模

追蹤租賃承諾、合資義務與殘值保證的總額變化。如果這些表外承諾持續膨脹，即使財報上的 CapEx 看起來放緩，實際的資本負擔也沒有減輕。

訊號六：法律判決對產品設計的影響

29 州聯合訴訟的進展。真正需要留意的是法院是否下令修改推薦演算法或限制青少年使用時長，罰款金額反而次要。

如果發生，衝擊的是 4.1 中量價框架的「量」，也就是全部估值的支點。

結語 | 四大巨頭的底層分野與估值哲學

回顧整篇文章，微軟、亞馬遜、Google 和 Meta，這四家被稱為「Hyperscalers」的超級巨頭，在 2026 年共同面對著同一個時代命題：

如何在逼近 7,600 億美元的 AI 資本支出狂潮中，把燒出去的錢連本帶利地賺回來。

但如果你仔細拆解，會發現它們雖然都在蓋機房、買 GPU，賺錢的方式、商業邏輯與所處的戰略階段卻截然不同。

微軟是「企業級鐵三角」。

它賣的是捆綁的訂閱與算力，打的是「成本-產出」的防守戰。

它的業務高度交織，只需要用整體 P/E 估值，核心看點是Copilot的使用量，以及自研架構能否守住毛利率，等待 CapEx 見頂後的利潤釋放。

亞馬遜是「水平整合的收費站」。

它不執著於最強模型，只做所有模型必經的計費層。

它的業務極度分裂，必須用 SOTP 拆解。它的生存法則是「用量跑贏通縮」，核心看點是 Trainium 的成本壓制力與 Bedrock 的聚合效應。

Alphabet 是「垂直整合的自營者」。

它手握搜尋與 Android 的無敵分發渠道，上演著「三次 Android 劇本」，用低毛利換取生態地盤。它的搜尋與雲端風險特徵迥異，必須用 SOTP 拆解。

核心看點是 TPU 的四通道分配，以及 Gemini 能否守住雲端的高估值天花板。

Meta 則是「34 億用戶的廣告帝國」。

它沒有雲端 Backlog，卻免疫於對手方違約風險；它的變現是即時的，但必須獨自承受龐大的折舊浪。

核心看點是廣告營收曲線與折舊曲線的賽跑。

理解了這些底層分野，你就會明白，為什麼不能用同一套尺去衡量它們，更不能用同一個指標去預測它們的未來。

估值哲學：不要迷戀數字，要迷戀邏輯

在經歷了這四場硬核的拆解後，我們必須回到一個最根本的投資哲學問題：

我們花了這麼多篇幅去計算 P/E、EV/EBIT 和 SOTP，到底是為了什麼？

很多投資人對估值有一種誤解，認為估值模型能算出一個絕對精確的「目標價」，或者能直接給出一個「買入」或「賣出」的二元結論。

但事實上，無論是微軟的標準化 P/E，還是亞馬遜和 Google 的 SOTP，亦或是 Meta 的隱含增速推算，所有的估值模型裡都塞滿了假設。

CapEx 什麼時候見頂？毛利率能不能守住 45%？Anthropic 的 Backlog 會不會違約？廣告曝光量有沒有觸及天花板？只要這些假設稍微偏移 5%，算出來的目標價就會天差地別。

因此，不要迷戀估值模型算出來的那個「絕對數字」。

估值無法告訴你「亞馬遜明天一定漲到多少塊」，也無法讓你簡單粗暴地貼上「Meta 最便宜所以全倉買入」的標籤。

估值是「錨」，也是「條件反射的觸發器」

那麼，我們到底該怎麼使用這套估值框架？

第一，把它當作理解市場定價的「錨」。

估值的作用，是幫你拆解市場當前到底在為什麼買單。

當你算出市場隱含給 AWS 28.5 倍，給 Google Cloud 37 倍，或者隱含 Meta 只有 15% 到 20% 的增速時，你就看穿了市場的底牌。

你會清楚地知道市場當下的樂觀或悲觀程度，知道它已經把哪些風險計入價格、把哪些期權給了零估值。

第二，把它當作建立「If-Then（如果...那麼...）」條件反射的觸發器。

真正的機構投資人，是靠動態追蹤系統行事，只看目標價是散戶的做法。

當財報季到來時，你要看的是我們在這四章裡提煉出的那些「核心信號」，而非 EPS 比華爾街預期多了幾毛錢。：

  • 微軟的 Copilot 真實活躍度有沒有提升？Azure 毛利率有沒有守住？

  • 亞馬遜的 CapEx 增速有沒有低於營收增速？Trainium 有沒有外部大客戶買單？

  • Google 的 TPU 外售比例有沒有稀釋毛利？Vertex 上到底是 Gemini 賺錢還是 Claude 賺錢？

  • Meta 的廣告增長是靠量還是靠價？Zuckerberg 有沒有給出 2027 年的 CapEx 指引？

當這些信號亮起綠燈，證明你的核心假設成立，估值的邏輯就會向上切換（Re-rating）；當信號亮起紅燈，證明假設被證偽，估值邏輯就會向下重估。

最後的話

在 AI 這個十年一遇的技術大浪潮中，7,600 億美元的資本支出只是入場券。

這四家偉大的公司，正在用截然不同的商業智慧，試圖把龐大的算力轉化為真實的商業利潤。

作為投資人，我們的工作，是去看透它們各自的護城河、成本結構與變現路徑。

拋棄對單一指標的迷信，建立屬於你自己的估值錨點與追蹤信號。

當你真正理解了這篇分析，你的投資就有了底氣。
