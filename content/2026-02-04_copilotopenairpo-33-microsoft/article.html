為了笨拙的Copilot放棄外部客戶？OpenAI佔RPO這麼多怎麼辦？為什麼要增加資本支出？ - 深入分析第33期：微軟 Microsoft

2026 年 1 月 29 日，這一天在華爾街留下了濃重的一筆。

微軟（Microsoft），這家全球科技巨頭，在單一交易日內股價暴跌 10%，瞬間蒸發了約 3,570 億美元的市值。這是美股歷史上第二大的單日市值蒸發，也是微軟自 2020 年 3 月新冠疫情熔斷以來，最黑暗的一天。

回顧微軟上市 40 年的歷史，這種級別的恐慌性拋售屈指可數：

  • 1987 年黑色星期一： 全球股市崩盤，系統性風險。

  • 2000 年網路泡沫破裂： 納斯達克指數崩潰，估值回歸。

  • 2020 年疫情危機： 全球經濟停擺的恐慌。

然而，今天的暴跌與上述歷史事件有著本質的區別。這一次，沒有全球性的金融海嘯，沒有突發的病毒肆虐，甚至微軟自己交出的營收成績單都「超出了預期」。

事實上，這是一次針對「AI 投資回報率 (ROI)」的清算。市場不再為「AI 夢想」無腦買單，而是開始嚴厲懲罰那些為了未來增長而犧牲當下利潤的行為。

華爾街正在問一個價值 3,500 億美元的問題：微軟是否為了追逐 AI 的星辰大海，而燒掉了腳下的安全網？

在這篇深度分析中，我們將剝開財報的表象，深入微軟帝國的運作機理，你將讀到：

  • 歷史的輪迴： 為什麼今天的 AI 狂熱，像極了微軟當年錯過移動互聯網時的恐懼與反擊？

  • Azure 的兩難： 微軟是如何通過「內部算力階級制度」，犧牲雲端業務的短期利潤來餵養自家 AI 的？

  • Copilot 的真相： 為什麼 GitHub Copilot 是天才，而 Office Copilot 卻像個笨拙的管家？這兩者的命運將如何分野？

  • 千億豪賭的賬單： 微軟半年燒掉超過700 億美元資本支出，這些錢到底變成了什麼？是未來的護城河，還是昂貴的廢鐵？

  • OpenAI 的危險關係： 深度解剖微軟與 OpenAI 之間數千億美元的捆綁，以及雙方正在進行的「分手預演」。

  • 估值的底線： 如果 AI 泡沫破裂，微軟的股價地板在哪裡？現在是抄底的良機，還是接刀的時刻？

讓我們從這場歷史性的暴跌開始，重新審視這家科技巨頭的第三次蛻變。

序章：從歷史中看微軟的轉變

在我們打開微軟 Q2 FY2026 那份充滿爭議的財報之前，必須先理解這家公司的靈魂。

在 2000 年代初期，微軟不僅僅是一家科技公司，它是科技界的「水電公司」。

透過與 Intel 組成的「Wintel 聯盟」，微軟控制了全球 90% 以上的個人電腦。那時的商業模式堪稱完美：零邊際成本的軟體授權費 (Licensing Fee)。每賣出一台 PC，微軟就坐收過路費。這種躺著賺錢的模式帶來了驚人的毛利率（80%+），也滋生了致命的傲慢。

在那個時代，微軟的內部文化是充滿攻擊性的。他們忙於應付反壟斷訴訟，忙於消滅 Netscape，忙於保護 Windows 的統治地位。對當時的微軟來說，Windows 是太陽，所有其他業務（包括 Office 和 Server）都只是圍繞著太陽旋轉的行星。 任何威脅到 Windows 核心地位的創新，都會被視為異端。

1. 失去的十年：從 2007 到 Nokia 的前車之鑑

轉折點發生在 2007 年。當 Steve Jobs 站在舞台上發布 iPhone 時，當時的 CEO Steve Ballmer 做出了那個著名的回應：「500 美元？沒有鍵盤？這不僅是世界上最貴的手機，而且對商業客戶毫無吸引力。」

這句話成為了微軟「失去的十年」的註腳。

微軟誤以為用戶離不開實體鍵盤和 Office 文檔，卻沒看到世界正在轉向觸控與 App 生態。

當微軟終於驚醒時，他們陷入了拙劣的模仿。Zune 模仿 iPod，Bing 模仿 Google，Surface 模仿 iPad。他們從「領航者」變成了「追隨者」。

這種恐慌在 2013 年達到頂峰，微軟收購了 Nokia 的手機業務，試圖買一張移動時代的末班車票。兩年後，這筆交易被證明是災難性的，微軟被迫減記 76 億美元，幾乎賠光了收購款。

那時的微軟，股價長期在 30 美元死氣沉沉地徘徊。在矽谷眼中，它已經從「邪惡帝國」變成了「無關緊要的老人」。

2. 2014 年的抉擇：為什麼是 Satya Nadella？

2014 年，當 Ballmer 黯然下台時，微軟董事會面臨一個生死攸關的選擇。他們沒有選擇外部的明星經理人，也沒有選擇負責 Windows 核心業務的高管，而是選擇了當時負責「雲端與企業部門」的 Satya Nadella。

這是一個明確的信號：微軟準備告別自己的過去。

Nadella 上任後，做出了三個打破傳統的決策，正是這三點將微軟從懸崖邊拉了回來：

  1. 文化重塑： 他強推《心態致勝》(Mindset) 一書的理念，將微軟那種「無所不知」(Know-it-alls) 的有毒文化，轉變為「無所不學」(Learn-it-alls)。這是為了讓工程師們承認：我們在移動領域失敗了，我們需要學習。

  2. 打破禁忌 (Mobile First, Cloud First)： 他做了一件 Ballmer 絕對不會做的事，在 iPad 上發布了 Office 套件。這意味著微軟承認 Windows 不再是世界的中心，服務用戶（哪怕他們用的是蘋果設備）比保護 Windows 更重要。

  3. 雲端豪賭： 他將公司最優秀的人才和資源從 Windows 部門抽調到 Azure。當時 Azure 遠遠落後於 AWS，華爾街質疑微軟能否在低毛利的基礎設施戰爭中獲勝。Nadella 的回答是：巨額資本支出。 他開始在全球瘋狂建設數據中心。

結果我們都知道了：Azure 成為了微軟的新引擎，股價翻了十倍，微軟重回市值第一的寶座(當然現在不是)。

3. 歷史的迴響：今天的 AI 狂熱

理解了這段歷史，你就能讀懂今天這份財報的潛台詞。

目前的微軟，正處於這兩種歷史力量的交匯點：

  • PTSD 的陰影： 生成式 AI (Generative AI) 被視為比移動互聯網更大的平台轉移。微軟高層深知，如果這次像當年錯過 iPhone 一樣錯過 AI，Windows 和 Office 的護城河將在一夜之間被蒸發。這種恐懼是真實且劇烈的。

  • 雲端勝利的肌肉記憶： Nadella 堅信他 2014 年的劇本可以複製。當年的經驗告訴他：在平台轉型期，激進的資本支出不是浪費，而是入場券。 只要建立了規模效應，利潤終將滾滾而來。

因此，當我們看到微軟在 Q2 財報中無視利潤率下滑，堅持投入數百億美元購買 GPU 時，這是一種經過計算的生存本能。

他們寧願因為「過度投資」而被華爾街罵兩季，也絕不願因為「投資不足」而重回 2010 年的黑暗時代。

但問題在於，2026 年的 AI 戰場比 2014 年的雲端戰場更加殘酷。硬體折舊更快、競爭對手更強、變現路徑更模糊。微軟是否正在將「雲端時代的成功經驗」錯誤地套用在一個完全不同的「AI 戰局」上？

讓我們翻開第一章，從那份引發市場恐慌的財報中尋找答案。

第一章：估值的斷裂

當微軟的財報公佈時，一切看起來都像是這家科技巨頭的又一次勝利巡遊。

營收達到 813 億美元，超出預期；每股收益 (EPS) 飆升至 4.14 美元，同比增長 24%；最令人瞠目結舌的是，微軟雲端業務 (Microsoft Cloud) 在單一季度內突破了 500 億美元的營收大關。

這是一個歷史性的里程碑，僅僅是微軟的「雲端部門」，現在就已經比大多數財富 500 強公司的全年營收還要龐大。

按照傳統的劇本，香檳應該已經開了，股價應該在盤後上漲 3% 到 5%。

然而，劇本被撕碎了。在下一個交易日，微軟的股價並未慶祝，而是崩潰了，股價暴跌超過 10%，瞬間蒸發了3000多億美元的市值。這不僅僅是回調，這是美股歷史上第二大的單日市值蒸發慘案。

為什麼？因為這份財報揭示了一個真相：微軟正陷入一場代價高昂的戰爭，而勝利的代價正在吞噬利潤。

1. 39% 的增長瓶頸：Azure 的減速

引發拋售的第一根導火線，是微軟核心王牌：Azure。

在過去的兩年裡，Azure 的增長率是支撐微軟高估值的唯一支柱。但在這個季度，Azure 的營收增長率從上一季的 40% 滑落至 39%。雖然這仍然是一個驚人的數字，但對於習慣了「AI 驅動加速」敘事的投資人來說，這是一個警訊。更糟糕的是，管理層給出的下一季指引暗示增長將進一步放緩至 37-38%。

在電話會議上，CFO Amy Hood 試圖用一個技術性的解釋來安撫市場，但這個解釋反而加劇了恐慌。

她表示，Azure 的增長放緩並非因為需求不足，而是因為產能不足。

她透露了內部決策邏輯：微軟確實收到了大量的 GPU，但他們沒有將這些算力全部賣給 Azure 的外部客戶，而是優先分配給了內部的 AI 產品（如 Copilot）以及研發部門。

「如果我把這些 GPU 全部給 Azure，我們的增長率早就超過 40% 了。」

這句話揭露了微軟內部正在執行的「算力分配階級制度」。在這個制度中，微軟正在「擠壓」它利潤最高的外部客戶，以支撐它內部的 AI 野心。

以下是根據分析師推測的數字：

第一階級：Copilot 的特權與代價

處於這條食物鏈頂端的，是 Microsoft 365 Copilot 和 GitHub Copilot。根據分析，這部分內部業務佔據了約 25-30% 的 GPU 推理產能。

第二階級：擺脫依賴的研發豪賭

緊隨其後的是微軟的「B 計劃」，內部研發與基礎模型構建，佔據了 15-20% 的產能。

這是一個純粹的研發支出。微軟為什麼要這麼做？因為他們深知依賴 OpenAI 的風險。微軟正在訓練自己的 Phi 模型系列，這些模型體積小、成本低，甚至可以在本地設備上運行。這是微軟試圖將 AI 推理成本從昂貴的雲端轉移到用戶終端（Edge）的關鍵佈局。

另外，2026 年 1 月剛發布的 Maia 200 加速器，專為推理工作負載設計。微軟宣稱其性價比比現有 GPU 高出 30%。這不僅是為了省錢，更是為了在 NVIDIA 的供應鏈霸權中撕開一道口子。

第三階級：OpenAI 的黃金手銬

在滿足了內部需求後，微軟必須履行對 OpenAI 的合約義務。這部分佔據了 35-40% 的產能。雖然這保證了營收的底線，卻限制了利潤的上限。

因為這是基於「合約價」的交易，其利潤率（約 45-55%）遠低於公開市場的 Azure 定價。OpenAI 既是微軟最大的客戶，也是微軟產能最大的「產能佔用者」。

第四階級：被限制住的搖錢樹

處於食物鏈最底層的，竟然是微軟最賺錢的客戶：那些願意支付全額公開雲端價格的財富 500 強企業和新創公司。

這些外部 Azure 客戶只能分食剩餘的 15-20% 產能。這就是為什麼 Azure 的增長率停留在 39% 的根本原因。Amy Hood 承認，如果微軟將這些 GPU 賣給外部客戶，增長率本可以輕鬆突破 40%。

簡單來說，微軟正在犧牲確定的 Azure 收入，去換取 Copilot 的未來。

在算力資源有限的情況下，微軟選擇了優先發展自家的AI產品，而非租出去賺錢。但問題是，這些AI產品回報十分不確定，而將算力租出去回報則十分可觀。

2. 375 億美元的豪賭：資本支出的高速增長

如果說 Azure 的減速是導火線，那麼資本支出 (CapEx) 就是炸藥桶。

在這個季度，微軟花掉了 375 億美元用於資本支出。為了讓這個數字具象化：這比微軟四年前全年的支出還要多。

這筆錢去了哪裡？大約三分之二用於購買伺服器、GPU 和 CPU。這些是「短壽命資產」，意味著它們會在幾年內折舊完畢，對利潤率造成巨大的持續壓力。

這引發了投資人最深層的恐懼：AI 的投資回報率 (ROI) 缺口。

市場開始意識到，微軟正在以「戰時速度」燒錢，但營收卻仍在以「和平時期」的速度增長。營收增長了 17%，但營收成本 (Cost of Revenue) 卻增長了 19%。特別是在 Azure 部門，營收成本驚人地增長了 44%，遠超營收增幅（39%）。

原因是，微軟將內部研發和 Copilot 的推理成本計入了「營收成本」，而不是「研發費用（R&D Expense）」。這讓外界誤以為 Azure 的盈利能力在下降，但實際上，這是微軟在進行一場大規模的內部資本支出。

但從財報上看來，微軟每賺進一美元的新收入，都要付出比以往更高的代價。

3. OpenAI 的陰影：45% 的單點風險

最後一根稻草，來自於財報的一個不起眼的註腳，卻在電話會議中被分析師們反覆拷問。

微軟自豪地宣布其「剩餘履約義務」(RPO，即已簽約但未確認的收入) 暴增至 6,250 億美元。這本該是個好消息，直到管理層承認：這其中有 45%（約 2,810 億美元）來自於單一客戶：OpenAI。

這是一個令人窒息的比例。

華爾街突然意識到，微軟所謂的「積壓訂單激增」，很大程度上只是左手倒右手的遊戲：微軟投資 OpenAI，OpenAI 再承諾購買微軟的雲服務。如果 OpenAI 未來的融資出現問題，或者其商業化進程受阻，這 2,800 億美元的「未來收入」可能瞬間化為泡影。

這不再是分散風險的 B2B 業務，這變成了一個巨大的、集中的風險敞口。

4. 蜜月期結束

在2025年之前，只要你喊出 “AI”，華爾街就會為你買單。但在這大半年，華爾街開始查帳了。

微軟交出了一份「好」的成績單，但在這個資本支出爆炸的年代，「好」已經不夠了。市場在問一個更尖銳的問題：Satya Nadella 究竟是在建造通往未來的橋樑，還是在建造一座昂貴的空中樓閣？

更重要的是，過去，微軟是賣鏟子的平台（Azure）；現在，微軟正在變成一家與客戶爭奪資源的產品公司（Copilot）。

微軟正在建立一個龐大的基礎設施，但這個設施似乎更多是為了服務微軟自己和 OpenAI，而不是為了服務廣大的雲端客戶。微軟主動放棄了利潤率最高、需求最旺盛的外部業務，轉而將資源傾斜給內部尚未完全證明變現能力的產品。

這種「自我優先」的策略是一場豪賭。既然微軟願意為了 Copilot 和內部模型犧牲 Azure 的短期增長，那麼問題來了：

這個被微軟視為「掌上明珠」、處於食物鏈最頂端的產品，究竟值不值這個價？

第一章：估值的斷裂

  • 市場恐慌： 儘管營收超預期，但因資本支出（CapEx）過高及 Azure 增長放緩，引發史上第二大單日市值蒸發。

  • 內部階級制度： 微軟實施「算力配給制」，優先將 GPU 供給內部的 Copilot 和 OpenAI，導致外部 Azure 客戶產能受限，壓抑了 Azure 的增長率（39%）。

  • 利潤壓縮： 單季 375 億美元的資本支出顯示微軟處於「戰時狀態」，營收成本激增，利潤率承壓。

  • 單點風險： 45% 的剩餘履約義務（RPO）來自單一客戶 OpenAI，揭示了巨大的集中度風險。

第二章：昂貴的管家 – Microsoft Copilot 365

微軟在AI時代的標誌性產品，當然是Microsoft Copilot 365，盛惠企業中的每人每月30美元。

當企業客戶看著報價單時，他們通常會問出一個最直觀的問題：「為什麼我不直接用每個月 20 美元的 ChatGPT？甚至是用免費版？」

畢竟，它們背後不都是同一個 GPT模型嗎？

要回答它，我們不能把 Copilot 看作一個聊天機器人。事實上，如果你把 Copilot 當作聊天機器人來買，你就已經虧了。

在微軟的架構圖裡，Copilot 並非一個模型，而是一套複雜的「中間人系統」。

1. 不是大腦，是神經系統

想像一下，你聘請了一位絕頂聰明的哈佛畢業生（這就是 GPT模型）。他上知天文下知地理，但他有一個致命的缺陷：他對你公司一無所知。

如果你問他：「上週那個項目的預算超支了嗎？」這位哈佛天才會一臉茫然，因為他從未見過你的內部賬本。

這就是 ChatGPT 在企業環境中的困境。

而 Copilot for Microsoft 365，本質上不是那位哈佛畢業生，而是一位站在畢業生旁邊、手握你公司所有檔案鑰匙的「管家」。

這個管家屬於 「編排層（Orchestration Layer）」。當你在 Word 裡敲下一個問題時，Copilot 並沒有直接把問題丟給 AI。相反，它開始了一場名為 「接地（Grounding）」 的瘋狂數據狩獵：

  1. 狩獵開始：Copilot 首先衝進一個名為 Microsoft Graph 的巨大數據庫。這裡存儲著你公司所有的數字足跡：你昨天發出的郵件、上週 Teams 會議的錄音逐字稿、躺在 SharePoint 角落裡的 Excel 表格。

  2. 拼湊真相：它從這些碎片中抓取相關信息。比如，它找到了那封標題為「Q4 預算修正」的郵件，以及附件裡的 PDF。

  3. 呈遞情報：只有在收集完這些「私有情報」後，Copilot 才會轉身，將你的問題連同這些情報一起打包，發送給那位哈佛畢業生（GPT）。

  4. 最終回答：GPT閱讀了情報，結合它的邏輯能力，給出了一個基於你公司真實情況的答案。

這就是為什麼 Copilot 每月要收 30 美元。你買的不是 AI 的智商（那個到處都能買到），你買的是讓 AI 安全讀懂你公司機密的能力。

2. 隱形的護城河：權限的迷宮

但這還不是最貴的部分。

對於一家擁有 10,000 名員工的大企業來說，最大的恐懼，其實是 AI 「知道得太多」。

試想一下，如果一個實習生問 Copilot：「公司薪資最高的人是誰？」而 Copilot 真的去讀取了 CEO 的薪資表並回答了，那將是一場災難。

這就是微軟真正的護城河，也是企業無法簡單使用 ChatGPT 的原因。Copilot 的核心算法中嵌入了一套嚴苛的權限過濾機制。

在它去 Microsoft Graph 抓取數據的那一毫秒裡，它會同時檢查發問者的身份權限。它會像一個盡職的保全，確保實習生只能看到實習生該看的文檔。如果某份文件對該用戶是「保密」的，Copilot 就會假裝那份文件不存在。

這是一項浩大的工程。微軟實際上是在向企業兜售一種「合規的懶惰」：

  • 選項 A（自建）：企業自己租用 OpenAI 的 API，然後自己花費數百萬美元、耗時 18 個月去開發一套能連接內部數據庫、還能完美處理權限管理的系統。

  • 選項 B（Copilot）：直接付錢給微軟，明天就能用。

微軟賭的就是：大企業寧願付費買現成的管家，也不願自己花錢去培養一個管家。

3. 算力的魔術：動態調包

還記得第一章裡提到的「算力階級制度」嗎？在 Copilot 的運作中，微軟還玩了一個聰明的成本魔術。

雖然對外宣傳總是綁定 GPT，但實際上，Copilot 是一個極其精明的模型調度員。

當你只是讓它「潤色一封郵件」時，它根本不會去打擾昂貴的 GPT。它會悄悄調用微軟自研的 Phi-3 或 Phi-4 小模型。這些模型體積小、反應快，最重要的是便宜。

只有當你要求它「分析這份 50 頁的財報並與去年的數據做對比」這種重活時，它才會切換到 GPT 這種重型武器。甚至在某些複雜的推理場景下，它可能會調用 Anthropic 的 Claude 模型作為補充。

這一切都在後台毫秒級發生，用戶毫無察覺。這就像你以為你每次都叫了豪華轎車，但實際上平台會根據路況，有時派來的是省油的小型車。這就是微軟在保證用戶體驗的同時，試圖從那 30 美元月費中擠出利潤的關鍵手段。

4. 完美的商業閉環？

至此，微軟似乎構建了一個完美的商業閉環：

  1. 利用 Office 的壟斷地位，將 Copilot 塞進每個人的工作流。

  2. 利用 Microsoft Graph 的數據壁壘，讓競爭對手（如 Google 或 OpenAI）無法觸及企業的核心數據。

  3. 利用複雜的合規需求，讓大企業不敢輕易嘗試自建方案。

從理論上講，這是一台印鈔機。這解釋了為什麼 Satya Nadella 願意犧牲 Azure 的短期增長來餵養它。他看到的是企業軟體的終極形態，一個你一旦用上，就再也離不開的「全知管家」。

但理論與現實之間，往往隔著一道巨大的鴻溝。

就在微軟以為這套邏輯無懈可擊時，現實給了他們一記響亮的耳光。當這套昂貴的系統真正部署到客戶那裡時，人們發現，這位「全知管家」不僅經常撒謊，而且還有一個致命的壞習慣：它非常依賴它的主人是否把家裡收拾乾淨。

而大多數企業的家裡，亂得像個垃圾場。

第二章：昂貴的管家 – Microsoft Copilot 365

  • 產品定位： Copilot 不僅是聊天機器人，更是連接企業數據（Microsoft Graph）與大模型的安全「編排層」。

  • 成本控制： 為維持利潤，系統會動態切換模型，簡單任務使用低成本的小模型（Phi），複雜任務才調用昂貴的 GPT-4。

  • 商業護城河： 微軟賭的是企業對數據安全與合規的需求，而非單純的模型智商。

第三章：笨拙的管家與隱藏的黃金

當Copilot這位管家興沖沖地走進企業的檔案室準備大顯身手時，他被眼前的景象驚呆了。

大多數企業的數據後台，並不像微軟演示影片中那樣井井有條。它們更像是一個經歷了二十年無人打掃的圖書館。這裡有十個版本的「2023_1st edit_final_v2.ppt」，有無數個被遺忘在 SharePoint 角落的文件夾，還有大量未經標記的無效數據。

這就是 Copilot 遭遇的第一個，也是最致命的敵人：垃圾進，垃圾出（Garbage In, Garbage Out）。

1. 幻覺與失望的低谷

當一家財富 500 強企業興奮地部署了 Copilot，第一週通常是充滿好奇的蜜月期。但到了第二週，抱怨聲開始出現。

員工問：「上個季度的營銷策略是什麼？」

Copilot 自信地回答了一個策略，並引用了一份文檔。

員工點開一看，發現那是 2019 年的一份廢棄草稿，只是因為文件名裡剛好有「營銷策略」四個字。

這不是 AI 笨，是因為企業的數據太髒了。Copilot 就像一輛法拉利，但大多數企業提供的是泥濘不堪的土路。

這種「期望落差」並非個案，而是普遍現象。Gartner 在 2025 年 6 月發布的一份針對 215 位 IT 領袖的調查報告，揭開了企業的情況：

  • 試點煉獄： 儘管 94% 的企業聲稱看到了某種程度的好處，但高達 72% 的企業仍被困在試點階段，遲遲無法推進。僅有 6% 的企業完成了全球範圍的全面部署。

  • 價值存疑： 對於這個每人每月 30 美元的昂貴工具，只有 12% 的企業報告了「顯著的商業價值」。相反，47% 的人認為僅是「有點價值」，更有 6% 的人直言「毫無價值」。

  • 執行鴻溝： 正如 Gartner 分析師 Dan Wilson 在雪梨大會上的一針見血評論：「微軟的營銷是天才級的，但執行力卻沒跟上。」他指出，企業發現要找到足夠的 ROI（投資回報率）來證明全面部署的合理性，仍然「相當具有挑戰性」。

這解釋了為什麼在財報電話會議上，雖然微軟宣佈 Copilot 用戶達到了 1500 萬（這本身是個巨大的數字），但相較於 Office 龐大的 4.5億商業用戶基數，這仍然只是九牛一毛。滲透率還不到 5%。

許多企業處於「觀望」狀態：買了 50 個帳號給高管和 IT 部門玩玩，但面對 Gartner 報告中那 35% 認為「收益微乎其微」 的反饋，CIO 們遲遲不敢簽下全公司的訂單。

2. 為什麼 Copilot 看起來比 ChatGPT「笨」？

除了數據髒，還有一個困擾無數用戶的謎題：明明都是基於 GPT技術，為什麼免費的 ChatGPT 能寫出漂亮的代碼，而每月收費 30 美元的 Copilot 卻經常拒絕回答，或者給出一堆廢話？

這是因為是企業級的安全銬鐐把它鎖住了：

  • 只動口不動手（執行鴻溝）：
    當你讓 ChatGPT「把 B 列的所有數字增加 10%」，它會給你一段代碼或公式，你自己去貼。但當你對 Excel Copilot 下同樣的指令時，你期待它直接幫你改好表格。然而，出於安全考慮（防止 AI 毀壞你的財務報表），Copilot 被設計成「沙盒模式」，它往往會給你列出 10 個步驟的「操作指南」，讓你手動去點。

用戶感受：「我都花錢買 AI 了，還要我自己動手？這不是懶，這是蠢。」

  • 過度的內容過濾：
    微軟對 Copilot 施加了比 OpenAI 嚴格得多的內容過濾。因為如果 ChatGPT 說錯話，那是 OpenAI 的事；但如果企業版 Copilot 在銀行或醫院裡胡言亂語，微軟可能面臨巨額訴訟。
    結果是，當你讓它寫一份「激進的營銷策略」或總結一封帶有敏感詞的郵件時，Copilot 經常會觸發審查機制直接拒絕，而 ChatGPT 卻能輕鬆完成。這讓 Copilot 看起來像個膽小怕事的實習生。

  • 數據磨損與失憶（上下文遺忘）：
    雖然 Copilot 號稱能讀取你的所有文檔，但每次查詢它都要經歷繁瑣的流程：檢索 SharePoint、檢查權限、過濾敏感信息。這個過程消耗了大量的算力（Token），導致留給「記憶」的空間變小了。
    現象： 用戶經常發現，聊了五句之後，Copilot 就忘了第一句在說什麼，它的腦容量被「合規性檢查」佔滿了。

3. 門外的野蠻人——Claude 的挑戰

就在微軟的 Office Copilot 還在企業的數據泥沼中艱難跋涉時，一個危險的信號從矽谷傳來：競爭對手 Anthropic 旗下的 Claude，正在不斷推出令人振奮的新產品。

Anthropic 的總營收預計在 2025 年底達到 90 億美元，其中 80% 來自企業客戶。這說明了一個事實：企業並非不願意為 AI 買單，他們只是不願意為「還沒準備好」的 AI 買單。

為什麼會這樣？

A. 治理的死結 vs. 開箱即用的安全

微軟的戰略是「平台捆綁」：將 Copilot 深度嵌入 M365 全家桶。這聽起來很美，但落地卻成了噩夢。

因為 Copilot 會同時檢索 SharePoint、Teams 和 OneDrive，它實際上變成了一個高效的「合規漏洞掃描器」。它會無情地暴露企業每一個數據治理的漏洞（例如：每個人都能搜到 CEO 的薪資單）。這導致了一種「雞生蛋」的死結：企業想用 Copilot，就必須先治理數據；但數據治理工程浩大，導致 Copilot 被無限期推遲。

相比之下，Claude 採取了截然不同的策略，這讓它成為了企業的「解藥」：

Claude 不要求接管你所有的數據庫。它更像是一個被請進特定會議室的外部顧問。企業不需要重構整個數據架構，只需要通過 API 將特定的、乾淨的數據「餵」給它。這種「外科手術式」的部署，讓企業可以繞過數據治理的泥沼，即刻上線。

B. 從開發者包圍辦公室

最讓微軟頭痛的是，Claude 偷師了微軟最擅長的策略：「農村包圍城市」。

微軟試圖直接向 CEO 兜售「全公司的生產力提升」，這是一個模糊且難以衡量的承諾。
而 Claude 選擇了從「開發者」切入。Claude Code 專注於代碼生成、測試和部署——這些任務的 ROI 是清晰可見的（軟體交付速度提升 15-25%）。

企業先是為了寫代碼買入 Claude，然後發現它在文檔分析和專業領域也很好用，於是迅速擴展到全公司。這就是標準的「Land and Expand（登陸並擴張）」策略。

現在，微軟面臨著一個尷尬的局面：它的 Office Copilot（管家）還在學著怎麼不打碎盤子，而門外的 Claude 已經憑藉著精準的 ROI 計算和合規優勢，開始蠶食微軟原本以為固若金湯的企業市場。

4. 隱藏的信號：10 倍的活躍度

如果故事只停留在這裡，那就是一場災難。但如果我們剝開那些抱怨，會發現數據中隱藏著一個反轉信號。

微軟在 2026 年初的財報電話會議中透露了一個關鍵指標：雖然用戶基數增長平穩，但每日活躍用戶數（DAU）同比增長了 10 倍。

這意味著什麼？這意味著市場正在兩極分化：

那些把 Copilot 當作搜索引擎用的人，很快就會放棄，覺得它「笨」。但那些學會了「提示工程（Prompt Engineering）」、懂得讓 Copilot 幫忙寫會議紀要、起草郵件草稿、分析 Excel 趨勢的用戶，展現出了驚人的黏性。

對於這些人來說，Copilot 就像是從撥號上網升級到了光纖。一旦習慣了「一句話生成 PPT 大綱」，就再也無法忍受面對空白幻燈片發呆的日子。

一位華爾街分析師在報告中寫道：「Copilot 目前就像是 90 年代的 Excel。剛出來時，會計師們覺得它難用且昂貴。但一旦他們學會了公式，Excel 就變成了他們身體的一部分。」

微軟正在賭這種「不可逆的習慣養成」。只要這 1500 萬種子用戶養成了依賴，他們就會成為企業內部最強的推銷員。

5. 關鍵轉折：主動披露數據的自信

因此，在這份最新的財報中，微軟做了一個非常大膽的舉動：他們開始單獨披露 Copilot 的具體用戶數字：1500 萬商業用戶。

乍看之下，相較於 Office 龐大的 4 億商業用戶基數，1500 萬（滲透率不到 5%）並不是一個驚豔的數字。但這裡隱藏著一個巨大的信號：

當一家巨頭開始主動披露某項業務的具體指標，即使數字目前還不完美，也代表了管理層對未來增長曲線的絕對自信。

他們敢於把這個數字放在聚光燈下，是因為他們確信這個數字在未來幾個季度會有爆發式的增長，改進空間巨大。

SemiAnalysis 給出了一個有趣的洞察：目前的增長並非來自「有機需求」，而是來自「合同續簽」。

大多數企業與微軟簽訂的是 2-3 年的長期合同。當合同到期時，微軟的銷售代表會給出一個無法拒絕的打包方案（Bundle）：續簽 Office 365，我們順便把 Copilot 加進去，給你打個折。

這就解釋了為什麼主動購買率只有 3.3%，但滲透率預計會跳升至 15-20%。企業是被「順勢導入」地帶入 AI 時代的。

6. ARPU 的魔法：不需要每個人都買單

從財務角度看，微軟其實不需要每個人都用 Copilot 就能賺大錢。

這是一個簡單的數學題。Office 365 的商業版平均每用戶收入（ARPU）大約是每月 10 到 20 美元。

而 Copilot 的定價是額外的 30 美元。

這意味著，哪怕只有 10% 的員工（通常是高薪的知識工作者、分析師、管理層）訂閱了 Copilot，微軟從這家公司獲得的總收入就能瞬間翻倍。

這是一種極其強悍的商業模式。微軟不需要說服前台接待員或倉庫管理員使用 AI，它只需要說服那些時間最值錢的人：「你的時間每小時值 100 美元，花 30 美元買一個月能幫你省下 5 小時的工具，你買不買？」

答案通常是肯定的。

7. 黎明前的修補

站在 2026 年初，我們看到的是一個典型的「青春期」產品。

微軟顯然聽到了市場的罵聲，並在 1 月發布了針對性的更新（如 Agent Mode 下放、Copilot Notebook 修復幻覺、治理工具上線）。

對於投資者來說，關鍵不在於現在的 3.3% 採用率，而在於那 10 倍增長的活躍度以及微軟敢於公開數據的底氣。這證明了 AI 不是虛火，只要微軟能修好那些「笨拙」的毛病，Copilot 依然掌握著通往未來的鑰匙。

然而，就在這位穿著西裝的「管家」還在辦公室裡跌跌撞撞時，在微軟帝國的另一個角落，一位穿著帽衫的「極客」卻發展得相常順利。

第三章：笨拙的管家與隱藏的黃金

  • 用戶落差： 嚴格的安全過濾與沙盒模式，讓 Copilot 體感上比 ChatGPT「笨拙」，導致許多企業卡在試點階段。

  • 隱藏信號： 儘管滲透率低（<5%），但日活躍用戶（DAU）增長 10 倍，顯示掌握「提示工程」的用戶黏性極高。

  • 增長策略： 微軟主動披露 1500 萬用戶數據，展現對未來改進與增長的自信。

  • 商業模式： 依靠企業合約續簽的捆綁銷售，即使主動購買率不高，滲透率仍將被動提升。

第四章：矽谷的叛逆之子——GitHub Copilot

如果說 Microsoft Copilot 365 是一位穿著西裝、謹小慎微、還在努力適應辦公室政治的「管家」，那麼 GitHub Copilot 就是一位穿著帽衫、不修邊幅、但效率驚人的「天才極客」。

就在華爾街分析師還在思考 Office Copilot 的 3.3% 滲透率的意義時，在另一個平行宇宙裡——全球 1.8 億開發者的代碼世界中——一場真正的革命已經完成了。

這裡沒有「試用期的觀望」，只有瘋狂的擁抱。

1. 75 億美元的豪賭與「代碼的直覺」

要理解 GitHub Copilot 的成功，我們必須把時鐘撥回 2018 年。

當時，微軟宣佈以 75 億美元收購 GitHub。這在當時被視為一場豪賭，甚至引發了開源社區的恐慌（人們擔心微軟會毀了這個代碼聖地）。但 Satya Nadella 看到了別人沒看到的東西：數據。

GitHub 擁有全球最大的開源代碼庫。這不僅僅是代碼，這是人類邏輯的精華，是數十億行被驗證過的「問題解決方案」。

當 OpenAI 的 GPT 模型出現時，微軟意識到他們手裡握著一把鑰匙。他們將 GPT 的語言能力與 GitHub 的代碼庫結合，誕生了 GitHub Copilot。

與 Office 場景中模糊的「幫我寫個方案」不同，代碼的世界是非黑即白的。代碼只有兩種狀態：能跑，或者報錯。這種確定性，讓 AI 在編程領域的表現遠遠超過了寫作領域。

2. GitHub Copilot的數據

同樣，在 Q2 財報電話會議上，微軟也首次正式披露了 GitHub Copilot 的詳細訂閱數據。

在此之前，微軟對此一直沒有公佈實質數字，外界只能靠猜測。但這一次，數字被擺在了聚光燈下：

  • 付費訂閱用戶： 470 萬（同比增長 75%）。

  • Pro+ 高級訂閱增長： 季度環比增長 77%（這意味著大量開發者正在從基礎版升級到更昂貴的高級版）。

  • 年經常性收入（ARR）：已突破 20 億美元。

  • 企業採用率： 財富 100 強企業中，超過 90% 都在使用。

這些數字傳遞了一個清晰的信號：GitHub Copilot 不再是一個實驗品，它是目前 AI 領域唯一真正實現了規模化變現和強產品市場契合的殺手級應用。

相比之下，Office Copilot 的增長雖然也在繼續，但更多是依賴於企業合約的捆綁銷售，而 GitHub Copilot 的增長則源於用戶的主動選擇，開發者們用腳投票，甚至自掏腰包也要使用它。

3. 為什麼它比 Office Copilot 更成功？

為什麼同樣是 Copilot，命運卻如此不同？

  • 沒有數據治理的噩夢：
    Office Copilot 需要先整理好公司那堆亂七八糟的文檔才能工作。但 GitHub Copilot 不需要。它直接讀取你當前的代碼文件，理解你的函數邏輯。對於開發者來說，它開箱即用，不需要先花三個月去「打掃衛生」。

  • 即時的反饋迴路：
    當 Office Copilot 寫了一段錯誤的營銷文案，你可能要讀完才能發現。但當 GitHub Copilot 寫了一段錯誤的代碼，編譯器會立刻報錯。開發者能在一秒鐘內判斷 AI 的建議是否有用。這種極速的反饋機制，讓人類與 AI 建立了極強的信任感。

  • 成癮性體驗：
    對於習慣了 Copilot 的程序員來說，關掉它就像是突然失去了一隻手。數據顯示，約7成的付費用戶每週都在使用它。一旦你習慣了打出 function calculateTax 然後按一下 Tab 鍵讓 AI 補全剩下的 20 行代碼，你就再也無法忍受逐字敲擊的痛苦了。

4. 技術架構的差異：不只是一個模型

GitHub Copilot 的成功不僅僅是因為它「早」，更是因為它在技術架構上比 Office 版更靈活、更激進。

在 Office 版裡，微軟為了合規，強制所有用戶使用同一套安全過濾後的模型。但在 GitHub Copilot 裡，微軟賦予了開發者選擇權。

這裡有四層架構：

  1. 模型層（The LLMs）： 它不再只依賴 OpenAI。開發者可以根據任務需求，在 OpenAI 的 GPT、Anthropic 的 Claude 甚至是 Google 的 Gemini 之間切換。寫簡單代碼用快模型，做複雜架構設計用聰明模型。這種靈活性在 Office 版中是不可想像的。

  2. 執行層（Execution）： 它極度優化了延遲。為了跟上程序員打字的速度，實時補全的延遲被壓縮到了 200 毫秒。

  3. 編排層（Orchestration）： 這是真正的黑科技。它不僅僅是把代碼發給 AI，它會掃描你打開的所有文件、你最近瀏覽的代碼庫，甚至是你同事寫的模塊，把這些「上下文」餵給 AI。這讓它看起來像是懂你整個項目的老手，而不是一個只會背語法的實習生。

  4. 體驗層（UX）： 它無縫集成在 VS Code 等開發工具中。開發者不需要切換窗口去網頁上問 AI，AI 就住在他們的指尖下。

5. 從「工具」到「有線電視」

但你可能會問，現在也有不少如 Cursor 編輯器或 Anthropic 的 Claude Code的Coding助手。然而，Satya Nadella 在早前接受訪問時曾經說過，「我喜歡這種競爭格局。」

這背後隱藏著GitHub更深層的「聚合者戰略」。

Nadella 將 GitHub 比喻為 AI 時代的「有線電視系統」。在這個比喻中，OpenAI、Claude、Google 的模型就像是不同的「電影製片廠」，而 GitHub 是那個擁有 1.8 億觀眾的「頻道」。

微軟不再執著於讓開發者只使用自家的模型。通過推出 Agent HQ（智能體總部） 等功能，GitHub 正在將自己變成一個調度中心。開發者可以在這裡指揮各路 AI 智能體協同工作：用 Claude 分析架構，用 GPT 生成代碼，用微軟自家的 Agent 進行測試。

這種策略將競爭對手轉化為生態系統的一部分。只要開發者還是在 GitHub 這個「作業系統」上進行開發，還是在 VS Code 這個「介面」上敲擊鍵盤，微軟就不在乎底層調用的是誰的模型。它目標是從「單一選手」升級成了「賽事主辦方」。

6. 兩種 Copilot，兩種命運？

將這兩款產品放在一起對比，我們看到了一幅有趣的圖景：

  • Microsoft 365 Copilot 試圖解決的是「組織效率」問題。這很難，因為組織是複雜的、數據是髒亂的、流程是僵化的。所以它走得慢，步履蹣跚，還在經歷「青春期」的陣痛。

  • GitHub Copilot 解決的是「個人生產力」問題。這相對簡單，因為代碼是邏輯的、反饋是即時的。所以它跑得快，已經成為了開發者的「外骨骼」。

但對於微軟來說，這兩者缺一不可。

GitHub Copilot 是先鋒部隊，它證明了 AI 確實能讓專業人士的效率翻倍（數據顯示開發速度提升了 55%）。它為微軟賺取了第一桶金，更重要的是，它贏得了全球最具影響力的人群：開發者的心。

而 Microsoft 365 Copilot 是主力軍團。雖然它現在行動緩慢，但它面對的是全球 12 億知識工作者的廣闊戰場。一旦 GitHub Copilot 驗證過的技術（如 Agent 模式、多模型切換）被移植到 Office 版，一旦企業完成了數據治理，主力軍團的推進速度將是驚人的。

但這裡有一個殘酷的財務現實：無論這兩支軍團跑得有多快，光靠賣「人頭費」的軟體訂閱，似乎趕不上微軟燒錢的速度。

第四章：矽谷的叛逆之子 – GitHub Copilot

  • 成功對比： 與 Office Copilot 的掙扎不同，GitHub Copilot 已獲 470 萬付費用戶與 20 億美元營收，是真正的殺手級應用。

  • 成功原因： 代碼反饋即時（能跑或報錯），無需清洗數據，且能顯著提升開發者效率。

  • 技術架構： 採用更靈活的多模型架構（可選 OpenAI、Claude 等）與極低延遲優化。

  • 戰略地位： GitHub Copilot 是驗證 AI 變現能力的先鋒，而 Office Copilot 則是進攻廣大市場的主力軍。

第五章：填補千億美元黑洞——Copilot Studio 與「特工」的崛起

即使我們樂觀地假設 Microsoft 365 Copilot 已經擁有了 1500 萬付費用戶，按每月 30 美元計算，它每年帶來的經常性收入（ARR）大約是 50 億美元。

聽起來很多？但請看另一邊的賬單：僅在 2026 財年的上半年，微軟在 Azure 和 AI 基礎設施上的資本支出（Capex）就高達 724 億美元。

這意味著，微軟目前最引以為傲的 AI 旗艦產品，其全年的收入甚至只能覆蓋半年基建支出的 7.5%。(當然，資本支出並不是只為了AI產品，但大家可以有個大概體感)

微軟需要新的增長引擎。它不能只賣「魚」，它必須教會企業「養魚」。這就是 Copilot Studio 登場的時刻。

1. 什麼是 Copilot Studio？從「閒聊」到「特工」的戰略急轉彎

如果說 M365 Copilot 是一個通用的、什麼都懂一點但什麼都不精通的「大學畢業生」，那麼 Copilot Studio 就是一所「職業技術學校」。它是一個低代碼開發平台，允許企業不寫一行代碼，就「生成」出一個專用的 AI 助手。

但在 2026 年初，這個產品經歷了一場劇烈的身份認同轉變。

在 2024 年之前，它的前身（Power Virtual Agents）主要被用來做那些笨拙的客服聊天機器人（Chatbot）。但在 2025 年末至 2026 年初，微軟進行了一次生死攸關的戰略重塑：從「Chatbot（聊天機器人）」轉向「Agent（智能體/特工）」。

Copilot Studio 就是製造這些 Agent 的工廠。

微軟定義的 Agent 不再是被動等待指令的僕人，而是具備「自主權（Autonomy）」的數字員工。

它們到底能做什麼？ 讓我們看看微軟展示的真實能力圖譜：

  • 自主觸發（Autonomous Triggers）：
    以前的機器人需要你@它才會醒。現在的 Agent 像獵人一樣潛伏。

    • 場景：一個 Agent 監控著 SharePoint 文件夾。一旦有人上傳了新的供應商合同，它自動醒來，讀取合同條款，提取付款日期，並在 SAP 系統中創建付款計劃，全程不需要人類介入。

    • 場景：當 Planner 看板上出現一個「緊急」標籤的任務時，Agent 自動在 Teams 裡拉群，把相關負責人拽進來，並把任務背景資料匯總發在群裡。

  • 複雜編排（Orchestration）：
    Agent 不再是單兵作戰，它們開始像工廠流水線一樣協作。

    • 順序協作：一封客戶投訴郵件進來 -> 分類 Agent 讀取並標記為「嚴重」 -> 路由 Agent 把它轉發給資深客服 -> 處理 Agent 同時去查閱該客戶的歷史訂單並生成賠償方案草稿。

    • 並行協作：新員工入職 -> 賬號 Agent 去開通郵箱 -> 培訓 Agent 去註冊課程 -> 行政 Agent 去預定工位。五個 Agent 同時開工，將入職流程從 3 天縮短到 3 分鐘。

  • 真實世界的戰績：
    太平洋煤氣電力公司（PG&E） 部署了 Agent 來自動化 315 個業務流程，每年節省了 52.7 萬小時（相當於 250 多名全職員工的工作量）。

2. 商業模式的進化：從「人頭稅」到「消耗量」

微軟在 Copilot Studio 上採用了一種更為激進的收費模式，這也是它填補那 724 億美元 Capex 的秘密武器。

M365 Copilot 收的是「人頭稅」（每人每月 30 美元）。這有上限，因為員工數量是有限的。

但 Copilot Studio 的 Agent 採用的是「消耗量」計費（基於消息數量或計算單元）。

  • 基礎許可：每租戶每月 200 美元（含 25,000 條消息）。

  • 超額部分：按消息量計費。

這意味著什麼？這意味著收入沒有天花板。

想像一下，一家物流公司構建了一個「訂單追蹤 Agent」，每天處理 10 萬次客戶查詢。這不需要 10 萬個員工賬號，但它會消耗海量的 Azure 算力。

這才是微軟真正的算盤： 表面上是在賣軟件，實際上是在賣底層的算力（Azure OpenAI Service）。每一個被創建出來的 Agent，都是一個不知疲倦的「員工」，源源不斷地為微軟的數據中心貢獻收入。如果微軟能讓 5 萬家企業每家運行 50 個活躍 Agent，這將是一個數十億美元的新金礦。

3. 擁擠的戰場：誰在圍獵微軟？

微軟並不是唯一看到「Agent」未來的玩家。這是一個價值千億美元的戰場，所有巨頭都在磨刀霍霍。

  • Google (Vertex AI Agents)：Google 在基礎設施和推理能力上是微軟最強勁的對手。Gartner 甚至將 Google 列為企業 Agent 平台的技術領導者。Google 的優勢在於其強大的底層模型（Gemini）和雲原生架構。

  • Amazon (AWS Bedrock)：如果說微軟是「封閉花園」（強綁定 OpenAI），亞馬遜則扮演了「軍火超市」的角色。通過 Amazon Bedrock，企業可以輕鬆構建 Agent，並且隨意切換大腦：今天是 Claude，明天是 Llama，後天是 Mistral。

  • Salesforce (Agentforce)：Salesforce 佔據了 CRM 這個最肥沃的領地。對於銷售和客服場景，企業更傾向於使用 Salesforce 原生的 Agent，而不是微軟的。

  • ServiceNow (Now Assist)：當微軟試圖接管辦公室時，ServiceNow 正在接管企業的「後台運作」。在 IT 服務管理 (ITSM) 和人力資源流程中，ServiceNow 的 Agent 已經根深蒂固。如果你的電腦壞了，或者需要申請休假，你更有可能是在和 ServiceNow 的 Agent 對話，而不是 Copilot。

  • OpenAI (AgentKit)：雖然是盟友，但在開發者心中，OpenAI 的原生工具更靈活、更輕量。許多硬核開發者更願意直接用 OpenAI 的 API 手搓 Agent，而不是被困在微軟的低代碼框框裡。

微軟的護城河在哪裡？

兩個字：「集成（Integration）」。

只有微軟擁有 Office 365 和 Dynamics 365 的數據。當你需要一個 Agent 能同時讀取 Outlook 郵件、Teams 聊天記錄和 SharePoint 文檔時，Copilot Studio 是唯一的選擇。微軟賭的是，企業的數據重力（Data Gravity）最終會戰勝技術上的細微差別。

4. 數據的狂歡與隱藏的真相：23 萬家企業的「虛實」

根據微軟最新的數據，已經有 230,000 家組織在使用 Copilot Studio。這個數字在短短一年內翻了數倍。更重要的是，財富 500 強企業中，有 90% 都在使用它。

但我們必須剖析這個數字：「使用（Using）」不等於「部署（Deployed）」。

微軟對「使用」的定義非常寬鬆：只要有一個團隊成員在過去 30 天內登錄過 Copilot Studio，或者在黑客馬拉松裡試著捏了一個原型，這家公司就被算作「用戶」。

然而，真正的生產環境部署（Production Deployment），即那些真正接管了業務流程、觸碰實時數據的 Agent，比例可能不到這 23 萬家的 5%。

5. 挑戰：誰來監管這些「數字員工」？

儘管前景誘人，Copilot Studio 目前也面臨著巨大的挑戰，這也是為什麼它還沒有完全爆發的原因：治理的恐懼。

當企業只有 10 個員工時，管理很簡單。但如果企業裡突然多出了 1000 個由不同部門員工隨手創建的 AI Agent，誰來管理它們？

  • 如果財務部的 Agent 錯誤地批准了一筆報銷怎麼辦？

  • 如果銷售部的 Agent 對客戶承諾了錯誤的折扣怎麼辦？

  • 如果一個 Agent 開始無限循環調用 API，產生了巨額賬單怎麼辦？

目前，Copilot Studio 的「管理後台」還追不上它的「製造能力」。CIO 們對此感到恐慌，他們擔心這些失控的 Agent 會成為新的安全漏洞。這導致許多企業雖然在試用，但遲遲不敢將關鍵業務完全交給這些 Agent。

微軟顯然意識到了這一點，在 2026 年 1 月緊急推出了 Microsoft Agent 365 治理平台，試圖給這些「數字員工」發身份證、設權限。這場「治理」與「創新」的賽跑，將決定 Copilot Studio 能否真正落地。

6. 這是微軟的「登月計劃」

回到最初的那個財務難題。

M365 Copilot （那個穿西裝的管家）負責提升「人的效率」，賺取高額的訂閱費。
GitHub Copilot （那個穿帽衫的極客）負責提升「開發者的效率」，鎖定技術生態。
而 Copilot Studio （特工工廠）則負責「替代流程」，通過消耗量計費，打開無限的收入空間。

微軟賭的是，未來企業的數字化資產，將不再是靜態的文檔，而是成千上萬個活躍的 Agent。

Copilot Studio 是微軟 AI 版圖中變數最大的一塊。

如果它失敗了，微軟就只是一個賣昂貴 Office 插件的軟件公司，無法支撐其高昂的 AI 資本支出。

如果它成功了，微軟將不再只是提供生產力工具，而是成為全球最大的數字勞動力供應商。

但這些成千上萬的「數位員工」不會憑空工作，它們需要消耗海量的電力和算力。它們需要一個家，而這個家，就是微軟正在傾家蕩產建造的超級工廠。

第五章：填補千億美元黑洞 – Copilot Studio 與「特工」的崛起

  • 營收缺口： 僅靠 Office Copilot 的訂閱費無法填補 724 億美元的基建支出，微軟需要新的增長引擎。

  • 戰略轉向： 產品重心從「聊天機器人」轉向具備自主權的「Agent（智能體/特工）」，旨在替代業務流程。

  • 計費模式： 採用「消耗量」計費（按消息/算力），打破了「人頭費」的收入天花板。

  • 治理挑戰： 雖然企業試用量大，但對「失控 Agent」的治理恐懼限制了大規模生產環境的部署。

第六章：Azure——從「雲計算」到「AI 鑄幣廠」的博弈

如果說前幾章提到的 Copilot 是微軟派往前線的「戰鬥機」，那麼 Azure 就是那艘超級航母。沒有 Azure 源源不斷輸送的算力燃料，所有的 Copilot 都將淪為只會顯示「連接超時」的廢鐵。

在 2026 年的商業版圖中，Azure 正在經歷微軟歷史上最激進、最昂貴的戰略轉型：它不再僅僅是存儲數據和運行服務器的「雲」，它正在變成一座「AI 鑄幣廠（AI Factory）」。

1. 財報裡的秘密：增速的狂飆與 AWS 的焦慮

根據最新的市場數據，全球雲端基礎設施市場的格局如下：

  • AWS (霸主減速)： 雖然仍以 30% 的市佔率和約 309 億美元的季度營收穩居第一，但其 18-20% 的同比增長率顯示出「大數法則」的疲態。

  • Azure (瘋狂追趕)： 市佔率約為 20-25%，但其 39% 的驚人增長率是 AWS 的兩倍以上。按照這個速度差，兩者的「黃金交叉點」可能會比預期更早到來。

  • Google Cloud (穩健老三)： 以約13% 的市佔率和 32% 的增長率緊隨其後，雖然基數較小，但在數據分析和 AI 領域展現了強大的執行力。

這意味著，微軟正在以競爭對手 2倍以上的速度掠奪市場份額。Azure 已經不再是一個單純的技術平台，它是微軟增長的絕對引擎。

2. AI 是誘餌，核心基建才是主菜

如果我們像外科醫生一樣剖析 Azure 的營收結構，會發現一個被忽視的真相：

  • 79% 的「舊」生意： Azure 龐大營收的近八成，依然來自於傳統的「核心基礎設施」，即虛擬機、數據庫、網絡服務。這些看似無聊的業務，才是真正的現金奶牛。

  • AI 的渦輪增壓： Azure AI 服務（主要是 Azure OpenAI）目前的年化營收（Run Rate）達到了 130 億美元，同比增長 175%。雖然增速驚人，但它目前只佔總營收的約 17%。

這揭示了微軟真正的戰略：AI 是一個巨大的導流入口。

企業客戶可能是為了 AI 而來（例如為了用 GPT），但在部署 AI 的過程中，他們發現必須將數據遷移到雲端、必須升級數據庫、必須購買安全服務。

正如 Satya Nadella 所言，雀巢 (Nestlé) 遷移了 200 多個 SAP 實例和 1.2 PB 的數據，巴克萊銀行 (Barclays) 擴展了 10 萬個席位。這些巨大的「傳統遷移」訂單，才是支撐 39% 增長的底座。如果我們剔除 AI 帶來的增長，Azure 的核心業務依然保持著約 25-28% 的健康增速，這依然高於 AWS。

3. 資本支出的豪賭：半年燒掉 724 億美元

為了支撐這種增長，微軟正在進行一場史無前例的「燒錢」運動。

在 2026 財年的上半年，微軟的資本支出（CapEx）達到了驚人的 724 億美元（Q1 349 億 + Q2 375 億）。

這是什麼概念？這意味著微軟每半年的基建投入，就超過了絕大多數財富 100 強企業全年的總收入。

但魔鬼藏在細節裡。CFO Amy Hood 給出的這份賬單，揭示了微軟如何精算這場豪賭：

A. 「期限匹配」護盾：2/3 短壽命資產的玄機

目前的資本支出中，約 2/3 流向了「短壽命資產」（服務器、GPU、CPU），只有 1/3 流向了「長壽命資產」（數據中心建築、電力設施）。這與 FY24/25 時期「一半蓋樓、一半買設備」的結構截然不同。

這傳遞了兩個關鍵信號：

  • 週期信號——「填滿外殼」階段： 微軟在過去兩年已經完成了大部分的土地和建築（外殼）建設。現在，他們正處於將這些空置的數據中心填滿昂貴 GPU 的階段。這意味著基礎設施建設最困難的「物理擴張期」已過，現在是「產能填充期」。

  • 風險對沖——資產與合約的完美對齊： Amy Hood 反覆強調，短壽命資產的折舊週期（約 2-3 年）是被設計用來匹配剩餘履約義務（RPO）的合約時長的。

    • 投資人解讀： 這極大降低了「資產擱淺」的風險。即便 AI 需求在 3 年後突然崩盤，這批 GPU 的成本也已經通過鎖定的 3 年期合約完全覆蓋了。微軟實際上是在用客戶的錢買設備，只是在會計上先墊付了現金。

  • 會計的玄機（現金 vs. 賬面）： 值得注意的是，雖然財報顯示 Q2 資本支出為 375 億美元，但實際的「現金支出（Cash Paid）」為 299 億美元。中間的 76 億美元差額，主要來自融資租賃（Finance Leases）。這意味著微軟正在利用資產負債表的槓桿來撬動土地和建築，而將寶貴的現金全部砸向了 GPU。

B. 現金流的真相：為什麼 FCF 暴跌是「自信」的表現？

Q2 自由現金流（FCF）暴跌至 59 億美元，直接原因是微軟改變了付款方式：從「融資租賃 (Finance Leases)」轉向了「現金直購 (Cash PP&E)」。

  • 過去 (FY24-FY25)： 更多依賴租賃。這讓當期現金流好看，但會在資產負債表上堆積長期的租賃負債。

  • 現在 (FY26)： 轉向現金直購。這雖然讓當期的 FCF 非常難看（錢馬上流出），但避免了未來數年背負沈重的租賃利息和債務。

這是一種「預付費」的自信信號。 結合高達 6,250 億美元 的 RPO（積壓訂單），微軟管理層顯然認為長期利用率極高，因此寧願現在忍受現金流的劇痛，直接買斷資產，也不願「租用」基礎設施。這是在用短期的財務陣痛，換取未來更乾淨的資產負債表和更高的利潤率。

C. 護城河的本質：長壽命資產的期權價值

那剩下的 1/3 長壽命資產（土地、電力許可、網絡光纖）呢？這些資產的折舊期長達 15 年以上。它們是微軟真正的護城河。一旦這些「外殼」和「電力」就位，未來每一波新的 GPU 迭代（無論是 NVIDIA 的下一代還是微軟自研晶片），都可以快速「插拔」進這些現成的插槽中。

這意味著，微軟正在構建一個「可插拔的 AI 平台」：前期投入巨大的固定成本（外殼），後期只需投入邊際成本（晶片），就能獲得極高的增量資本回報率 (ROIC)。

然而，如此龐大的投入引發了一個問題：如果 OpenAI 失敗了，或者跑了，這些昂貴的數據中心會變成廢鐵嗎？

這就引出了微軟的戰略。

4. 可替換性 (Fungibility) 與長尾賭注

在面對「資產擱淺」的質疑時，Nadella在早前的一個訪問中，拋出了兩個關鍵概念，這也是解讀微軟Azure戰略的密碼：「可替換性」與「AI 工作負載的長尾」。

A. 可替換性（Fungibility）：拒絕做「定製西裝」

「可替換性」是一個財經術語，意指「可以互相取代，沒有本質差別」。就像我錢包裡的一百元和你錢包裡的一百元，價值完全相同。反之，《蒙娜麗莎》的真跡就是「不可替換」的。

Nadella 的戰略核心是：微軟的數據中心必須是那張「一百元」，而不是《蒙娜麗莎》。

「我們不想只成為一家公司的託管商（Hoster for one company）。」Nadella 在訪談中直言。如果微軟為了 OpenAI 建立了一座專屬的、不可替換的「定製工廠」，一旦 OpenAI 需求下滑或技術路徑改變（例如從 Transformer 轉向 MoE 架構），整座工廠就會作廢。

因此，Azure 的架構被設計成高度模組化的。今天的 GPU 集群可以服務 OpenAI 訓練 GPT-5，明天就可以拆分成一萬個小單元，服務一萬家企業進行 AI 推理，後天又能支持金融公司的數據分析。這種「物理層面的流動性」，是微軟敢於投入千億美金的底氣。

B. 擁抱長尾（The Long Tail）

如果說 OpenAI 是書店門口那幾本銷量驚人的「暢銷書」（頭部），那麼微軟真正的野心在於書店深處那成千上萬本「冷門書」（長尾）。

  • 頭部（The Head）： 像 OpenAI、Anthropic 這樣需要動用數萬片 GPU 進行超大模型訓練的客戶。雖然單筆訂單巨大，但客戶極少，且議價能力強。

  • 長尾（The Tail）： 這是 Nadella 瞄準的真正藍海。

    • 中小型企業用 AI 生成商品描述。

    • 律師用 AI 總結法律文件。

    • 全球開發者使用 GitHub Copilot。

    • 十幾億 Office 用戶在 Word 裡點擊「幫我重寫」。

這些需求的單次消耗極低（可能只是一度電），但匯聚起來是天文數字。

通過建立「可替換」的基礎設施，微軟確保了自己不是某個 AI 明星的「軍火商」，而是整個 AI 經濟體的「電力公司」。無論未來流行的是 GPT 還是 Llama，無論是訓練還是推理，只要你需要算力，你就得接入 Azure 的電網。

5. 物理學的戰爭：Fairwater與矽片獨立

為了實現這種「可替換性」並服務好「長尾」，微軟必須掌控硬體的定義權。這 724 億美元並不僅僅是用來買 NVIDIA 的顯卡，微軟正在重構數據中心的設計規範。

A. Fairwater 藍圖：單體超級電腦的誕生

在威斯康星州的 Mount Pleasant，微軟正在建造一個名為 Fairwater 的項目。這不是傳統意義上的數據中心，更像是一台單體 AI 超級電腦。

通過使用 NVLink 和 NVSwitch 技術，微軟將數萬個 GPU 連接成一個巨大的計算單元。在這裡，機櫃不再是獨立的孤島，它們共享高達 1.8 TB/s 的帶寬和 14TB 的內存池。這解決了 AI 訓練最大的瓶頸：通訊延遲。Fairwater 預計將消耗 2 吉瓦（GW）的電力，這相當於一個中型國家的用電量。

B. 擺脫 NVIDIA 的項圈：Maia 與 Cobalt 的雙重奏

為了奪回定價權，微軟在 2026 年初亮出了完整的自研晶片矩陣：

  • Maia 200（AI 加速器）： 微軟發現 90% 的負載是「推理」，因此 Maia 200 砍掉了通用的訓練功能，專注於推理效率。微軟官方宣稱 Maia 200 比現有硬體提供了 30% 的「每美元性能 (Performance per Dollar)」提升。這意味著，對於 Copilot 和 ChatGPT 這種大規模推理任務，微軟每產生一個 Token 的成本將降低約三分之一。這將直接轉化為毛利率的擴張，假設推理成本佔 Azure AI 營收成本的 50%，僅此一項就能為 Azure 帶來約 150-200 個基點 (bps) 的毛利率提升。

  • Cobalt 200（宿主 CPU）： 這是一個常被忽略但至關重要的佈局。每一台 AI 服務器都需要一個 CPU 來指揮 GPU。過去微軟必須向 Intel 或 AMD 繳納「過路費」。現在，微軟用自研的 Cobalt 200（基於 ARM 架構，擁有 132 個核心）取而代之。這不僅省錢，還因為它與 Maia 共享供電和散熱設計，進一步榨乾了每一瓦電力的價值。

採用率預測：
目前 Maia 200 已在愛荷華州 (Des Moines) 的數據中心上線，並正擴展至鳳凰城 (Phoenix)。雖然微軟不會完全拋棄 NVIDIA（訓練端仍需依賴），但根據分析師預計，到 2027 年，微軟內部 40%或以上的推理負載（包括 Microsoft 365 Copilot 和 OpenAI 的部分模型）將轉移至 Maia 架構。這將大幅降低微軟對外部供應鏈的依賴，並顯著改善其 AI 業務的單位經濟效益 (Unit Economics)。

6. 「Token 工廠」的經濟模型

傳統雲計算是「租賃模式」：企業租一台服務器，用不用是你的事。
Azure 的 AI 模式是「生產模式」：企業購買的是 Token（智能）。

微軟構建了一個內部經濟閉環：

  1. 上層應用（Copilot）：當一個員工用 M365 Copilot 寫郵件時，他在消耗 Token。

  2. 底層設施（Azure）：這個需求直接轉化為 Azure 的算力調用。

  3. 基礎建設（CapEx）：確定的內部需求讓微軟敢於提前建設龐大的數據中心，而不怕閒置。

這就是為什麼微軟敢於在一個季度內投入 350 億美元的原因。與 AWS 需要等待外部客戶下單不同，微軟自己的軟件產品（Office, GitHub, Dynamics）就是 Azure 最大的、最穩定的客戶。這種「自產自銷」的能力，讓微軟在基礎設施建設上擁有極高的確定性。

7. 戰略支柱：Azure AI Foundry——企業 AI 的「兵工廠」

在底層芯片和上層應用之間，微軟構建了一個至關重要的中間層：Azure AI Foundry。這不僅僅是一個開發平台，它是微軟區別於 AWS 和 Google Cloud 的核心護城河。

為了理解 Foundry 的戰略地位，我們必須將其與 Copilot Studio 區分開來。這兩者構成了微軟的「雙層代理架構」：

  • Copilot Studio（前台）：這是給業務人員用的「低代碼」工具。它像樂高積木，能快速搭建簡單的聊天機器人，直接集成在 Teams 或 Office 裡。它的優勢是快，但無法觸及模型底層。

  • Azure AI Foundry（後台）：這是給專業開發者和數據科學家用的「重型武器」。它是代碼優先（Code-First）的生產環境。

Foundry 的三大核心價值：

  1. 模型超市與微調中心：
    Foundry 提供了超過 11,000 個模型（包括 OpenAI、Mistral、Meta Llama 等）。更關鍵的是，它允許企業對這些模型進行微調（Fine-tuning）。對於金融、醫療等高風險行業，通用的 GPT可能不夠精準，企業必須用自己的私有數據在 Foundry 中訓練專屬模型，這直接帶動了 Azure 底層算力的消耗。

  2. 複雜的 Agent 編排：
    如果說 Copilot Studio 只能處理線性的「問答」，Foundry 則能構建複雜的多 Agent 協作系統。例如，一個「供應鏈管理系統」可能包含採購 Agent、庫存 Agent 和物流 Agent，它們之間需要互相對話、協調和決策。這種高級的編排能力（基於 Semantic Kernel 和 AutoGen 框架）是企業級 AI 的核心需求。

  3. 企業級治理與安全：
    這是大企業最看重的一點。Foundry 提供了身份級別的審計、虛擬網絡隔離（VNet Isolation）和合規控制。它解決了 CEO 們最大的恐懼——「我的數據會不會洩露給公有模型？」通過 Foundry，企業可以在完全私有的環境中運行 AI，確保數據不出域。

這正是「可替換性」戰略的體現：無論客戶想用什麼模型，Foundry 都能提供服務，並最終將算力消耗導向 Azure 的底層設施。

目前已有 70,000 家組織 使用 Foundry，其中 10,000 家（如喜力啤酒、Carvana）已經部署了自定義 Agent。這些 Agent 在上個季度處理了 100兆個 Token，這直接轉化為 Azure 的營收。

8. 陰影下的隱憂：利潤率的壓縮與產能瓶頸

儘管增長迅猛，但 Azure 並非高枕無憂。Q2 財報中隱藏著一個危險信號：營收成本（Cost of Revenue）激增了 44%，遠高於營收增長。

這導致微軟雲的毛利率出現了罕見的下滑。原因很簡單：AI 基礎設施太貴了，電力太貴了，芯片太貴了。微軟正在犧牲短期的利潤率，以換取長期的市場壟斷地位。

此外，產能瓶頸依然存在。CFO Amy Hood 坦承，Azure 的增長受到了「可用容量」的限制。換句話說，客戶拿著錢排隊，但微軟造數據中心的速度還不夠快。這也是為什麼微軟急於推出 Maia 200 的原因——如果買不到足夠的 NVIDIA 顯卡，那就自己造。

然而，就在微軟不惜代價擴充產能的同時，一個更深層的恐懼開始浮現：如果這座龐大工廠最大的 VIP 客戶，其實是用微軟借給他的錢來買單呢？

我們是時候，面對房間裡的那頭大象：OpenAI。

第六章：Azure——從「雲計算」到「AI 鑄幣廠」的博弈

  • 市場掠奪： Azure 增速（39%）是 AWS 的兩倍，AI 成為吸引企業遷移傳統業務上雲的「特洛伊木馬」。

  • 資產策略： 從「租賃」轉向「擁有」基礎設施，通過預付現金建設數據中心來鎖定長期利潤率。

  • 硬體自主： 推出自研晶片 Maia 200（加速器）和 Cobalt 200（CPU），目標是將 40% 推理負載轉移至自有晶片，降低對 NVIDIA 的依賴。

  • 中間層護城河： 「Azure AI Foundry」作為企業級 AI 工廠，鎖定模型微調與 Agent 編排，增加客戶黏性。

第七章：危險的槓桿——解剖 2,810 億美元的 RPO 黑箱

2026 年 1 月 28 日，微軟財報電話會議的氣氛在 CFO Amy Hood 說出一個數字的瞬間凝固了。

她首次承認，在微軟高達 6,250 億美元的商業剩餘履約義務（RPO，即已簽約但未確認的收入）中，OpenAI 佔據了 45%。

這是一個令人警惕的比例。這意味著微軟未來約 2,810 億美元 的雲端收入，完全依賴於單一客戶的生存與支付能力。這不再是分散風險的 B2B 雲端業務，這變成了一場將微軟國運與一家尚未盈利的新創公司深度綁定的豪賭。

華爾街的恐慌並非空穴來風。當我們剝開這 2,810 億美元，會發現裡面包裹著一個由「真金白銀」與「會計魔術」交織而成的複雜結構。

1. 推理的真相：真金白銀的現金流

首先，我們必須澄清一個誤區：這 2,810 億美元並不全是微軟左手倒右手的「代金券」。

根據洩露的內部數據與分析，這筆巨額訂單中，約 50-55%（即 1,400 億至 1,550 億美元）來自於「推理（Inference）」支出。

這是一個關鍵的區別。

  • 訓練（Training） 是週期性的、巨大的研發投入，這部分往往由微軟通過投資款和 Azure 信用額度（Credits）進行補貼。這部分確實帶有濃厚的「會計遊戲」色彩。

  • 推理（Inference） 則是 OpenAI 為了維持 ChatGPT 運轉、回應全球數億用戶 API 請求所必須支付的運營成本。

推理是微軟真正的現金奶牛。 數據顯示，僅在 2025 年的前 9 個月，OpenAI 就為推理業務支付了 87 億美元的現金。隨著 ChatGPT 企業版和 API 的普及，這部分支出正在呈指數級增長。對於這部分賬單，OpenAI 必須用真金白銀支付，微軟收到的是實打實的現金。

從這個角度看，Azure 的增長並非全是虛火。只要 ChatGPT 的用戶還在提問，OpenAI 就必須向微軟繳納這筆昂貴的「電費」。

2. 循環融資的陷阱

然而，這枚硬幣的另一面，是華爾街最為忌憚的「循環融資（Circular Financing）」結構。

雖然「推理」收入是現金，但這些現金從哪裡來？

OpenAI 目前的財務狀況是，燒錢速度每年在增加，2025預計在85億美元，估計到了2028年甚至高達 400-500 億美元。這意味著 OpenAI 每年有巨大的資金缺口。

這個缺口是怎麼填補的？

  1. 微軟注資： 微軟投資 OpenAI（現金+算力）。

  2. 購買服務： OpenAI 拿著這些錢（以及從其他投資人那裡融來的錢），轉身向微軟購買 Azure 服務。

  3. 確認收入： 微軟將這些銷售確認為 Azure 的營收，並在財報上展示 39% 的亮眼增長。

  4. 股價上漲： 微軟股價因雲端增長而上漲，OpenAI 估值因營收增長而上漲（微軟再確認投資收益）。

這是一個完美的閉環，直到音樂停止的那一刻。

這個閉環運轉的前提是：OpenAI 必須能持續不斷地從外部融到巨資。

這就是為什麼 OpenAI 正在尋求以 7,500 億至 8,300 億美元的估值進行新一輪 1,000 億美元的融資。如果融資失敗，或者估值崩塌，OpenAI 將無力支付那 2,810 億美元的訂單，微軟的 RPO 將瞬間變成壞帳。

3. 76 億美元的紙面富貴

這種風險在 Q2 財報中已經初現端倪。

微軟本季度錄得了 76 億美元的投資收益，這直接美化了 EPS（每股收益）。但這筆錢並非現金，而是基於 OpenAI 2025 年 10 月重組後估值上升帶來的「公允價值變動（Mark-to-Market）」。

這是一種極具誤導性的利潤。

如果未來 OpenAI 的估值因為燒錢過快或競爭加劇而回調，微軟將被迫在未來的財報中減記這筆資產，導致 EPS 劇烈波動。投資人必須清醒地意識到：微軟 GAAP 利潤的 60% 增長中，有相當一部分是這種「紙面富貴」。

4. 產能的豪賭：擱淺資產的恐懼

最讓機構投資者深感憂慮的，是時間錯配。

微軟現在就在燒錢。Q2 資本支出（CapEx）飆升至 375 億美元，全年預計超過 1,000 億美元。這些錢變成了數據中心、GPU 和伺服器。

而那 2,810 億美元的收入，是分攤在未來 6-7 年內實現的。

微軟是在用今天的現金，去賭未來的收入。

如果 OpenAI 在未來出現資金鏈問題，微軟今天建設的這些龐大數據中心，可能會變成昂貴的「擱淺資產（Stranded Assets）」。

這就是為什麼儘管微軟交出了一份「超預期」的財報，股價卻在盤後大跌。市場不是在質疑微軟今天的賺錢能力，市場是在恐懼微軟戰略重心過度依賴一家還在燒錢的新創公司。

5. 排隊的飢餓人群與可替換性的護盾

市場對 RPO 集中度的擔憂是合理的，但微軟管理層顯然比華爾街更清楚這一點。這就是為什麼 Nadella 如此執著於我們在第六章提到的「可替換性（Fungibility）」戰略。

這裡有一個被忽視的關鍵事實：Azure 目前正處於嚴重的「供不應求」狀態。

在財報電話會議中，CFO Amy Hood 透露了一個重要信息：由於產能限制，微軟目前正在拒絕大量外部客戶的需求。無數的財富 500 強企業、新創公司都在排隊等待 GPU 資源，但因為微軟優先將算力供給了 OpenAI 和內部的 Copilot，這些外部客戶只能拿著錢在門外乾著急。

這意味著什麼？這意味著微軟擁有一個巨大的、看不見的「候補名單（Waitlist）」。

如果最壞的情況發生，OpenAI 真的無法履行那 2,810 億美元的合約，或者 OpenAI 倒閉了，微軟的數據中心並不會變成廢鐵。

由於微軟堅持建立「可替換」的標準化基礎設施，他們只需要在後台按幾個按鈕，將原本分配給 OpenAI 的 GPU 集群釋放出來，轉租給門外那些飢渴的排隊客戶。

  • 情境 A (現狀)： 微軟優先服務 OpenAI，利潤率較低（合約價），但規模巨大。

  • 情境 B (災難)： OpenAI 退出，微軟將算力釋放給外部客戶。這些客戶通常支付的是更高的公開市場價格（List Price）。

諷刺的是，在某種極端情況下，OpenAI 的違約甚至可能在短期內提升 Azure 的利潤率，因為微軟終於可以把算力賣給出價更高的買家了。

因此，那 2,810 億美元的 RPO 雖然看起來像是一個懸在頭頂的達摩克利斯之劍，但它的下方並不是萬丈深淵，而是一張由全球強勁 AI 需求編織成的安全網。微軟賭的不是 OpenAI 一家公司的成敗，而是賭「只要算力是通用的，就永遠有人買單」。

第七章：危險的槓桿——解剖 2,810 億美元的 RPO 黑箱

  • 依賴深度： 微軟未來 2,810 億美元的雲端收入完全依賴 OpenAI，這是一場國運級的綁定。

  • 資金循環： 推理業務（Inference）帶來真實現金流，但訓練業務（Training）依賴 OpenAI 不斷融資，形成脆弱的「循環融資」結構。

  • 紙面富貴： 投資收益多來自 OpenAI 估值上升的公允價值變動，而非實際利潤。

  • 資產風險： 若 OpenAI 未來違約或遷移，微軟鉅資建設的數據中心恐面臨「資產擱淺」風險。

  • 安全網： 儘管 RPO 風險巨大，但 Azure 目前供不應求。基於「可替換性」戰略，即便 OpenAI 違約，微軟也能迅速將算力轉租給排隊的外部客戶，降低資產擱淺風險。

第八章：同床異夢——雙軌制帝國與分手預演

如果說第七章揭示了微軟與 OpenAI 在財務上的深度捆綁，那麼第八章我們將看到，在戰略層面，這對合作夥伴早已開始了同床異夢的「分手預演」。

2025 年 10 月的合約重組，不僅僅是一次股權結構的調整，它標誌著雙方關係的根本性轉變：從「獨家綁定」走向了「開放式博弈」。

1. 失去的獨家權：從「唯一」到「優先」

在 2025 年之前，微軟是 OpenAI 唯一的雲端供應商。這意味著 OpenAI 的每一行代碼、每一次推理，都必須跑在 Azure 上。

但在 2025 年 10 月的新協議中，這個條款被悄然修改了。

現在，微軟僅擁有「優先拒絕權（Right of First Refusal）」。

這意味著，當 OpenAI 需要算力時，必須先問微軟：「你能提供嗎？」如果微軟無法提供足夠的容量，或者價格談不攏，OpenAI 就可以名正言順地去找別人。

這是一個巨大的漏洞。鑑於 OpenAI 對算力的需求是無底洞（預計 2026 年需求將超過微軟總產能的一半），微軟幾乎註定無法滿足所有需求。這給了 OpenAI 合法的理由去「另結新歡」。

2. 圍獵 Azure：Oracle 與 AWS 的入場

OpenAI 並沒有浪費這個自由。事實上，它正在積極構建一個「去微軟化」的基礎設施版圖。

  • Oracle 的 3,000 億美元訂單： 這是一個比微軟 RPO 更驚人的數字。OpenAI 已經承諾向 Oracle 購買高達 3,000 億美元的算力。Oracle 憑藉其與 NVIDIA 的特殊關係以及更靈活的裸金屬架構，正在成為 OpenAI 訓練任務的新寵。

  • AWS 的 380 億美元試水： 2025 年 11 月，OpenAI 更是破天荒地與亞馬遜 AWS 簽署了 380 億美元的協議。雖然金額相對較小，但象徵意義極大——OpenAI 正在將雞蛋放入微軟最大競爭對手的籃子裡。

隨著 2027 年 Oracle 的大規模集群上線，OpenAI 可能會將大量的訓練負載遷移出去，只將與微軟產品（Copilot）強綁定的推理負載留在 Azure。

3. 星際之門 (Stargate)：OpenAI 的獨立宣言

最讓微軟感到寒意的，是 OpenAI 於 2025年 1 月公佈的 “Stargate“（星際之門） 項目。

這是一個預算高達 5,000 億美元 的基礎設施合資項目。

關鍵在於它的合作夥伴名單：SoftBank（軟銀）、Oracle、以及投資公司 MGX。

微軟在哪裡？微軟只是「參與者」之一，甚至不是主導者。

Stargate 的本質是 OpenAI 的獨立宣言。

Sam Altman 深知，只要算力依賴於微軟，OpenAI 就永遠只是微軟的附庸。通過引入軟銀的資金和 Oracle 的技術，OpenAI 試圖建立屬於自己的、不被微軟控制的算力王國。

4. 複製粘貼的「循環融資」：Anthropic 入局

Satya Nadella 顯然不會坐以待斃。他也在執行微軟的「去 OpenAI 化」戰略。

2025 年 11 月，微軟與 NVIDIA 聯手向 OpenAI 的頭號勁敵 Anthropic 注資。這不僅僅是一次財務投資，這是一次戰略上的「複製品」。

根據市場消息，微軟承諾向 Anthropic 投資高達 50 億美元。Anthropic 同時承諾購買 300 億美元 的 Azure 算力，並預訂了高達 1 吉瓦（GW） 的計算容量。

這與 OpenAI 的模式如出一轍：

  • 微軟給錢（投資）。

  • Anthropic 把錢還回來（買雲端服務）。

  • 微軟鎖定未來的雲端營收（RPO）。

這證明了「循環融資」並非微軟對 OpenAI 的特例，而是微軟試圖壟斷 AI 基礎設施的標準作業程序（SOP）。微軟正在用同樣的劇本，將市場的老二也鎖進 Azure 的鐵籠裡。在微軟的Copilot中，GPT再不是唯一的選項。

6. 終局：誰是最後的贏家？

我們看到的是一場「膽小鬼博弈（Game of Chicken）」。

  • OpenAI 賭的是：在燒光現金之前，利用所有人的錢，率先實現 AGI，從而徹底擺脫所有人的控制。

  • 微軟賭的是：利用合約鎖定 OpenAI 的商業化喉嚨（API 獨家權），同時在 OpenAI 能夠獨立之前，內化其技術優勢，轉移到自己的 Azure 和 Copilot 生態中，同時扶植其他玩家。

這 2,810 億美元的 RPO，既是雙方合作的紐帶，也是隨時可能引爆的炸彈。對於投資者來說，微軟不再是一個穩穩當當的收租公，它變成了一家正在走鋼絲的巨頭。而在鋼絲的另一端，是一個野心勃勃、試圖切斷繩索的合作夥伴。

第八章：同床異夢——雙軌制帝國與分手預演

  • 失去獨家： 2025 年合約修改後，微軟僅擁有「優先拒絕權」，不再是 OpenAI 的唯一雲端供應商。

  • OpenAI 的背叛： OpenAI 正通過與 Oracle（3000 億美元訂單）和 AWS 合作，以及「星際之門」計畫，試圖擺脫對 Azure 的依賴。

  • 微軟的對沖： 微軟投資 OpenAI 競爭對手 Anthropic，複製同樣的「投資換雲端訂單」模式進行避險。

  • 博弈本質： 雙方正在進行一場「膽小鬼博弈」，爭奪基礎設施的主導權與技術獨立性。

第九章：地板價與估值衝擊分析

在前幾章中，我們剖析了微軟與 OpenAI 的戰略博弈，以及這場 AI 豪賭背後的巨大資本支出。現在，我們必須將這些定性的分析轉化為定量的框架。

這不是為了算出一個精確到小數點的目標價，我們是為了看清市場目前的定價隱含了什麼樣的假設。

我們將進行一場「壓力測試」：假設最差的情況下，OpenAI 未能履行其承諾，微軟的股價合理價位（地板價）在哪裡？當然估值有很多假設成份，大家當作一個框架參考就好。

在這個「災難情境」下，我們將微軟拆解為三個部分（SOTP，分部加總法）來計算其殘值。

1. 生產力與業務流程（Office/Windows）：防禦核心

這是微軟的「現金牛業務 (Cash Cow)」。無論 AI 泡沫是否破裂，企業依然需要 Office 365 和 Windows 來運作。這部分業務現金流穩定，受資本支出波動影響較小。

  • 估值邏輯： 參考成熟軟體公司的估值水平。

  • 給予倍數： 保守給予 18 倍 EV/EBITDA（低於歷史平均，反映市場對成長放緩的擔憂）。

  • 貢獻價值： 約 $245/股。

2. 智慧雲端（Azure）：估值核心變數

這是估值變動最大的變數。為了精確計算 Azure 在災難情境下的價值，我們必須先釐清它的現狀與合理估值區間。

Azure 的現狀數據（Q2 FY2026 年化數據）

  • 年化營收： 約 684 億美元（佔智慧雲端部門約 52%）。

  • 年化 EBITDA： 約 253 億美元（基於 37% 的估計營業利潤率）。

  • 當前成長率： 39%（其中約 12-15% 來自 OpenAI 的貢獻）。

估值錨點：為什麼是這個倍數？

我們參考市場上的可比公司來設定 Azure 的估值地板：

  • AWS（地板）： 成長率 20%，交易倍數約 12-13.5x EV/EBITDA。這是雲端基礎設施的估值下限。

  • Google Cloud（參照）： 成長率 26%，交易倍數約 15-18x EV/EBITDA。

災難情境設定：OpenAI 違約

如果 OpenAI 營收歸零，且微軟無法填補閒置產能：

  1. 成長率重估： 扣除 OpenAI 貢獻，Azure 的「有機成長率」將回落至 24% 左右（接近 Google Cloud 水平）。

  2. 利潤率壓縮： 由於 GPU 產能閒置導致折舊壓力大增，利潤率將從 37% 壓縮至 33-35%。

  3. 估值倍數修正： 在這種情況下，Azure 不再享有高成長溢價，其估值將向 AWS 收斂。

    • 給予倍數： 14-16 倍 EV/EBITDA。

      • 這比目前的 20-22 倍大幅折讓，反映了成長停滯與資產閒置的風險。

      • 這相當於給予 Azure 約 3,500 億至 4,000 億美元的企業價值（Enterprise Value）。

    • 貢獻價值： 約 $80/股。

(註：目前市場給予 Azure 的定價約為 20-22 倍 EV/EBITDA，隱含價值約 $500B+。災難情境意味著 Azure 的估值將縮水約 30%。)

3. 個人運算（Xbox/Surface）：成熟業務

估值邏輯： 屬於週期性較強且成長緩慢的業務。

  • 估值：給予 10 倍 EV/EBITDA。

  • 貢獻價值：約 $13/股。

4. 淨現金與其他調整

  • 貢獻價值：約 $0/股（假設現金用於償還建設資料中心的債務）。

將這幾個數字加起來，地板價大約在$340左右。

這個數字意味著什麼？

  1. 安全邊際： 只有在 OpenAI 破產、AI 泡沫徹底破裂、且微軟完全無法將 GPU 轉租給其他人的極端情況下，股價才會跌到這裡。這是一個極端情境下的估值。

  2. Azure 是關鍵變數： 投資人可以根據自己對 Azure 未來的信心調整上述倍數。

    • 如果你認為 Azure 即使失去 OpenAI 也能維持 30% 成長，那麼 Azure 的估值倍數應維持在 18 倍以上，股價地板就會上移至 $360-$370。

    • 如果你認為 AWS 的 12 倍才是雲端運算的最終歸宿，那麼地板價可能會進一步

  3. 為什麼我選擇 SOTP 而非 DCF？
    細心的投資者可能會發現，我並未採用傳統的現金流折現模型（DCF, Discounted Cash Flow），這主要是考量到微軟當前的特殊財務週期：

    1. 資本支出的短期扭曲：
      DCF 模型的核心是自由現金流（FCF）。微軟目前正處於歷史性的資本支出週期（興建資料中心、採購 GPU），這導致當前的 FCF 被巨額 CapEx 大幅壓低。若直接使用當前的 FCF 進行線性外推，將嚴重低估公司的真實價值。

    2. 折舊與獲利的錯配：
      AI 基礎設施的投入是「前置」的，而收益是「後置」的。EV/EBITDA（企業價值倍數）關注的是息稅折舊攤銷前利潤，它能剔除折舊政策和資本結構的影響，更純粹地反映業務在「投資期」的經營績效。

    3. 業務屬性的差異化：
      微軟內部同時包含「穩定現金流業務」（Office）與「高資本密集成長業務」（Azure）。SOTP 能讓我們對不同風險特徵的業務給予不同的估值倍數，比單一的 DCF 模型更具顆粒度。

4. 操作指引：這取決於你的投資風格

算出 $340 這個地板價，並不代表你必須等到股價跌到這裡才進場。事實上，這個數字更多是用來衡量風險，而非預測走勢。你的決策應取決於你的投資哲學：

  • 深度價值投資者：等待極端情境

    • 如果你極度厭惡風險，堅持要有巨大的「安全邊際」，你可以選擇等待股價接近這個區間。

    • 代價： 你必須接受「踏空」的風險。如果 OpenAI 成功履行承諾，或者 Azure 的成長持續優於預期，災難情境可能永遠不會發生，你將完全錯過微軟在 AI 時代的潛在漲幅。

  • 成長型/趨勢投資者：評估盈虧比（Risk-Reward Ratio）

    • 你不一定要等到地板價，而是應該在當前價格基礎上，計算潛在的下行風險（Downside） 與 上行空間（Upside） 的比例，然後算出OpenAI成功的機率，Azure保持高速上升的機率，最後作出勝率高的下注。

    • 歸根結底，估值模型只能告訴你「如果發生 X，價格應該是 Y」。至於 X 發生的機率是多少，以及你願意為此承擔多少風險，這才是投資人必須自己做出的核心判斷。

終章：微軟的「第三次蛻變」

當我們合上這份充滿爭議的財報，回望微軟過去 50 年的歷史，你會發現這家公司正在經歷第三次轉型。

  • 第一次（1990-2010）： 它是操作系統的壟斷者（Windows）。它向每台電腦收稅，商業模式是「授權費」。

  • 第二次（2014-2023）： 它是雲端基礎設施的租賃者（Azure）。它向每家企業出租伺服器，商業模式是「租金」。

  • 第三次（2024-未來）： 它試圖成為數位勞動力的供應商（Copilot & Agents）。它不再只是提供工具，而是直接提供「工作結果」。

這就是為什麼華爾街感到恐慌，也是為什麼 Satya Nadella 如此堅決。

2026 年的微軟，不再是那個躺著賺錢的「防禦型標的」，它重新變成了一家「成長型創業公司」。

它主動打破了 Azure 躺贏的舒適圈，跳進了 AI 這個燒錢的資本密集型的戰場。這讓習慣了穩定現金流的投資人感到不適，甚至恐懼。

但請記住序章裡那個關於 Nokia 的故事。

當年微軟因為不敢破壞 Windows 的利潤而錯過了移動時代，那個代價是整整十年的沈淪。
今天，微軟選擇了另一條路：它寧願因為「過度投資」而被市場懲罰幾個季度，也不願因為「錯失未來」而被歷史懲罰十年。

如果你只看這兩年的利潤表，微軟是混亂的、昂貴的、充滿風險的。

但如果你相信在未來，人類的一半工作將由 AI Agent 協助完成，而這些 Agent 都將運行在 Azure 的矽片之上，通過 Copilot 的界面與人類交互。那麼，眼下的每一次大跌，或許都是轉型期的陣痛。

很多人擔心OpenAI的風險，OpenAI 確實是微軟身上最大的槓桿，也是最脆弱的環節。即便 OpenAI 失敗了，人類對「智能化」的需求不會消失。微軟建設的那些龐大數據中心（長壽命資產）、鎖定的電力許可、鋪設的光纖網絡，是未來十年數位世界的「水電煤」。晶片會折舊，但「能源與連接」的價值將永存。微軟正在用今天的現金，買下未來十年的入場券。

這場價值 4 兆美元的戰爭才剛剛開始。微軟已經把所有的籌碼推向了桌子中央，你相信他們嗎？
