而在這場神仙打架的戲碼中，雲端三巨頭中的昔日霸主 Amazon (AWS)，處境顯得格外尷尬。

  • 沒有王牌： 手上沒有一個像 ChatGPT 那樣讓大眾尖叫的殺手級產品。

  • 產能危機： 2025 年中的 GPU 缺貨事件，更是讓這家以「穩定」著稱的基礎設施巨人顏面掃地。

雖然 AWS 仍處於雲端龍頭寶座，但其增長率已明顯落後於 Azure 和 Google Cloud，市佔率的護城河開始出現裂痕。

乍看之下，AWS 像是一頭在超市裡迷路的大象，眼睜睜看著微軟和 Google 在「誰更聰明」的比賽中領跑，自己卻拿不出像樣的武器反擊。

但，事實真的如此嗎？

  1. 戰略轉向（Bedrock & Nova）： 為什麼 AWS 放棄了追求「最聰明的大腦」，轉而去做管理大腦的「管家」？

  2. 合縱連橫（Anthropic）： 揭秘亞馬遜與 Anthropic 之間價值 80 億美元的「開放式關係」，以及背後隱藏的晶片條款。

  3. 硬體豪賭（Trainium & Nvidia）： 面對 Nvidia 的壟斷，AWS 如何透過自研晶片與「打不過就加入」的策略，試圖重掌定價權？

  4. 內部革命： 亞馬遜如何打破二十年的部門高牆，用自己的電商與 Alexa 業務作為 AI 的試驗場？

  5. 終局武器（AWS Transform）： 亞馬遜真正的殺手鐧，不是陪你聊天，而是用 AI 幫全球企業償還三十年的「技術債」。

  6. 投資視角： 在 1,250 億美元的驚人資本支出下，投資者該如何判斷這是一場偉大的復興，還是一個巨大的錢坑？

第一章：巨人的焦慮——當賣鏟子的人發現金礦變了

在拉斯維加斯的霓虹燈下，全球最大的雲端帝國 Amazon Web Services (AWS) 舉辦了一場名為 re:Invent 的年度大會。

你可以把這場大會想像成科技界的「巴黎時裝週」，或者是雲端運算領域的「奧斯卡頒獎典禮」。

每年這時候，AWS 都會向全世界展示他們最新的「武器」，告訴大家未來一年的科技風向球往哪吹。

但在 2025 年的這場盛會上，空氣中卻瀰漫著一股前所未有的焦慮感。

為什麼？因為這家過去十多年躺著賺錢的科技巨頭，發現遊戲規則變了。

曾經的劇本：賣水電給淘金者

過去十五年，AWS 的生意模式非常簡單且暴利：它就是網路世界的「電力公司」。

  • 你想開一家像 Netflix 這樣的串流平台？不用自己蓋機房，跟 AWS 租。

  • 你想做一個像 Uber 叫車 App？不用買伺服器，跟 AWS 租。

AWS 只要把基礎設施（伺服器、硬碟、網路線）蓋好，全世界的創業公司就會排隊來繳「電費」。這讓 AWS 成為了 Amazon 最賺錢的金雞母，利潤甚至比 Amazon 賣東西的電商業務還高。

但 ChatGPT 的出現，把這個完美的劇本撕碎了。

新的危機：大腦比肌肉更值錢？

AI 時代來臨後，企業不再只滿足於租用「死板的伺服器」（肌肉），他們想要租用「聰明的 AI 大腦」（模型）。

這時候，AWS 發現自己落後了：

  • 微軟 (Microsoft) 搶先綁定了 OpenAI (ChatGPT)，擁有了當時世界上最聰明的大腦。

  • Google 搬出了自家的 Gemini，這是另一個天才大腦。

  • AWS 呢？ 手上只有一堆伺服器，卻沒有一個能与之抗衡的「頂級大腦」。

這就是 2025 年 re:Invent 大會的背景：一個擁有最強肌肉的巨人，急需證明自己也有大腦，或者至少證明：
你不需要那麼聰明的大腦也能賺大錢。

戰略大轉彎：2024 vs. 2025

要看懂 2025 年的 AWS，我們必須先對比一下2024 年的情況。

  • 2024 年的劇本：模型軍備競賽
    那時候，全世界都被 OpenAI 的 GPT-4 嚇壞了。AWS 的反應是防禦性的，他們急於證明：「嘿，我們也有大腦！」
    當時的 AWS 試圖告訴大家，自家的 Titan 和剛亮相的 Nova 模型也很聰明，也能跟 GPT掰手腕。那是一種「人有我也要有」的追趕心態。

  • 2025 年的劇本：代理人實戰
    面對微軟和 Google 的強勢，AWS 在這次大會上做出了一個驚人的戰略轉身。他們不再執著於「我要造出全世界最聰明的 AI」，而是換了一套說法：

「你們真的需要愛因斯坦來幫你們倒咖啡嗎？」

AWS 認為，雖然大家都想要 ChatGPT 這種頂級天才，但對於大多數公司來說，請天才太貴、太慢、而且大材小用。
大部分的企業工作（比如整理發票、回答客服問題），其實只需要一個「動作快、聽話、便宜」的實習生就夠了。

AWS 發現了一個殘酷但有利的事實：大部份企業其實不在乎 AI 聰不聰明，只在乎 AI 能不能幫公司賺錢。

大多數企業買了昂貴的 AI 模型回去，卻發現它們只會聊天，無法處理訂單、不敢讓它碰機密數據。

於是，AWS 在 2025 年的方向變成了：

「忘掉聊天機器人 (Chatbot)，擁抱代理人 (Agent)。」

什麼是「代理人 (Agent)」？

  • 聊天機器人： 像是一個「被動的顧問」。你問它：「怎麼訂機票？」它會告訴你步驟，但你得自己去訂。

  • 代理人： 像是一個「主動的員工」。你給它一個目標：「幫我訂一張去東京最便宜的機票。」它會自己去查價、比價、刷卡、然後把行程加到你的行事曆，中間完全不需要你插手。

AWS嘗試在形勢不利的時候，將大家的焦點改變，將戰場換到自己有利的位置。

但究竟AWS的優勢在哪裡？

第一章小結

  • 市場地位的動搖： AWS 過去靠出租伺服器（肌肉）躺著賺錢，但 AI 時代企業更想要聰明的模型（大腦），導致 AWS 在這場競賽中一度落後於微軟和 Google。

  • 戰略大轉彎： 2024 年 AWS 還在試圖證明自己有「最聰明的模型」，到了 2025 年則轉向務實，不再執著於造大腦，而是強調「代理人 (Agent)」。

  • 重新定義需求： AWS 認為大多數企業不需要昂貴的天才（GPT-4）來做雜事，而是需要便宜、聽話且能實際執行任務的實習生（Agent）。

在進入第二章之前，會員們可以投下你們的神聖一票，決定下星期「深入研究」的主題。

投票將在 3天後 結束。

第二章：反擊的號角——Bedrock 的中立與 Nova 的野心

在這個背景之下，我們來認識一下AWS Bedrock。

簡單來說，如果 OpenAI 是只賣自家產品的「蘋果專賣店」，那麼 Bedrock 就是「AI 模型的大賣場（Costco）」。

AWS 的邏輯是：

「你們想要最聰明的 Claude？我有。想要最開放的 Llama？我有。甚至想要死對頭 Google 的模型？我也有。你們不需要被綁死在任何一家店，來我的賣場，想用什麼就拿什麼。」

Bedrock 是一個平台（服務），它不生產單一的「菜」，而是把世界上最好的「食材」（AI 模型）都幫你準備好，讓你直接拿來用。

  • 大賣場的概念： 你不用只買 AWS 自家的東西。在 Bedrock 裡，你可以選購來自不同頂尖公司的 AI 模型，比如：

    • Anthropic (很有名的 Claude 系列)

    • Meta (Facebook 的 Llama 系列)

    • Mistral (法國很強的模型)

    • 還有 Amazon 自己 的模型 (Titan, Nova)

  • 中央廚房的概念： 它幫你把這些模型都「處理」好了。你不需要自己架設昂貴的伺服器去跑這些模型，只要透過Bedrock呼叫它們，就能直接使用。

為什麼AWS覺得企業會愛用 Bedrock？

  • 選擇多，不被綁死： 今天覺得 Claude 好用就用 Claude，明天覺得 Meta 的便宜就換 Meta，不需要重新寫程式，因為在 Bedrock 裡切換很方便。

  • 資料安全（這點最重要）： 企業最怕把公司機密丟給 AI，結果資料被拿去訓練，最後洩漏出去。Bedrock 保證你的資料不會被拿來訓練公開的模型，你的資料永遠是你的。

  • 容易加工： Bedrock 提供了很多工具（叫做 Agents 和 Guardrails），讓你可以限制 AI 不要亂講話，或者讓 AI 可以去讀你公司的內部文件（RAG 技術）。

簡單總結 Bedrock：

它是一個「AI 模型的中介平台」。它讓企業不用自己從頭造輪子，就能安全、快速地租用世界上最強大的各種 AI 大腦。

AWS 賭的是「模型商品化 (Commoditization)」。
他們認為，未來 AI 模型就像電池型號一樣，雖然現在大家只認名牌，但未來只要能用就好。既然如此，控制「賣場通路（Bedrock）」的人，會比生產「模型」的人賺得更久。

在這個新戰略中，Amazon Bedrock 的地位被無限拔高。

Bedrock 不再只是一個賣場，它升級成了「中央指揮部」。透過新發布的 AgentCore 功能，AWS 讓企業可以像管理員工一樣管理 AI：設定權限（不能亂花錢）、賦予記憶（記得客戶喜好）、考核績效。

隱藏的危機：Costco 的「利潤率陷阱」

然而，這個看似完美的「大賣場策略」背後，藏著一個財務隱憂。

如果你將Bedrock視為Costco 來看，雖然生意興隆，但大家都知道 Costco 的毛利極低。同樣的邏輯也發生在 Bedrock 上：

  1. 中間商的悲哀： 當企業透過 Bedrock 呼叫 Anthropic 的 Claude 3.5 模型時，AWS 實際上只是一個「二房東」。AWS 收到的錢，有一大半必須拆帳分給 Anthropic 作為「模型授權費」。這與 AWS 過去賣 EC2 或 S3 這種「自產自銷」、享有 30% 以上高利潤率的生意完全不同。

  2. 硬體的雙重剝削： 更慘的是，為了運行這些模型，AWS 還得向 Nvidia 購買昂貴的 GPU。這意味著，AWS 在軟體層面要被 Anthropic 分一杯羹，在硬體層面又要被 Nvidia 賺走大頭。

如果 AWS 所有的客戶都只用 Claude，那麼 AWS 的營收雖然會暴漲，但利潤率（Operating Margin）將會出現結構性的崩盤。

這就是為什麼 AWS 需要自家的Nova 模型。

Nova 的真實戰略地位：AWS 的「Kirkland Signature」

很多人以為 Amazon 推 Nova 只是為了證明「我也會做 AI」，其實不然。Nova 的真正使命是——保障利潤。

在 Costco 裡，最賺錢的不是可口可樂，而是 Costco 的自有品牌「Kirkland Signature」。Nova 就是 AWS 的 Kirkland。

  • 100% 的利潤保留： 當客戶從使用 Claude 轉為使用 Nova 時，AWS 不需要付給任何人一毛錢的授權費。每一分錢都留在 AWS 口袋裡。

  • 硬體的成本控制： AWS 強制 Nova 模型運行在自研的 Trainium 和 Inferentia 晶片上（我們稍後會詳細討論）。根據分析師估算，這比使用 Nvidia 晶片的成本低了 40-50%。

所以，2025 年 AWS 的算盤打得非常精：
用 Bedrock 這個「大賣場」把客戶吸引進來，讓他們先用 Claude（名牌貨）嘗鮮。等客戶依賴上 AI 功能後，再用極致的性價比（便宜 70%）誘惑客戶改用 Nova（自有品牌）。

AWS 賭的是，透過「自有模型 (Nova)」加上「自有晶片 (Inferentia)」，它能把 AI 的利潤率從「經銷商水準」拉回到「科技巨頭水準」。

這也解釋了 Nova 這次的產品定位為何如此務實。

Nova 的重新定位：不當愛因斯坦，當最強打工人

很多人以為Amazon沒有自家的大語語模型，其實並不是，他們也有自己的Nova和Titan，只不過用的人不多而已。

這一次，Amazon Nova 雖然不是新面孔，但它的「人設」徹底變了。

2024 年，大家還在期待 Nova 能不能在智商上打敗 GPT。但 2025 年，AWS 很誠實地攤牌了：我們不追求單一模型的世界第一，我們追求「極致的性價比」和「專才」。

AWS 這次推出的 Nova 2 系列（Lite, Pro, Omni, Sonic），就像是一支特種部隊：

  • Nova 2 Sonic： 專門負責聽和說，反應快到像真人，不像以前還要等轉圈圈。

  • Nova 2 Lite： 專門處理簡單雜事，便宜到你可以讓它 24 小時幫你讀郵件也不心疼。

  • Nova 2 Omni： 什麼都能看（圖、文、影、音），全能型選手。

AWS 的潛台詞是：「你不需要請一個諾貝爾獎得主（昂貴的 GPT-5）來幫你填 Excel 表格。用我的 Nova Lite 吧，它夠聰明，而且便宜 70%。」

這是一種非常「亞馬遜式」的打法——用規模經濟和低價策略，把 AI 變成像水電一樣便宜的基礎資源。

從「焦慮」到「務實」

這次的re:Invent大會，我們看到了一個不再逞強的 AWS。
他們不再試圖在「智商測驗」上贏過 Google 和 OpenAI。相反，他們回到了自己最擅長的領域：做生意。他們要把 AI 從「高不可攀的黑科技」，變成「便宜好用的水電」。

第二章小結

  • Bedrock 的定位： AWS 將 Bedrock 打造為「AI 模型的大賣場 (Costco)」，提供多種模型選擇（Claude, Llama 等），主打中立性與資料安全，不綁死單一供應商。

  • 利潤率的隱憂： 當「二房東」轉賣別人的模型利潤微薄，且需支付昂貴的硬體成本。

  • Nova 的角色： AWS 推出的自研模型 Nova 並非為了爭奪「智商第一」，而是作為高利潤率的自有品牌（Kirkland），搭配自研晶片提供極致性價比，以此挽救利潤。

第三章：代理人戰爭——Anthropic 與亞馬遜的「開放式關係」

在聊完 Bedrock 這個「大賣場」後，我們必須談談賣場裡最昂貴、最耀眼的商品——Anthropic 的 Claude 模型。

外界常有一個誤解：微軟擁有 OpenAI，Google 擁有Gemini，然後 Amazon 擁有 Anthropic。

但事實上，這段關係比婚姻更複雜，更像是一場精心計算的「開放式關係」。

這不僅解釋了 Amazon 的防禦策略，更揭示了他們作為「軍火商」的真實面目。

1. 以基建換股權：不買公司，買客戶

截至 2025 年底，Amazon 對 Anthropic 的投資總額已達 80 億美元。這筆錢並不是單純的風險投資，而是一種被華爾街稱為「以基建換股權 (Infrastructure for Equity)」的飛輪操作。

這其實也是一個循環交易(Circular Deal)：

  • 現金流出： Amazon 給 Anthropic 數十億美金。

  • 營收回流： Anthropic 轉手將這些錢付給 AWS，用來購買算力和儲存空間。

Amazon 其實不是在「買技術」，而是在「買客戶」。根據預估，Anthropic 在 2025 年將為 AWS 貢獻超過 10 億美元營收，到了 2027 年這個數字將再翻幾倍。

Anthropic 承諾將其主力模型（Claude 系列）的訓練全部轉移到 Trainium 上。

這對 AWS 至關重要，因為它向世界證明了：「Trainium 不只是便宜貨，它真的能跑世界級的頂級模型（Frontier Models）。」 這是 Trainium 獲得市場信任的唯一途徑。

令Anthropic 擊敗 OpenAI，並不是AWS的最終目標。它只在乎這場仗繼續打下去，而且雙方都必須用 AWS 的雲端服務來打仗。這就是典型的「軍火商」思維。

2. 為什麼允許「劈腿」？

最讓外界困惑的是，Anthropic 同時也拿了 Google 30 億美元的投資，並且大量使用 Google Cloud 的 TPU 進行訓練。

為什麼 Amazon 容忍這種「劈腿」行為？這其實是 Amazon 的高明之處：

  • 監管的避雷針： 微軟對 OpenAI 的緊密控制已經引來反壟斷機構的死盯。Amazon 通過保持這種「非獨家」關係，可以對監管機構兩手一攤：「看，他們也用 Google，我們並沒有控制他們。」

  • 企業的瑞士銀行： Anthropic 將自己定位為 AI 界的「中立國」。對於那些討厭微軟（競爭對手）或不信任 Google（隱私擔憂）的銀行與醫療機構來說，Anthropic 是唯一「安全」的選擇。這種中立性，反而讓它成為 AWS 吸引高端企業客戶的磁石。

3. 隱藏的條款：Trainium 的試飛員

這筆 80 億美元交易中，最關鍵的條款不是股權，而是「晶片強制令」。

協議規定，Anthropic 必須大部份使用 AWS 自研的晶片來進行主要的訓練和推論任務。

這為之後我們會提到的硬體戰爭埋下了伏筆。Amazon 知道，要打破 Nvidia 的壟斷，光靠 PPT 是沒用的。他們需要一個頂級的「試飛員」。

如果連世界上最聰明的模型之一 Claude 是用 Trainium 訓練出來的，那麼其他企業就沒有理由質疑這款晶片的性能。

Anthropic 在這裡的角色，不僅是軟體合作夥伴，更是 Amazon 自研硬體成敗的關鍵驗證者。

4. 風險：租來的皇冠

當然，這種策略並非沒有風險。Amazon 本質上是在「租用」一個前沿模型，而不是擁有它。

如果未來 Anthropic 決定倒向 Google，或者開發者大規模遷移到其他模型，Amazon 將面臨巨大的被動。

雖然 Amazon 也在開發自己的 Nova 模型，但目前來看，Claude 仍是 AWS 皇冠上那顆借來的寶石。

5. 危險的單押 (Concentration Risk)

因此，這也是一場危險的賭博。

目前 Trainium 的產能有極大比例是為了滿足 Anthropic 的需求（Project Rainier）。這導致其他外部客戶很難拿到足夠的 Trainium 資源，限制了生態系的擴張。
雖然有 Databricks、Ricoh 等公司採用，但市場滲透率依然有限。
根據 Business Insider 報導，Cohere 和 Stability AI 等公司反映，Trainium 的延遲 (Latency) 高於預期，且開發期間取得配額困難。
許多公司發現，將原本在 NVIDIA 上訓練的模型轉移到 Trainium 上時，會遇到精度下降或參數不匹配的問題。

我們終於理解了AWS的超市(Bedrock)，租來的皇冠(Anthropic)，以及便宜的模型（Nova）。

但是，企業買了這些 AI 回去，如果不會用怎麼辦？這就引出了 AWS 的戰略目標——「代理人 (Agents)」。

第三章小結：

  • 以基建換股權： AWS 投資 Anthropic 80 億美元，實質上是「買客戶」，讓 Anthropic 承諾使用 AWS 雲端服務與 Trainium 晶片，形成資金迴圈。

  • 容忍「劈腿」的策略： 允許 Anthropic 同時使用 Google Cloud，是為了維持其「中立國」形象以吸引對微軟/Google 有疑慮的敏感客戶，並規避反壟斷審查。

  • 晶片試飛員： Anthropic 的關鍵任務是證明 AWS 自研晶片 Trainium 能訓練頂級模型，為 AWS 的硬體實力背書。

第四章：AWS 的理想——做 AI 時代的「餐廳經理」

如果說頭兩章的結論是「AWS 不想造大腦，只想管大腦」，那麼現在我們要問的是：
憑什麼AWS 能管好大腦？

在 AI 的淘金熱中，媒體的聚光燈總是打在「模型層 (Model Layer)」上——GPT-5 寫詩多美、Gemini 讀圖多快。

但對於企業 CIO 來說，這些都不重要。他們不敢用 ChatGPT，不是因為它不夠聰明，而是因為它不可控。

這就是 AWS 的機會。

在模型層的戰場失去先機後，AWS 嘗試將大家的目光從「大腦」轉向一個更務實的戰場：營運層 (Operational Layer)。

什麼是營運層？從「買食材」到「進廚房」

我們在第二章將 Bedrock 比喻為「大賣場」，那裡解決的是「買什麼」的問題。

但買回來的頂級牛排（模型）並不能直接丟給客戶吃。為了講清楚這個關鍵差異，我們必須走進後台的「廚房」：

  • 模型層 (Model) = 食材： 這是 GPT-4、Claude、Llama的底層。它們是生的牛肉、新鮮的蔬菜。它們決定了菜餚的上限，但光有食材是沒法吃的。

  • 應用層 (Application) = 餐桌： 這是 ChatGPT 的網頁介面，或者是微軟 Copilot 的按鈕。這是客人實際坐下來吃飯的地方。

  • 營運層 (Operational) = 廚房管理系統： 這才是 AWS Bedrock 的真面目。

營運層包含了什麼？它包含了食譜（Prompt Engineering）、衛生局的檢查標準（安全護欄 Guardrails）、副主廚的備料流程（RAG 檢索）、以及庫存管理（記憶體）。

AWS 的策略是：微軟和 Google 都在忙著培育出最好的牛肉（模型），但我擁有世界上最先進的廚房（Bedrock）。

不管你買了誰家的牛肉，如果你想把它做成一道能端給客人吃、且不會讓客人食物中毒的安全料理，你就得來借我的廚房。

AWS 發現，企業在 AI 上的預算，其實只有 10-15% 是花在「請廚師」（模型費用），卻有 50-60% 是花在「請店長」（營運管理）。

Bedrock 就是這個擁有鐵腕手段的店長，它透過以下三大功能來管理 AI：

1. AgentCore 的「自然語言護欄」

企業最怕 AI 什麼？怕它胡說八道（幻覺），更怕它洩漏機密。

想像一下，你問公司的 AI：「幫我總結一下 Q3 的財報。」
結果 AI 不僅總結了，還順便把這些未公開的數據上傳到了公有雲，或者在回答中夾帶了競爭對手的名字。這對企業來說是災難。

AWS 在 2025 年推出的 AgentCore，就是為了解決這個問題。它不只是一個 API，它是「副主廚」兼「保全」。

這是 Bedrock 最強的差異化優勢。過去要限制 AI 不亂說話，工程師要寫一堆複雜的程式碼。現在，你只要用白話文寫下「店規」：

  • 「禁止提供任何理財建議。」

  • 「如果被問到競爭對手，請禮貌地拒絕回答。」

  • 「這筆交易如果超過 100 萬美元，必須先取得人類主管同意。」

Bedrock 會在 AI 回答之前，像保全一樣進行攔截和審查。這對於銀行、醫療這種「說錯話會被罰款」的行業來說，比 AI 聰不聰明更重要。

2. 情節記憶

過去的 AI 像是一個患有失憶症的員工，每次對話都是從零開始。Bedrock 賦予了 AI「情節記憶」。它能記住：「這個客戶昨天說他討厭科技股，今天別再推了。」這讓 AI 從一個冷冰冰的問答機器，變成了懂人情世故的代理人。

3. 企業級 RAG (檢索增強生成)

這是將 AI 與企業內部知識庫連結的技術。Bedrock 讓這件事變得像「隨插即用」一樣簡單。它自動幫你把成千上萬份 PDF 文件切分、向量化，讓 AI 可以精準地回答：「根據公司第 34 頁的規章，出差費上限是 200 美元。」

資料重力——物理學的絕對優勢

在 AI 時代，模型需要「吃」數據才能工作。

想像一下，你是一家像 Netflix 或 BMW 這樣的大公司，你過去 10 年累積的 PB 級數據（用戶資料、生產紀錄、交易流水），原本就存在 AWS 的 S3 (Simple Storage Service) 倉庫裡。

現在你有兩個選擇：

  1. 搬家： 把這些幾千噸重的數據，透過網路搬到 Google 或微軟的雲端去訓練 AI。這不僅要花幾百萬美元的傳輸費，還要花好幾個月的時間，而且中間還有資安風險。

  2. 就地取材： 直接在 AWS 裡，把 AI 模型「搬」到數據旁邊。

AWS 的 Bedrock 能夠直接與 S3 無縫對接（透過 S3 Vectors 等新功能）。「把輕盈的模型搬到沈重的數據旁邊」，永遠比「把沈重的數據搬到模型旁邊」更便宜、更快、更安全。

只要全球 30% 的企業數據還躺在 AWS 的倉庫裡，AWS 就擁有天然的主場優勢。

瑞士策略——中立國的誘惑

在雲端三巨頭中，AWS 扮演了「瑞士」的角色——永久中立國。

  • 微軟 (Azure)： 它是 OpenAI 的專賣店。如果你用 Azure，你基本上就被綁定在 GPT 系列模型上了。萬一哪天 OpenAI 漲價，或者 GPT-5 表現不如預期，你很難跳船。

  • Google (GCP)： 它雖然開放，但它最想賣的還是自家的 Gemini。企業總會擔心：我用了 Google 的雲，又用 Google 的模型，我的數據會不會被 Google 拿去訓練它的 AI？

AWS 則不同。Bedrock 是一個真正的「模型聯合國」。

在 AWS 的控制台上，你可以早上用 Anthropic 的 Claude 3.5 寫程式（因為它邏輯好），下午切換到 Meta 的 Llama 3.2 做摘要（因為它開源便宜），晚上甚至試試 Mistral 的模型。

這種「可插拔 (Pluggable)」的特性，讓企業擁有談判籌碼。企業不想被單一模型廠商綁架，而 AWS 是唯一能提供這種「早上下午換不同大腦，但身體（營運層）不用重做」的平台。

為什麼要給 AWS 賺一手？

你可能會問：「既然我要用 Claude，為什麼不直接去 Anthropic 官網訂閱 API？為什麼要透過 Bedrock，甚至忍受可能的溢價？」

這就像是問：「為什麼大公司買電腦要找經銷商採購，而不是叫員工自己去 Apple Store 買？」

對於一般消費者，直接找原廠當然最便宜。但對於企業 (Corporate/B2B)，「便宜」不是第一考量，「睡得著覺」才是。

Bedrock 賣的不是模型，而是「企業級的服務」：

  • 解決採購惡夢：
    想像一下，你的公司有三個 App，分別用了 OpenAI、Anthropic 和 Meta。財務部門每個月要處理三家廠商、三種合約、三種幣別。
    用 Bedrock，所有費用都算在 AWS 的一張帳單裡。企業通常已與 AWS 簽訂長期折扣合約 (EDP)，這筆費用甚至能用來抵稅或湊折扣額度。

  • 資料不出內網：
    直接呼叫原廠 API，資料通常會經過公共網際網路 (Public Internet)。
    Bedrock 支援 AWS PrivateLink，這意味著資料從你的伺服器傳到 AI 模型，全程都在 AWS 的私有內部網路裡跑，完全不接觸外網。這對資安長 (CISO) 來說，是無價的「安全感」。

  • 權限管理的細緻度 (IAM Integration)：
    直接找原廠，你可能要管理一堆 API Key，一旦洩漏就完蛋。
    Bedrock 直接整合 AWS 的權限系統 (IAM)。你可以設定：「只有『行銷部』的工程師，在『上班時間』，可以呼叫『Claude 模型』」。這種細緻的控管，是原廠 API 很難做到的。

營運層的真正含義：B2B 的安全帶

這也解釋了為什麼大眾覺得 Amazon 在 AI 領域「沒聲音」。

因為一般消費者只在乎聊天機器人好不好玩（ChatGPT），不在乎什麼「護欄」、「向量資料庫」或「RAG」。

但企業非常在乎。花旗銀行不敢用 ChatGPT 怕洩密，豐田汽車怕 AI 胡說八道損害品牌。Bedrock 的 AgentCore 就是賣給這些企業的「安全帶」與「方向盤」。

完美的設計圖，與現實的裂痕

總結來說，AWS 在 2025 年構建了一個完美的「營運層」藍圖：

  1. AgentCore 解決了安全與管理問題。

  2. 資料重力 解決了成本與效率問題。

  3. 中立策略 解決了廠商鎖定問題。

AWS 的如意算盤是——你們去爭奪誰是愛因斯坦（最強模型），我來做管理愛因斯坦的管家。

只要企業想安全、合規地使用 AI，就繞不開我的營運層。

然而，現實不會總是這麼完美。

第四章小結

  • 營運層 (Operational Layer) 的概念： AWS 強調光有食材（模型）不夠，還需要廚房管理（營運）。Bedrock 扮演「廚房經理」，負責食譜（Prompt）、衛生（安全護欄）與庫存（記憶體）。

  • AgentCore 的功能： 提供自然語言護欄（防止亂說話）、情節記憶（記住客戶喜好）與企業級 RAG（連結內部數據），解決企業最在意的安全與合規問題。

  • 資料重力優勢： 利用企業數據原本就存在 AWS S3 的優勢，主張「把模型搬到數據旁」比「搬數據去別家」更安全高效。

第五章：市場的現實——頂級客戶的認可與大眾市場的失落

AWS 的戰略聽起來完美無缺：中立、安全、可控。

但當我們看看 2025 年的真實戰場，會發現一幅充滿矛盾的畫面。

1. 頂級客戶的背書：Bedrock 的「護城河」

首先，AWS 的策略確實奏效了——但僅限於那些「最難搞」的客戶。Bedrock 贏得了一系列含金量極高的標竿客戶，證明了它在高端市場的價值：

  • 法拉利 (Ferrari)： 這家頂級跑車製造商需要一個能處理複雜 3D 配置、又能保護商業機密的平台。他們看中了 Bedrock 的多模型能力，用它來打造下一代汽車配置器。

  • Intuit (TurboTax 母公司)： 處理稅務數據容不得半點差錯。Intuit 選擇 Bedrock 來支撐其 AI 助手，在報稅季高峰期成功服務了數百萬用戶。這證明了 Bedrock 在「高併發」和「合規性」上的實力。

  • Lyft： 他們利用 Bedrock 的代理人功能，將客戶服務的解決時間縮短了 87%。這是一個真實的「降本增效」案例，證明了 AgentCore 不是噱頭。

  • Robinhood： 這家金融科技公司利用 Bedrock 將 AI 成本降低了 80%。對於交易量巨大的企業來說，Bedrock 的「預配置吞吐量 (Provisioned Throughput)」模式比 OpenAI 的計費更具成本優勢。

這些案例傳遞了一個訊號：如果你是受監管的、對資安有潔癖的、或者數據原本就在 AWS 上的大企業，Bedrock 是你的首選。

2. 殘酷的數據：大眾市場的失落

然而，儘管有這些亮眼的勝利，整體的戰局對 AWS 來說卻相當不利。

根據IOT-Analytics今年的分析師報告，在新的AI 專案中：

  • Microsoft Azure OpenAI 佔據了 62% 的份額。

  • Google Vertex AI 佔據了 18%。

  • AWS Bedrock 僅佔 16%。

這是一個驚人的落差。作為全球雲端市佔率第一 (32%) 的霸主，AWS 在 AI 領域的份額竟然只有微軟的四分之一。為什麼？

A. 「最強大腦」的誘惑 vs. 「選擇權」的迷思

AWS 強調「選擇權」（你可以選 Claude, Llama, Mistral），但市場用腳投票證明：大多數企業其實不想選，他們只想用最強的。

Azure 獨家擁有 OpenAI 的 GPT模型（擅長複雜推理）。對於大多數開發者來說，OpenAI 就是標準。AWS 雖然有強大的 Claude，但在品牌心智上，依然難以撼動「OpenAI = AI」的刻板印象。

B. 生態系的護城河

微軟的殺手鐧不是雲端，而是 Office。

當企業使用 Azure OpenAI 時，它可以無縫整合到 Word, Excel, Teams 和 Copilot 中。這種「開箱即用」的便利性，對於非科技公司來說是無法抗拒的。

相比之下，Bedrock 雖然強大，但更像是一堆精密的零件，需要專業的工程師才能組裝起來。

C. 技術門檻與人才缺口

Bedrock 的 AgentCore 功能雖然強大，但也非常複雜。許多企業的 IT 部門連基本的 Prompt Engineering 都還沒搞懂，根本不知道如何設定複雜的護欄和記憶體。結果就是，大家更傾向於使用微軟那種「傻瓜式」的解決方案。

D. 成本與效能的隱形門檻

透過 Bedrock 呼叫模型，通常會有溢價，且延遲 (Latency) 可能較高。

  • 為什麼企業還要用？

    1. 資料重力 (Data Gravity)： 如果你的資料已經在 AWS 上，把它搬去 Google 或 Azure 的傳輸費和工程成本，遠高於要付的溢價。

    2. 批發價優惠： 對於 Robinhood 這種超大用量的客戶，Bedrock 提供的「包場模式」折扣，反而比直接找原廠更便宜。

  • 但對中小企業呢？
    對於還在「試玩」階段的中小企業，他們沒有龐大的數據包袱，也不需要批發價。對他們來說，Bedrock 就是「又貴又複雜」。

贏了戰役，輸了戰場？

AWS 目前處於一個尷尬的境地：

  • 在「深度」上贏了： 它擁有出色的治理工具和靈活的架構，贏得了法拉利和 Intuit 這種金字塔頂端的客戶。

  • 在「廣度」上輸了： 它失去了中小型企業和那些追求「簡單快用」的主流市場。

AWS 的理想是成為 AI 時代的「水電行」（基礎設施），但現實是，更多的新創更喜歡微軟提供的「精裝修公寓」。

更糟糕的是，當客戶終於被說服來使用 Bedrock 時，他們遇到了一個更實際的問題——缺貨。

第五章小結

  • 高端市場的勝利： Bedrock 成功贏得法拉利、Intuit 等對資安與合規要求極高的頂級客戶。

  • 大眾市場的挫敗： 在整體 AI 專案市佔率上，AWS (16%) 遠落後於微軟 (62%)。中小企業更偏好微軟「開箱即用」的 Office 整合，認為 Bedrock 門檻過高且複雜。

  • 品牌心智劣勢： 市場仍普遍認為「OpenAI = AI」，AWS 強調的「選擇權」對許多只想用最強模型的客戶來說吸引力不足。

第六章：隱藏的危機——產能、配額與「消失的瓦斯」

擁有世界上最先進的廚房管理系統（Bedrock），AWS 本應在 AI 時代大殺四方。然而，在這一年以來，這家雲端霸主卻遭遇了一場前所未有的信任危機。

客戶們驚恐地發現：廚房很漂亮，菜單很豐富，但是爐子點不著火——因為沒有瓦斯。

這裡的「瓦斯」，就是 GPU 算力。

事件重現：當 VIP 客戶開始逃亡

危機並非一夜之間爆發，而是透過一連串「無法交付」的訂單顯現出來的。

根據Business Insider的報導，最著名的案例發生在遊戲巨頭 Epic Games（Fortnite 開發商）身上。作為 AWS 的長期頂級客戶，Epic Games 準備大規模部署生成式 AI 來輔助遊戲開發。

他們理所當然地選擇了 Bedrock。然而，當他們提出算力配額（Quota）申請時，得到的不是「批准」，而是「請等待」。

對於一家分秒必爭的科技巨頭來說，「等待」是不可接受的。結果是災難性的： Epic Games 直接帶著數千萬美元的 AI 預算，轉身投向了 Google Cloud 的懷抱。

同樣的故事也發生在 Thomson Reuters（湯森路透）身上。這家數據巨頭在測試中發現，同樣運行 Claude 3 模型，Google Vertex AI 的響應速度竟然比 AWS Bedrock 快了 30%，且完全沒有配額限制。

這些事件揭露了一個殘酷的事實：AWS 的供應鏈斷裂了。

根本原因：用舊思維打新戰爭

為什麼全球最大的雲端公司會缺貨？這不是因為 AWS 沒錢，而是因為它的決策慣性。

AWS 過去 15 年的成功，建立在精準的「數據驅動 (Data-Driven)」採購上。

  • 舊思維： 「看到訂單才買伺服器。」為了避免庫存浪費，AWS 習慣等到客戶需求訊號明確後，再下單採購硬體。這在傳統雲端時代是最高效的策略。

  • 新戰爭： AI 時代的邏輯完全不同。Nvidia 的 H100/H200 GPU 交貨週期長達 6 到 12 個月。

當 2023 年生成式 AI 需求呈現「指數級」爆發時，微軟（Azure）因為豪賭 OpenAI，早在兩年前就囤積了大量 GPU。

而 AWS 仍堅持「不見兔子不撒鷹」，等到 2024 年訂單如雪片般飛來時，才發現市面上的 GPU 早就被搶光了。

AWS 試圖用軟體（Bedrock 的調度能力）來掩蓋硬體的不足，實施了嚴格的配額限制。這就像餐廳為了掩蓋食材不足，規定每位客人只能點半份牛排。

結果，這反而激怒了習慣「無限吃到飽」的雲端客戶。

代價：1,250 億美元的緊急修補

為了挽回這場災難，AWS 付出了昂貴的代價。

在 2025 年，Amazon 宣布了一項震驚華爾街的資本支出計畫。這筆天文數字般的預算不是為了創新，而是為了「補課」。

  • 緊急採購： AWS 被迫在現貨市場以高價搶購 Nvidia GPU，這大幅壓縮了利潤空間。

  • 加速建設： 為了把這些晶片裝上去，AWS 在全球瘋狂建設數據中心，甚至不惜重金收購核電廠來確保電力供應。

這解釋了為什麼 Amazon 近期的財報中，雖然營收數字漂亮，但自由現金流 (Free Cash Flow) 卻顯得異常緊繃。這就是 AWS 為「舊思維」繳納的罰款。

危機後的覺醒

這場產能危機是 AWS 歷史上最危險的時刻。它打破了「AWS = 穩定」的神話，讓競爭對手有機可乘。

為了不讓GPU成為瓶頸，AWS也嘗試靠自己，推出自己的自研芯片。

第六章小結：

  • 供應鏈斷裂： 由於堅持「見訂單才採購」的舊思維，AWS 未能及時囤積 GPU，導致 Epic Games 等大客戶因算力缺貨而跳槽 Google。

  • 信任危機： 嚴格的配額限制打破了 AWS「無限供應、穩定」的神話。

  • 鉅額補課費： Amazon 被迫投入 1,250 億美元資本支出，高價搶購現貨 GPU 並瘋狂建設數據中心，導致自由現金流吃緊。

第七章：硬體的豪賭——Trainium 的演化與困境

如果說軟體 (Bedrock) 是 AWS 的靈魂，那麼硬體就是它的骨架。在 2025 年，這副骨架正面臨前所未有的拉扯。

要看懂 AWS 在 AI 晶片上的焦慮，我們得先回頭看一段歷史。AWS 並不是晶片新手，事實上，他們曾經打贏過一場漂亮的硬體戰爭。

前傳：Graviton 的勝利

早在 2015 年，AWS 就收購了一家以色列晶片公司 Annapurna Labs。當時沒人看懂這步棋，直到 2018 年 AWS 推出了自研的 CPU——Graviton。

  • 輝煌戰績： Graviton (基於 ARM 架構) 取得了巨大的成功。它比 Intel 和 AMD 的處理器便宜 20-40%，而且效能相當。對於 Spotify、Netflix 這種大規模運算的客戶來說，換用 Graviton 一年能省下幾百萬美金。

  • ASIC 的甜頭： 這讓 AWS 嚐到了 ASIC (Application-Specific Integrated Circuit，特殊應用積體電路) 的甜頭。簡單說，就是「與其買通用的晶片，不如自己造專用的」。這不僅能擺脫對 Intel 的依賴，還能大幅拉高利潤率。

帶著 Graviton 的勝利光環，AWS 信心滿滿地殺入 AI 領域，推出了兩款 AI 專用晶片：

  1. Inferentia (2019)： 專攻「推理 (Inference)」。也就是當模型訓練好後，用來回答用戶問題的階段。這款晶片評價不錯，因為便宜、省電，適合跑 Alexa 這種語音辨識。

  2. Trainium (2020)： 專攻「訓練 (Training)」。這是最難啃的骨頭，也是 Nvidia 的絕對領域。

然而，當 AWS 試圖複製 Graviton 的成功模式時，他們撞上了一堵牆——這堵牆叫 CUDA。

要開發者改用 AWS 的 Neuron SDK，就像要一個習慣用 Windows 的人改用 Linux 終端機。

雖然 AWS 宣稱支援 PyTorch，但在除錯 (Debugging)、算子優化 (Operator Optimization) 上，Neuron SDK 與 CUDA 的成熟度差距至少還有 5 年。

這導致 Trainium 難以吸引除了超大型客戶（有能力自己改底層代碼）以外的中小企業。

進化之路：從「省錢備胎」到「戰略基石」

回顧 Trainium 的發展史，我們可以看到 AWS 是如何在跌跌撞撞中調整航向：

  1. 2021-2022 (Trn1)：試水溫與頻寬焦慮
    口號是「Nvidia 以外的便宜選擇」。但客戶發現，便宜是有代價的。Trn1 在訓練大模型時，因頻寬不足導致晶片經常「空轉」等待數據。AWS 被迫緊急推出 Trn1n，將頻寬翻倍才解決了擴展性問題。

  2. 2023-2024 (Trn2)：Project Rainier 的豪賭
    這是轉捩點。AWS 意識到光靠「便宜」沒用，必須證明能跑「世界級模型」。

    • 關鍵戰役： 與 Anthropic 結盟，將 Claude 的訓練轉移到 Trainium2 上。這不僅是商業上的綁定，更是技術上的生死狀——AWS 必須證明 Trainium2 的集群能夠跑得動世界級的 Claude 模型。

    • UltraCluster： 建構能容納數萬顆晶片的集群，證明其具備訓練 GPT-4 等級模型的能力。

  3. 2025 (Trn3)：技術大躍進


    在 re:Invent 2025 上，AWS 亮出 Trainium3。這是雲端業界首款 3nm AI 加速器，效能暴增 4.4 倍，並針對 Transformer 架構進行極致「特化」。

不對稱的戰爭：Trainium 可以成為下一個 TPU嗎？

那麼最近Google 的 TPU 已經證明了自研晶片可以搶下巨大市佔，那麼AWS的Trainium可以照著做嗎？

答案是否定的。

這並不是因為 AWS 的工程師不夠努力，而是因為這兩家公司在打一場「不對稱的戰爭」。

1. 時間的複利效應：10年的領先 vs. 3年的追趕

晶片設計沒有捷徑，經驗是無法跳級的。

  • Google TPU (先行者)： Google 早在 2013 年就意識到 AI 運算瓶頸，並於 2016 年推出 TPU v1。至今已迭代至第 7 代 (TPU v7 Ironwood)。這 10 年間，Google 針對自家的 TensorFlow 框架和內部業務（搜尋、YouTube、Gmail）進行了無數次的優化。

  • AWS Trainium (追趕者)： AWS 直到 2018 年收購 Annapurna Labs 才認真投入，2021 年才推出第一代產品。

  • 結論： Google 已經踩過了 AWS 現在正在踩的所有坑。當 AWS 終於推出一代成熟產品時，Google 往往已經在部署下一代架構了。

2. 架構設計：專用手術刀 vs. 通用瑞士刀

  • TPU (手術刀)： Google 的設計哲學極端且專注。TPU 採用巨大的「脈動陣列 (Systolic Arrays)」架構。

    • 結果： TPU 的模型算力利用率 (MFU) 可達 80% 以上。這意味著它標榜的算力，絕大部分是真的被用到的。

  • Trainium (瑞士刀)： AWS 為了滿足各種租賃客戶的需求，設計上比較「貪心」。它試圖兼顧訓練和推論，且為了配合 Anthropic 的特殊需求（強化學習），犧牲了部分原始算力來換取記憶體頻寬。

    • 結果： Trainium 的 MFU 僅約 65-70%。這意味著雖然帳面數字好看，但實際跑起來，有 30% 的效能是浪費掉的。

3. 軟體生態系：TPU 的原生護城河

這是 AWS 最痛的點。

  • Google： TPU 是與 TensorFlow 和 JAX 這兩個 AI 框架「共同演化」的。底層的 XLA 編譯器會自動把程式碼轉換成 TPU 最喜歡的形狀，開發者幾乎無感。

  • AWS： Neuron SDK 相對年輕且不成熟。開發者往往需要花大量時間手動調整代碼才能跑出效能。這也是為什麼除了 Anthropic（有 AWS 派工程師駐點幫忙）之外，很少有外部客戶能順利大規模使用 Trainium。

Trainium 可以追上 TPU 嗎？

答案是：機率很低。

為什麼？

  1. 基因不同： Google 本質上是一家 AI 公司，做晶片是為了讓自己的 AI 更強；AWS 本質上是基礎設施公司，做晶片是為了讓客戶租得更便宜。AI 公司的基因在設計 AI 晶片時有天然優勢。

  2. 軟體壁壘： TPU 的軟體生態系已經累積了 10 年，這是時間堆出來的壁壘，AWS 很難在短期內透過砸錢來彌補。

Trainium 的未來角色是什麼？

雖然追不上 TPU 的「統治地位」，但 Trainium 也不會失敗。它會找到自己的利基市場：

  1. 專用工作負載： 例如 Anthropic 的強化學習（RL）訓練，Trainium 的高記憶體頻寬設計在這方面表現優異。

  2. AWS 的「防禦性武器」： 只要 Trainium 存在，Nvidia 就不敢對 AWS 漫天要價。Trainium 的存在讓 AWS 在與 Nvidia 談判時有籌碼。

  3. 成本敏感型客戶： 對於那些被鎖定在 AWS 生態系中，且對成本極度敏感的企業，Trainium 提供了一個比 Nvidia GPU 便宜 30-50% 的選擇。

不要期待 Trainium 能像 AWS Graviton（CPU）那樣橫掃市場。在 AI 晶片領域，Google TPU 是真正的「隱形冠軍」，而 Trainium 目前更像是 AWS 為了降低成本而打造的「備胎」。

在這次的re:Invent大會中，AWS 正在押注下一代晶片 Trainium4，試圖縮小差距。

不過，規格並不是重點，AWS在re:Invent大會宣佈和Nvidia的合作，才是重中之重。

第七章小結：

  • 追趕者的劣勢： 相比 Google TPU 十年的積累，AWS Trainium 起步較晚，軟體生態系（Neuron SDK）成熟度遠不及 Nvidia CUDA。

  • Trainium 的定位： 雖然難以撼動 Nvidia 的統治地位，但 Trainium 可作為「高性價比備胎」與談判籌碼，專攻對成本敏感的推理任務及特定工作負載。

  • 技術大躍進： Trainium3 試圖透過 3nm 製程與架構優化縮小差距，並透過 Anthropic 的使用來驗證效能。

第八章：「打不過就加入」，AWS和Nvidia的合作

面對 Nvidia 90% 的市佔率，AWS 在 2025 年似乎悟出了一個道理：如果不能擊敗它，那就利用它。

在 re:Invent 2025 上，AWS 丟出了一顆震撼彈：下一代 Trainium4 晶片將整合 Nvidia 的 NVLink 技術。

這標誌著 AWS 從單純的「NVIDIA 客戶」轉變為「NVIDIA 生態系的深度整合者」，同時也揭示了 NVIDIA 從「晶片供應商」轉型為「運算平台架構師」的野心。

什麼是 NVLink Fusion？

在理解協議之前，必須先了解這項技術的核心價值。

NVLink Fusion 是 NVIDIA 開發的一種機架級互連技術 (Rack-Scale Interconnect)。簡單來說，它是一條超高速的「數據高速公路」，讓數十甚至數百個 AI 晶片能像一顆超級大腦一樣協同工作。

  • 技術突破： 傳統的連接方式（如 PCIe）速度有限，導致多晶片協作時會有延遲。NVLink Fusion 允許 72 個加速器（晶片） 以 每秒 3.6 TB 的驚人速度進行點對點通訊。

  • 關鍵能力： 它支援「直接記憶體存取 (DMA)」，這意味著晶片 A 可以直接讀取晶片 B 的記憶體，完全不需要經過 CPU，消除了通訊瓶頸。

  • 意義： 這讓分散的晶片能組合成一個巨大的、統一的運算單元，這對於訓練像 GPT-4 或 Nova 這樣的大型模型至關重要。

AWS 與 NVIDIA 的協議內容

在 re:Invent 2025 上，AWS 承諾將 NVLink Fusion 技術整合進其三大核心基礎設施中：

  • 整合計畫： 未來的 Trainium4 晶片將直接內建 NVIDIA 的 NVLink 6 IP（智慧財產權），直接將 Nvidia 設計的 「NVLink Fusion Chiplet」 物理植入到 Trainium4 的晶片設計中。這就像是 AWS 的心臟裡，裝了一個 Nvidia 做的瓣膜。

  • 戰略意義： 這意味著 AWS 的自研晶片將能與 NVIDIA 的 GPU（如 Blackwell 或未來的 Vera Rubin）在同一個機架內、透過同一條高速公路混和使用。

  • 效能目標： 預計 Trainium4 的效能將是前代 Trainium3 的 6 倍。透過這個 Chiplet，Trainium4 能連接到 Vera-Rubin NVLink Switch。這允許單個機架內的 72 顆 Trainium4 晶片，以每秒 3.6 TB (總頻寬 260 TB/s) 的驚人速度進行全對全通訊。

  • AWS 將利用 NVLink Fusion 技術，將數萬顆 GPU 和 Trainium 晶片連接起來，支援數兆參數級別的模型訓練。

  • AWS 將在其「AI 工廠」解決方案中採用 NVIDIA 的 MGX 伺服器架構。這是一種標準化的伺服器設計規範，包含冷卻、供電和機殼設計，確保 AWS 的硬體能與 NVIDIA 的生態系完美相容。

為什麼雙方要這麼做？

這看似是一個雙贏的合作，但背後充滿了防禦性與進攻性的戰略考量。

對 AWS 而言：用錢買時間 (Time-to-Market)

AWS 為什麼要低頭用對手的技術？Nvidia 的公告點出了一個殘酷的現實：「自研晶片容易，自研機架很難。」

  1. 供應鏈的惡夢： 要打造一個能跑 AI 的機架，需要整合液冷、配電單元、匯流排等數十個供應商的零組件。這通常需要耗費數年時間和數十億美元的研發成本。

  2. 購買「加速包」： 透過採用 NVLink Fusion 和 MGX 架構，AWS 等於直接購買了 Nvidia 已經驗證過的基礎設施方案。這讓 AWS 能跳過繁瑣的硬體整合階段，讓 Trainium4 更快上市，解決了自研硬體最大的痛點——部署週期過長。

  3. 打破「NVIDIA 壟斷」的護城河：

    • 問題： 過去，企業如果選擇了 NVIDIA 的 GPU，就會被其強大的 NVLink 生態系綁死，因為只有 NVIDIA 的晶片能用這條高速公路。這讓 AWS 很難推銷自己的 Trainium 晶片。

    • 解法： 通過引入 NVLink，AWS 拆除了這道牆。現在，客戶可以在同一個系統中混用 NVIDIA GPU (用於訓練) 和 AWS Trainium (用於推理)，而不需要重新設計網路架構。

    • 拆牆戰術： 這打破了 Nvidia 的硬體鎖定。AWS 告訴客戶：「你不必二選一，你可以兩個都用。」這大幅降低了客戶嘗試 Trainium 的心理門檻與技術門檻。

  4. 成本優勢的最大化：

    • AWS 的自研晶片成本遠低於購買 NVIDIA GPU。如果能解決互連問題，AWS 就能以極低的價格提供高效能算力（例如用於 Nova 模型），這對價格敏感的企業極具吸引力。

  5. 基礎設施的主導權：

    • AWS 透過採用 NVIDIA 的標準（MGX 架構），讓自己成為「AI 基礎設施的最佳營運商」。無論客戶想用哪家的晶片，AWS 都能提供最佳化的環境。

瞄準「推理」這塊肥肉

AI 的運算成本中，訓練只佔 20%，推理佔 80%。AWS 的算盤是：

  • 訓練 (Training)： 讓給 Nvidia。這塊骨頭太硬，且客戶黏著度太高。

  • 推理 (Inference)： 用 Trainium 吃下來。一旦客戶習慣了混合模式，他們會發現 Trainium 在推理上的成本比 Nvidia 便宜 50%。

  • 結局： AWS 透過 NVLink 這個「木馬」，滲透進了 Nvidia 的領地，準備慢慢把利潤最豐厚的「推理市場」偷過來。

對 NVIDIA 而言 (從賣晶片轉向賣平台)

  1. 商業模式轉型：

    • NVIDIA 意識到，隨著 Google (TPU)、AWS (Trainium)、Meta (MTIA) 都在自研晶片，單純賣 GPU 的市佔率未來可能會被侵蝕。

    • 策略： NVIDIA 決定開放其最強大的武器——NVLink。通過授權這項技術，NVIDIA 從「賣鏟子的人」變成了「收過路費的人」。即使客戶用的是 AWS 的晶片，他們依然在使用 NVIDIA 的互連技術和軟體生態。

  2. 擴大生態系邊界：

    • 恐懼點： NVIDIA 最怕的不是 AWS 賣晶片，而是怕所有雲端巨頭（Hyperscalers）聯合起來搞一個「非 NVIDIA 的互連標準」（例如 AMD 牽頭的 UALink）。

    • 策略： 如果 NVIDIA 拒絕開放 NVLink，AWS 就會被迫去擁抱 UALink。

    • 結論： NVIDIA 開放 NVLink 給 Trainium，其實是一招「招安」。Jensen Huang 寧願讓出一部分「運算晶片」的市佔率給 Trainium，也要死死守住「互連標準（Interconnect）」的壟斷地位。只要資料中心還是在用 NVLink 佈線，NVIDIA 就依然是莊家。通過讓 AWS 採用 NVLink，NVIDIA 確保了其技術標準成為行業的絕對主流，邊緣化了其他競爭對手。

對市場與投資者的影響

對企業客戶的影響：

  • 選擇更多，成本更低： 未來企業不再需要被迫「二選一」。他們可以在訓練階段使用強大的 NVIDIA GPU，在推理階段無縫切換到便宜的 AWS Trainium，且都在同一個高效能網路中運行。

  • 降低遷移風險： 由於底層互連技術統一，從純 NVIDIA 架構遷移到 AWS 混合架構的技術門檻大幅降低。

  • 這就像是你可以在一台法拉利（NVIDIA GPU）裡，無縫安裝一個 Toyota 的省油引擎（Trainium）來負責怠速和滑行。客戶可以在同一個機櫃裡，用 NVIDIA 攻克最難的訓練，用 Trainium 處理海量的推論，成本大幅下降。

AWS 選擇了「打不過就加入」，透過硬體層面的妥協，換取了軟體與服務層面的生存空間。

與Google TPU不同的是，Trainium 並不試圖「殺死」NVIDIA GPU，它轉型成了 NVIDIA 生態系中「最高性價比的副駕駛」。

但這一切的硬體佈局——數百億美元的 GPU、與 Nvidia 的結盟、Trainium 的研發——最終都需要一個巨大的「出口」。

AWS 蓋了這麼多的算力基礎設施，如果沒有一個殺手級應用的話，只會不斷將市場份額送給微軟和谷歌。

對此，AWS給出了它的答案。

第八章小結：

  • 戰略妥協： AWS 宣布下一代 Trainium4 將整合 Nvidia 的 NVLink 技術，承認自研機架難度過高，選擇直接購買 Nvidia 的成熟架構以縮短上市時間。

  • 打破硬體鎖定： 此舉讓客戶能在同一機架內混用 Nvidia GPU（訓練）與 AWS Trainium（推理），降低了客戶嘗試 AWS 自研晶片的門檻。

  • 瞄準推理市場： AWS 的算盤是將高難度的訓練讓給 Nvidia，利用混合架構慢慢蠶食利潤更豐厚的推理市場。

第九章：從「各自為政」到「超級武器」

過去二十年，Amazon 奉行 Jeff Bezos 的「兩個披薩原則 (Two-Pizza Teams)」——每個團隊都要小到兩個披薩能餵飽，並且像獨立創業公司一樣運作。

這導致了一個奇怪的現象：AWS、Amazon 電商 (Retail)、Alexa 和 Prime Video 就像是四家完全不同的公司，老死不相往來。

但在近年，這種「穀倉效應」被徹底打破了。

1. 歷史的轉折：當「分治」變成「致命傷」

要理解這個轉變，我們得回到 2015 年。那時候，Alexa 團隊在波士頓閉門造車，用著自己的一套 AI 軟體；Amazon 電商團隊在西雅圖，用著另一套數據中心；而 AWS 正在向 Netflix 兜售雲端服務，卻發現自家人根本不買帳。

這種混亂在 AI 時代變成了致命傷。

當 ChatGPT 出現時，微軟迅速整合了 OpenAI 的能力進入 Office 和 Bing。而 Amazon 呢？Alexa 聽不懂人話，因為它還跑在十年前的舊架構上；AWS 有晶片，但電商團隊不敢用。

Jassy 意識到：如果 Amazon 繼續分裂，就會被各個擊破。於是，一道死命令下達了：

Amazon 的所有部門，必須成為 AWS 的「零號客戶 (Customer Zero)」。

2. Rufus：8 萬顆晶片的豪賭

還記得我們在早前提到的 Trainium 晶片嗎？外界最大的質疑是：「這晶片除了便宜，真的能扛住大流量嗎？」

AWS 不需要發白皮書來辯解，它直接搬出了 Rufus。

Rufus 是 Amazon App 裡的 AI 購物助手。在 2025 年的 Prime Day——這個地球上流量最恐怖的電商節日——Rufus 並沒有跑在 Nvidia 的昂貴顯卡上，而是跑在 AWS Trainium 和 Inferentia 晶片組成的集群上。

這就是 「一個亞馬遜」 的重點：

  • AWS 負責造晶片（工廠）。

  • Amazon 電商 負責提供全世界最複雜的戰場（試驗場）。

  • 結果： 成本降低了 4.5 倍，且扛住了每分鐘 300 萬個 Token 的吞吐量。

當 AWS 的銷售員現在去向銀行推銷 Trainium 時，他們不再說「這晶片理論上很快」，而是說：「它撐過了 Prime Day，你的銀行交易量能比 Amazon 還大嗎？」

3. Alexa+ 的換腦手術

多年來，Alexa 就像一個被困在舊時代的管家，只能聽懂簡單的指令。

在 2025 年，Amazon 終於狠下心來，廢棄了 Alexa 累積十年的舊代碼，將其大腦完全移植到了 Amazon Bedrock 平台上，並換上了統一的 Nova 模型。

現在，當你在家裡問 Alexa+ 天氣時，它調用的底層 AI 能力，和你在公司用 AWS 寫程式時調用的能力，是完全同一套。

Amazon 終於將消費端（Alexa）和企業端（AWS）的技術棧打通了。

4. 21,000 個 AI 代理人的秘密軍團

re:Invent 2025 的廣告牌上寫著「Agentic AI (代理人 AI)」，這聽起來很像行銷術語。但 Amazon 隨後揭露的一個數字，讓所有人閉上了嘴。

Amazon 宣布，他們內部已經部署了約 21,000 個 AI Agents。

在三巨頭中，微軟有最好的軟體（Office），Google 有最好的數據（Search），而 Amazon 擁有真實的物理世界運營經驗。

第十章：終局之戰 (上)——用 AI 償還三十年的技術債

在矽谷，每個人都在談論未來的 AI Agent 能做什麼；但在華爾街和倫敦金融城，CIO 們更頭痛的是過去 30 年留下的爛攤子。

AWS 看準了這個巨大的落差，推出了 AWS Transform。這不僅僅是一個新產品，它是 AWS 為了鎖定全球財富 500 強企業所設下的技術。

痛點：被困在時光膠囊裡的巨頭

要理解 AWS Transform 的價值，首先要理解大企業的絕望。

  • 30 年前的老房子： 全球銀行交易的 70%、航空公司的訂票系統、保險公司的理賠核心，至今仍運行在 Mainframe (大型主機) 上，使用的是 COBOL 這種連大學都不教的古董語言。還有無數企業跑在已經停止維護的舊版 Windows Server 和 .NET Framework 上。

  • AI 的絕緣體： 這些系統就像是一棟沒有插座、沒有網路線的百年老宅。你想用最新的 AI 模型（如 Claude 或 GPT-4）來優化業務？抱歉，這些舊系統根本無法對接現代化的 API。

  • 人才斷層的危機： 懂 COBOL 的工程師大多已經退休甚至過世了。企業不敢動這些代碼，因為「一動就崩，崩了沒人會修」。這就是所謂的「技術債 (Technical Debt)」，它像癌症一樣吞噬著企業的創新能力。

解法：AWS Transform——不是「工具」，是「工頭」

1. AI Agent 的降維打擊

AWS Transform 是一個 「代理人 (Agentic AI)」。它不只是回答問題，它會行動。

它會閱讀你那幾百萬行沒人看得懂的舊代碼，理解邏輯，然後將其重寫為現代語言（如將 COBOL 轉為 Java，或將舊版 Windows .NET 轉為 Linux 運行的 .NET Core）。

AWS Transform 不是讓你的工程師用 AI，而是派 AI 替代你的工程師。

  • 分析 (Analyze)： AI Agent 會閱讀你那幾百萬行、沒人看得懂的舊代碼，理解其中的業務邏輯（Business Logic）。

  • 重寫 (Refactor)： 它不只是翻譯（比如把 COBOL 翻成 Java），它會進行現代化重構。它會把單體架構（Monolith）拆解成微服務（Microservices）。

  • 驗證 (Validate)： 這是最關鍵的一步。AI 會自動生成測試用例，確保新寫出來的 Java 代碼跑出來的結果，跟舊的 COBOL 代碼一模一樣。

2. 驚人的效率數據

根據 re:Invent 2025 的數據，AWS Transform 已經分析了超過 11 億行的程式碼。

  • 案例： 加拿大航空 (Air Canada) 利用這項技術，將原本需要數個月的人工遷移工作，縮短到了幾天。

  • 意義： 這意味著企業現代化的時間成本被壓縮了 90% 以上。原本要花 5 年、耗資數億美元的「數位轉型」，現在可能只需要 6 個月。

產品矩陣深度解析：針對三大技術債的精準打擊

AWS Transform 不是一個通用工具，而是分化為三個針對特定「舊時代遺毒」的殺手鐧：

  1. AWS Transform for Windows (微軟稅收割機)
    這是 AWS 對 Microsoft Azure 的直接進攻，目標是移除昂貴的 Windows/SQL Server 授權費（即「微軟稅」）。

    • 技術細節：

      • 應用層： 自動將舊版 .NET Framework (僅限 Windows) 重寫為 .NET (Core) (跨平台)。這讓應用程式可以直接運行在 Linux 容器 (Amazon ECS/EKS) 上。

      • UI 層 (2025 新亮點)： 支援將古老的 ASP.NET Web Forms 自動轉換為現代化的 Blazor。這是極難自動化的部分，因為涉及前端互動邏輯的重寫。

      • 資料庫層： 自動將 SQL Server 遷移到 Amazon Aurora PostgreSQL。這不僅是數據搬運，還涉及 T-SQL 存儲過程 (Stored Procedures) 到 PL/pgSQL 的語法轉換。

    • 商業價值： 消除高達 70% 的維護與授權成本。

  2. AWS Transform for Mainframe (銀行核心的開膛手)
    這是針對金融、保險業核心系統（通常運行在 IBM 主機上的 COBOL/PL1）的解決方案。

    • 技術難點： 這些系統通常沒有文檔，最初的開發者已經退休或過世。

    • AI 解法：

      • 逆向工程： AI Agent 通過閱讀二進制代碼或源碼，反向生成業務邏輯文檔。

      • 自動化測試規劃： 這是本次發布的亮點。AI 自動生成測試計畫，解決了大型主機遷移中「不敢動，怕改壞」的心理障礙。

  3. AWS Transform Custom (企業私有代碼的解碼器)
    這是針對企業內部「祖傳代碼」的殺手鐧，也是與通用模型最大的區別。

    • 問題： 每個大公司都有自己獨門的、不規範的代碼寫法（Internal Frameworks），通用 LLM（如 GPT-4）看不懂。

    • 解法： 利用 生成式 AI (GenAI) 進行少樣本學習 (Few-Shot Learning)。

      • 運作： 它會「閱讀」該公司過去已經成功現代化的優質代碼，學習其命名規則、架構風格。

      • 成效： 能夠自動化跨儲存庫 (Cross-repository) 的轉換，將執行時間縮短高達 80%。

這而是已經正在發生的事實

這項技術不是實驗室裡的玩具。根據 AWS 最新數據，Transform 已經分析了超過 11 億行 的程式碼。

誰在使用它？看看這些戰績：

  1. 湯森路透 (Thomson Reuters)：

    • 困境： 擁有龐大的舊版 .NET 應用程式，阻礙了創新。

    • 結果： 利用 Transform 平行處理多個現代化專案，成本降低了 30%。這比人類團隊手動重寫快了數倍。

  2. 加拿大航空 (Air Canada)：

    • 困境： 需要升級數千個 Lambda 函數，原本預計耗時數月。

    • 結果： 在 幾天內 就完成了遷移，時間與成本縮減了 80%。

  3. QAD (企業軟體商)：

    • 結果： AI 在 3 天內 就重構了 18 萬行代碼，而這項工作原本預估需要人類工程師花 2 週才能完成。

這意味著，原本要花 5 年、耗資數億美元的「數位轉型」，現在可能只需要 6 個月。

市場格局：在「翻新」賽道上的降維打擊

如果我們把 AI 寫程式的市場看作一個整體，微軟的 GitHub Copilot 無疑是目前的流量之王。

但在企業級的「舊屋翻新」這條利基賽道上，AWS Transform 正在形成一種獨特的壟斷優勢。

1. 創造 vs. 翻新：兩條完全不同的賽道

要理解 AWS 的領導地位，必須區分兩種 AI 工具：

  • 代碼助手 (Code Assistants)： 代表是 GitHub Copilot (微軟)。

    • 功能： 幫助開發者寫出 下一行 代碼。

    • 場景： 就像一個坐在你旁邊的資深工程師，你打字，它給建議。

    • 目標： 提升個人生產力。

  • 現代化代理 (Modernization Agents)： 代表是 AWS Transform。

    • 功能： 自動升級 整個專案。

    • 場景： 就像一支全自動裝修隊，你把鑰匙交給它，它通宵工作，早上交屋。

    • 目標： 消除雲端遷移的障礙。

在「助手」賽道，微軟領先；但在「代理人」賽道，尤其是針對 Mainframe 和舊版 Windows 的自動化遷移，AWS 擁有先發優勢。

2. 為什麼 AWS 能在這個領域領先？

根據市場分析，AWS Transform 目前被視為「自動化遺留系統現代化 (Automated Legacy Modernization)」領域的領導者，原因有二：

  • 針對微軟的「特洛伊木馬」：
    AWS Transform 最激進的功能之一，就是專門針對微軟的舊資產（Legacy Windows/.NET）。它能將這些原本必須跑在 Windows 上的舊程式，自動重寫成可以在 Linux 上運行的 .NET Core。

  • 微軟不可能開發一個工具來「殺死」自己的 Windows 授權收入，這給了 AWS 在這個領域完美的獨佔空間。

  • 數據優勢 (The Data Moat)：
    為什麼 AWS 的 AI 懂怎麼拆解單體架構？因為亞馬遜自己經歷過。AWS 用亞馬遜內部過去 20 年來「從單體拆分成微服務」的龐大數據訓練了這些模型。它們比任何人都更懂如何把一團亂麻的代碼梳理清楚。

AWS Transform 或許不是市面上最「熱門」的 AI 聊天機器人，但它是目前唯一能以工業化規模、自動化處理數億行「技術債」的成熟產品，這才是真正能撬動兆級美元存量市場的槓桿。

第十章小結：

  • 瞄準存量市場： AWS 推出 AWS Transform，利用 AI Agent 幫企業將老舊的 Mainframe (COBOL) 和 Windows (.NET) 系統自動重寫為現代代碼。

  • 針對性打擊： 特別針對微軟舊系統進行轉譯，旨在移除昂貴的 Windows 授權費（微軟稅），並將客戶鎖定在 AWS 的 Linux 環境中。

  • 效率革命： 案例顯示遷移時間可縮短 90%，將原本需耗時數年的數位轉型壓縮至數月，大幅降低獲客成本。

第十一章：終局之戰 (下)——信任的護城河與商業模式的重塑

但是對於金融、醫療或任何關鍵基礎設施產業的 CIO 來說，「AI 寫出 99% 正確的代碼」等於「100% 的災難」。

如果 AWS Transform 只是「生成代碼」，那它就是一個定時炸彈。

如果 AI 在重構銀行的核心交易系統時，把 > 寫成了 >=，或者遺漏了一個邊界條件檢查，後果將是數十億美元的損失。

AWS 實際上非常清楚這一點，他們解決這個問題的核心技術並不是「更好的 LLM」，而是 「自動推理 (Automated Reasoning)」 與 「閉環驗證 (Closed-Loop Verification)」。

為了讓這些保守的巨頭買單，AWS 祭出了三道防線，將 Transform 從一個「概率性的生成工具」變成一個「確定性的工程工具」。

1. 第一道防線：編譯器作為裁判

這是 AWS Transform 與一般 ChatGPT 寫代碼最大的不同。

  • 一般的 AI： 寫完代碼就丟給你，不管能不能跑。

  • AWS Transform 的代理機制： 它擁有一個內建的「沙盒環境」。當 AI 生成代碼後，它會立刻嘗試編譯（Build）。

    • 如果編譯失敗（Syntax Error），AI 會讀取錯誤訊息，自我修正，然後再試一次。

    • 這個過程會重複數次，直到代碼能夠完美通過編譯器。這消除了絕大多數低級的「語法幻覺」。

2. 第二道防線：自動推理與形式化驗證

這是 AWS 的殺手鐧，也是他們與微軟/Google 最大的技術護城河。AWS 擁有一個世界頂級的 「自動推理小組 (Automated Reasoning Group, ARG)」。

  • 什麼是形式化驗證？ 這不是用 AI「猜」代碼是否正確，而是用數學邏輯來證明代碼的正確性。AWS 將代碼轉化為數學公式，證明在所有可能的輸入情況下，程式的行為都符合預期（例如：證明這個變數永遠不會溢位，或者這個權限永遠不會外洩）。

  • 在 Transform 中的應用： AWS 利用這項技術來確保現代化後的代碼（例如從 Java 8 到 Java 17）在邏輯上與原始代碼是等價的。這不是「看起來像」，而是「數學上證明它一樣」。這對於銀行來說是至關重要的信心來源。

3. 第三道防線：強制性的「人機協作」

AWS 很聰明地不把 Transform 定位為「全自動駕駛」，而是「超級副駕駛」。

  • Pull Request 機制： Transform 輸出的結果永遠不會直接進入生產環境。它會生成一個 Pull Request (PR)。

  • 差異比對 (Diff View)： 它會清楚列出：「原本是 A，我改成了 B，原因是 C」。

  • 責任歸屬： 最終按下 Merge 按鈕的必須是人類工程師。這解決了銀行的合規問題——如果出錯，責任在於審核的人，而不是「AI 演算法」。

商業邏輯：從「賣鏟子」到「賣裝修」，再到「終身房東」

這是 AWS 商業模式的一次重大升級，也是這兩章標題「終局之戰」的含義所在。

1. 商業模式的轉變

  • 過去 (IaaS)： AWS 賣的是基礎設施（EC2, S3）。就像賣你一塊地和磚頭，你自己蓋房子。

  • 現在 (AWS Transform)： AWS 賣的是「裝修服務」。AWS 說：「你那棟老房子太破了，住得不舒服。我免費（或極低價）派 AI 機器人幫你翻新成智慧豪宅。」

想像一下，你想搬進一棟高級公寓（AWS Cloud），但你家裡的傢俱（舊代碼）太重了搬不動。

AWS Transform 就像是一家免費的搬家公司。它對你說：「只要你承諾未來住在我這，我幫你把舊傢俱翻新、打包、搬進去，搬家費極低。」

2. 終極的鎖定效應

這才是 AWS 的真正圖謀。

  • 一旦翻新，無法搬家： 當 AWS Transform 把你的 COBOL 代碼變成了 Java，這些新代碼是為了在 AWS 的環境（如 Lambda, Fargate, Aurora）上運行而優化的。這棟「新房子」的地基是 AWS 打的，管線是 AWS 接的。

  • 資料重力 (Data Gravity) 加劇： 舊系統搬上來後，隨之而來的是數十年的歷史數據。這些數據一旦進入 AWS 的數據湖（Data Lake），要想再搬走（比如搬去 Azure），成本將是天文數字。透過消滅 Windows/Oracle 授權費，將企業的 IT 預算從微軟/甲骨文手中，轉移到 AWS 的運算和資料庫收入上。

  • 長期獲利： AWS 不靠 Transform 這個工具本身賺大錢，它賺的是「翻新後」未來 20 年的雲端租金。

這極大增加了營收的可預測性。這不是一次性的交易，而是鎖定了未來兩年的經常性收入 (ARR)。

3. 利潤率的提升

過去，要幫一家銀行搬上雲端，AWS 需要派出一支昂貴的「專業服務團隊 (ProServe)」或依賴埃森哲 (Accenture) 的顧問，這些都是高成本的人力。

現在，AWS 用低成本的 AI Agent 取代了高成本的人力顧問。這大幅降低了獲客成本 (CAC)，直接提升了整體的利潤率。

市場現實與風險

儘管技術願景宏大，我們必須正視現實中的挑戰：

  1. 信任赤字：

    • 現狀： 95% 的企業 AI 專案尚未產生 ROI。企業對於讓 AI Agent 自動修改核心代碼仍心存恐懼。

    • AWS 的對策： 引入 Bedrock AgentCore 的治理功能（護欄、審計日誌），試圖用「可控性」來換取企業的「信任」。

  2. 產能危機的陰影 ：

    • 風險： AWS Transform 背後依賴龐大的推理算力。如果 AWS 的 GPU/Trainium 供應鏈再次出現 2025 年中的短缺，這個服務的響應速度和可用性將大打折扣，進而影響客戶信心。

AWS Transform 不是一個會寫詩的 AI，它是一個會幹髒活、累活的 AI 工頭。

對於亞馬遜來說，這是它維持雲端霸主地位、吞噬傳統 IT 市場份額的終局武器。

第十一章小結

  • 解決信任赤字： 為了讓銀行等保守客戶敢用 AI 改代碼，AWS 引入「自動推理」與「編譯器沙盒」進行數學級別的驗證，確保代碼邏輯正確。

  • 商業模式升級： 從單純賣基建（IaaS）轉變為賣「現代化服務」，透過免費或低價幫客戶「翻新舊屋」，換取客戶未來長期駐留在 AWS 雲端（鎖定效應）。

  • 風險與挑戰： 儘管願景宏大，但仍面臨企業對 AI 修改核心代碼的恐懼，以及若算力再次短缺可能導致服務停擺的風險。

第十二章：投資地圖——牛市與熊市的劇本

1. 市場情緒現狀：焦慮的觀望者

目前的 市場對亞馬遜處於一種極度矛盾的心理狀態，可以概括為「認同戰略，但恐懼帳單」。

  • 股價行為： 2025 年 Q3 財報後股價一度急升，隨後因公布的資本支出計畫回落。這顯示市場雖然看好 AWS 的營收反彈（+20% YoY），但被天價的支出嚇壞了。

  • 核心恐懼： 1,250 億美元的資本支出。

    • Amazon 宣布 2025 年將投入 1,250 億美元用於購買 GPU 和建設數據中心，且暗示 2026-2027 年可能更多。

    • 這導致部分季度的自由現金流 (FCF) 可能轉負，打破了 Amazon 過去作為「現金流怪獸」的投資邏輯。

  • 關鍵問題： 這筆錢是會像 2010 年建設 AWS 初期那樣帶來百倍回報？還是會像 2000 年光纖泡沫一樣，變成一堆折舊的廢鐵？

2. 牛市劇本 (The Bull Case)：Agent 經濟的基礎設施霸主

如果以下三個條件在 2026-2027 年達成，Amazon 股價有望繼續突破。

A. 產能危機解除，AWS 重奪定價權

  • 邏輯： 1,250 億美元的支出在 2026 年中轉化為實際的算力供給。Bedrock 的配額限制解除，延遲問題解決。

  • 催化劑： 那些因為缺貨而流失到 Google/Azure 的客戶（如 Epic Games），發現 AWS 的生態系整合度（Data Gravity）還是最好，開始回流。

  • 財務影響： AWS 營收成長率維持在 20% 以上，且因為供給充足，不再需要降價搶客。

B. Agent 成為企業剛需，Transform 成為殺手級應用

  • 邏輯： 企業發現 AI Agent 不再是玩具，而是能替代昂貴人力的「數位員工」。

  • 關鍵路徑： AWS Transform 成功幫助大量財富 500 強企業（銀行、保險）將老舊的 Mainframe/Windows 系統遷移上雲。這證明了 AWS 的算力投資是有回報的，而不僅僅是軍備競賽的浪費。

  • 護城河效應： 這些企業一旦使用 AWS 的 Agent 完成現代化，其核心業務邏輯將與 AWS 原生服務（Lambda, Aurora）深度綁定，形成極高的轉換成本（Switching Cost）。AWS 成功將「一次性遷移」轉化為「永久性雲端收入」。

C. Trainium 晶片成功「變現」，利潤率結構性提升

  • 邏輯： 這是牛市劇本中最暴利的一環。

  • 關鍵路徑： AWS 成功說服除了 Anthropic 以外的 20-30% 客戶，將推理工作負載（Inference）從 NVIDIA GPU 轉移到 Trainium3。

  • 財務影響： 由於自研晶片成本遠低於外購 NVIDIA GPU，AWS 的毛利率將顯著提升。這種「交叉補貼」能力讓 AWS 可以在價格戰中擊垮 Azure（依賴 NVIDIA），同時保持高利潤。

3. 熊市劇本 (The Bear Case)：資本支出的黑洞

如果以下風險在未來 18 個月內爆發，Amazon 股價可能回測。

A. 技術過早，市場過冷 (元宇宙時刻)

  • 邏輯： AWS 押注的 Agentic AI 技術太超前，就像當年的 VR 或元宇宙。

  • 風險點： 企業發現 Agent 雖然聰明，但不可控（幻覺問題）、資安風險太高。CIO 們決定暫緩部署，繼續觀望。

  • 財務災難： AWS 已經蓋好的數據中心和買好的晶片開始閒置。鉅額的折舊費用（Depreciation）開始侵蝕利潤，導致 AWS 雖然營收成長，但營業利潤（Operating Income）卻停滯甚至下滑。

B. 微軟 Azure 的「入口壟斷」

  • 邏輯： 企業 AI 的真正入口不是雲端控制台，而是員工每天打開的 Office 365 和 Teams。

  • 風險點： 微軟利用 Copilot Studio 與 Office 的無縫整合，讓企業覺得「不需要再去 AWS 設定複雜的 Agent」。Azure 憑藉 SaaS 層的優勢，向下通吃 IaaS 層。

  • 結果： AWS 被迫退守到底層，變成單純提供算力的「水電行」，失去對應用層的定價權。

C. Trainium 失敗，NVIDIA 稅負過重

  • 邏輯： 開發者生態系（CUDA）壁壘太高，Neuron SDK 難以使用。

  • 風險點： 除了 Anthropic（有戰略協議）之外，沒有其他大客戶願意使用 Trainium。客戶堅持只用 NVIDIA GPU。

  • 財務影響： AWS 被迫繼續向 NVIDIA 採購昂貴的硬體，利潤率被壓縮。自研晶片的數十億研發費用成為沉沒成本。

4. 投資者的觀察指標 (The Watchlist)

在未來幾個季度，投資者應密切關注以下三個信號，來判斷劇情是走向牛市還是熊市：

  1. AWS 營收成長率 vs. 資本支出增速：
    如果 AWS 營收成長保持在 20%附近，而資本支出增速開始放緩，這是強烈買入信號（收割期開始）。

    • 如果營收成長掉到 15% 以下，而資本支出還在狂飆，這是強烈賣出信號（效率低落）。

  2. Trainium 的外部採用率：
    不要看 Anthropic 的用量（那是買來的）。要看有沒有像 Airbnb、Uber、Snap 這種技術型公司宣布大規模採用 Trainium。如果有，代表自研晶片成功了。

  3. 自由現金流 (FCF) 的轉折點：
    市場可以容忍 1-2 個季度的負現金流，但不能容忍長期趨勢惡化。關注管理層對 2026 年現金流轉正的承諾是否兌現。

在舊世界之上，嘗試建立新秩序的亞馬遜

AWS 的反擊戰，本質上是一場關於「工作即服務 (Work as a Service)」的豪賭：

  1. 企業 AI 的價值前沿不是更好的模型，而是能運作並帶來 ROI 的 Agent。

  2. 競爭優勢在於垂直整合（擁有整個堆疊）。

  3. 變現路徑是現代化。

它賭的是，未來的企業需要的不是一個會寫詩的聊天機器人，而是一個能幹髒活、累活，能幫企業償還三十年技術債的數位工頭。

如果 AWS 贏了，它將成為企業 AI Agent 的預設基礎設施，到 2030 年每年營收增加 500-1000 億美元。

如果輸了，Agent 將淪為利基市場，AWS 則變成單純比拼價格的雲端商品供應商。它將不得不面對利潤被侵蝕、護城河被填平的平庸未來。

2025 年的 re:Invent 宣告了 AWS 全押（All-in）在這個賭注上。接下來的 18-24 個月將決定這筆賭注是會帶來豐厚回報，還是變成數十億美元的沉沒成本。

現在的亞馬遜，並水不是一個垂垂老矣的巨人，而是一個正在經歷劇烈陣痛、試圖自我革新的帝國。

作為投資者的我們，現在唯一能做的，就是屏息以待，看這場價值 1,250 億美元的賭局，最終會開出什麼樣的結果。
