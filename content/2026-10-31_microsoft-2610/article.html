四巨頭中最好的財報？財報解剖: Microsoft 微軟| 26年10月

本文目錄

  2. 重點二｜上層：Copilot從賣人頭，走向賣用量
  3. 重點三｜現金流：微軟花得比亞馬遜還兇，現金流卻是正的

  5. 結語

這大概是這一輪財報季裡，最好的一份成績單。

Azure 第一次公布美元金額：單季331.7 億美元，年增48%，比公司自己給的44% 到45% 指引高出3 個百分點以上。下一季的指引再拉到49% 到50%，市場原本只預估45% 左右。

總營收922.8 億美元，年增19%；營業利益459 億美元，年增21%；每股盈餘4.89 美元，市場預估是4.73 美元。

同一週Alphabet 和Meta 的自由現金流都轉成負數，微軟還交出186 億美元的正數。

財報公布後的兩天，股價比財報本身更能說明問題。

週四，Alphabet跌了大約13%，創下史上最大單日跌幅，市值蒸發將近5,000 億美元。

同一天ServiceNow 跌了27%，Fortinet跌了20%，軟體股又一次被AI 顛覆的恐慌拖下去。

週五輪到Amazon 和Intel。

Intel跌了將近三成，是1974 年以來最慘的一天。Nasdaq單日跌2.9%，整個10 月跌了5.3%，是2025 年3 月以來最差的一個月。

兩天下來，Nasdaq跌了大約4.2%，微軟只跌1.7%。

而且就在這兩天裡，微軟還做了一件可能嚇到市場的事。

法說會上，財務長Amy Hood 才說公司還沒有動用債券市場；隔天晚上，微軟就發行了250 億美元的公司債，這是2017 年以來第一次在美國發投資等級債。

AI 資本支出恐慌最嚴重的一週，資金選擇留在微軟。

市場用行動回答了第一個問題：所有雲端巨頭裡，微軟最穩。

但這也代表，最穩這件事已經反映在股價裡了。

接下來的問題是：資本支出再加速、公司開始借錢、OpenAI的比重越來越高，微軟還能繼續當那個避風港嗎？

先看懂新的財報結構

過去11 年，微軟的財報分成三個部門：生產力與業務流程、智慧雲端、個人運算。

那是PC 和傳統軟體時代的分法，雲端、Office、Windows和Xbox 還能分開講。

Satya Nadella 的說法是，AI讓產品之間的界線越來越模糊，舊的分類裝不下新的微軟。所以從這季開始，三個部門改成兩個：

  • 代理與基礎設施（Agents & Infra）： 營收768 億美元，占總營收83%，年增25%。包含Azure、Microsoft 365 雲端、各種AI 代理和產業解決方案。

  • 設備與消費者（Devices & Consumer）： 營收155 億美元，占17%，年減3%。包含搜尋與廣告、Xbox、Surface和Windows OEM。

微軟沒有放棄Windows 和Xbox，只是讓它們退到了幕後。

不過，設備與消費者這一塊還有54 億美元的營業利益，利益率大約35%，占全公司獲利大約12%。退到幕後的業務，每季還是穩定貢獻獲利。

在新的架構下，微軟的AI 生意可以分成上下兩層：

  • 底層是 Azure，出租算力給企業和AI 公司。

  • 上層是 Copilot 和各種 Agent，嵌進企業每天的工作流程。

下面先拆這兩層，再看撐起這一切的現金流，最後回到股價：市場到底已經替哪些事情付過錢。

重點一｜底層：Azure的 332億美元

1.1 第一次看到收銀機裡的錢

過去很多年，微軟講Azure的方式，很像只告訴你店門口排隊的人變多了，從來不說收銀機裡有多少錢。它只給成長率，讓投資人自己反推。

這季終於有金額了：單季331.7 億美元，一年前是223.8 億。

一般來說，生意做到這麼大，成長率會因為基期太高而放緩。Azure反過來，從上一季大約42% 加速到48%。

光是Azure 一年多出來的108 億美元，就占了微軟全公司營收增加金額的大約四分之三。

規模這麼大還在加速，代表AI 的算力需求是在巨大的基礎上繼續往上疊。

1.2 Azure 的定義變乾淨了

微軟在換部門的同時，也把GitHub 雲端服務、Security Copilot 這些偏應用層的軟體，從Azure 搬到了Microsoft 365 雲端。

這就像一家飯店把餐廳、SPA和會議室的收入切出去，只算客房住宿。切完之後的48%，更接近純粹的算力和基礎設施需求。

從現在開始，投資人可以直接拿這332 億美元，跟AWS 和Google Cloud 比規模、比成長、比資本回收。透明度高了，市場檢視的標準也跟著變高。

1.3 房間不夠，為什麼還能加速？

管理層這季反覆強調一句話：需求還是大於供給。

第一季的資本支出（含融資租賃）是452 億美元，低於市場預估的大約500億。原因是部分第三方機房延後交付，沒趕在季底前開出來。翻成白話：客人很多，房間還沒準備好。

這就出現一個問題：房間不夠，Azure為什麼還能超標？下一季的指引為什麼還拉得更高？

UBS 和Morgan Stanley 的分析師都在法說會上追問這件事。Hood的回答可以用一家餐廳來理解，微軟靠的是三件事：

  1. 翻桌率變高。 工程團隊在GPU、CPU 和軟體層做優化，從現有的機器裡擠出更多產能，分給客戶和Foundry。桌子沒有變多，每張桌子一天能接的客人變多了。

  2. 小菜和飲料也賣出去了。 CPU 這些傳統運算資源的變現率跟著提升。客人為了主餐來，順便把原本空著的座位和小菜也點了。

  3. 客人改點比較貴的套餐。 客戶開始用更高階的推理模型，每個token 的單價比預期高。同一張桌子坐一小時，收到的錢變多了。

所以外部供應延遲了，微軟還是交出加速的成長。

但Hood 自己也說，持續釋放效率對達成指引非常關鍵。下一季49%到50% 的指引，有一部分押在工程團隊能繼續從舊機器裡擠出產能。

這招能用多久，是 Azure指引最大的變數。

1.4 6,770 億美元的訂單：總數持平，結構在變

商業剩餘履約義務（RPO，也就是已經簽約、還沒認列成營收的訂單）是6,770 億美元，年增73%。

可是跟上一季的6,780 億相比，幾乎持平。新簽訂單金額也年減12%。

這不代表需求見頂。去年同期OpenAI 簽下大約2,500 億美元的Azure 合約，基期非常高。而且產能受限的時候，前面簽新單的速度，會被後面消化舊單的速度抵銷。

更值得看的是訂單的結構：

  • 未來 12 個月內會認列的部分，大約占 30%，年增 29%。

  • 12 個月以後才會認列的部分，年增 98%。

前者大約2,030 億美元，29%的成長剛好跟Microsoft Cloud 營收30%的成長差不多，代表短期營收有合約撐著。後者幾乎翻倍，代表訂單的期限越拉越長，也越來越集中在少數幾份超大合約上。

1.5 OpenAI：比重正在上升

這季微軟揭露，來自OpenAI 的營收大約100 億美元，占總營收大約11%。上個財年全年是241 億美元，大約占7.6%。OpenAI占微軟營收的比重，還在往上走。

OpenAI 欠微軟的應收帳款，也從6 月底的60 億美元增加到72 億美元。

市場最想知道的兩個數字，微軟還是沒拆：

  • 332 億美元的 Azure 營收裡，有多少來自 OpenAI？

  • 6,770 億美元的訂單裡，OpenAI 占多少？今年 1 月那一季，Hood 曾經說過大約 45%。

微軟也在努力證明自己不只靠OpenAI。

Foundry有超過12 萬家企業客戶，營收年增超過3 倍；非OpenAI 模型的營收成長大約10 倍；自家的MAI 模型也在追趕。

Nadella在法說會上也坦白，光靠少數幾個大型AI 客戶，撐不起長期的成長。

這些都是方向正確的訊號。可是在微軟公布Foundry 實際賺多少錢之前，11%的營收占比和持續增加的應收帳款，還是要緊盯的風險。

重點二｜上層：Copilot從賣人頭，走向賣用量

2.1 Copilot 的數字換了寫法

過去幾季，微軟都會更新Microsoft 365 Copilot 的付費席位數。這一季沒有給絕對數字，Nadella只說日活躍人數季增50%。

微軟希望市場看的指標，已經從有多少人用，換成每個人付多少錢。

證據在這裡：M365商業付費席位只成長5%，M365雲端營收卻成長18%。中間的落差來自兩個地方。

第一，每個客戶付得更多。擁有超過5 萬個Copilot 席位的大客戶數量年增8 倍，例如Volkswagen 宣布替超過33 萬名員工部署。

微軟也推出把Copilot、E5、Entra和Agent 365 打包在一起的E7 方案，已經有數千家企業買單。Copilot正在從加購選項，變成企業換約時的標準配備。

第二，會計分類的順風。

GitHub 和Security Copilot 搬進M365 雲端之後，也墊高了這一塊的成長率，傳統E3 授權的放緩被蓋掉了一部分。

2.2 席位加用量：兩個口袋

現在微軟向企業收兩種錢：

  • 按席位： 照員工人數收月費，由IT 部門編預算。這是穩定的基本盤。

  • 按用量： 企業跑複雜任務、大量呼叫Agent 時，用多少算多少，由真正創造業績的業務部門買單。這季採用按量計費的客戶數季增超過75%。

席位費是地板，用量費是天花板。只看賣了多少席位，已經看不出微軟在應用層真正的潛力。

要注意的是，微軟沒有公布用量收費的營收金額。這一塊目前只看得到客戶數，還看不到錢。

2.3 90% 走Auto Mode：一好一壞

這季有一個很值得玩味的數字：90%的Copilot 查詢走的是Auto Mode。

系統會依照任務難度、速度和成本，自動決定要用哪個模型。簡單問答用便宜的小模型，深度推理才找最貴的大模型。

好的一面： 企業根本不在乎底下跑的是OpenAI、Anthropic還是開源模型，只在乎能不能用合理的成本把事情做完。

決定任務交給哪個模型的是微軟。模型可以隨時換，負責分派任務的平台很難換。

這跟AWS 的Bedrock 是同一套邏輯。

壞的一面： Agent 365 的註冊數突破5,000 萬，GitHub上由Agent 產生的程式碼合併請求半年翻了6 倍。

可是大部分員工每天做的，還是問答、摘要和簡單的輔助。像Unilever 或Rolls-Royce 那種跨系統、全自動跑完整個流程的案例，目前還是少數。

現在Copilot 幫人寫信、做摘要的生意已經在收割，幫企業跑完整個流程的生意才剛發芽。

後者才是用量收費真正的成長空間。

重點三｜現金流：微軟花得比亞馬遜還兇，現金流卻是正的

3.1 同一週的對照

  • Alphabet： 單季資本支出513.6 億美元，自由現金流負90.7 億。

  • Meta： 資本支出349.1 億美元，自由現金流負21.2 億。

  • 微軟： 營業現金流580 億美元，年增29%，自由現金流正186 億。

3.2 微軟其實花得更快

看到這組數字，很多人會覺得微軟比較有紀律、比較省。

算一下比例就會發現：微軟這季的資本支出（含租賃）大約是營收的49%，只算現金也有43%。亞馬遜第三季大約是37%。

以營收比例來看，微軟花錢的速度比亞馬遜還快。

兩家的差別在賺錢能力。微軟每100 美元的營收，能帶進大約63 美元的營業現金流；亞馬遜大約只有21 美元。

微軟的正現金流，靠的是背後那門高利潤的軟體生意。

Microsoft 365這種訂閱制軟體，利潤高、客戶黏、現金收得快，微軟才能用自己賺的錢，撐住這種規模的AI 機房建設。

3.3 186 億美元的三個注腳

第一，時間差。

資本支出低於預期，是因為第三方產能延後。

Hood 已經說第二季的資本支出會超過500 億美元，下半年還會再加速，主要花在CPU、GPU，以及越來越貴的記憶體和儲存。

2026 年全年的資本支出大約1,700 億美元，比7 月說的1,750 億略低，延後的部分會移到2027 年上半年。

這季多出來的現金，有一部分只是晚一點付帳。

第二，租賃。

微軟官方的自由現金流，是營業現金流減掉用現金買設備的錢，這季另外還有74 億美元的融資租賃沒算進去。如果用含租賃的452 億美元去扣，自由現金流大約只剩128 億。

第三，年減。

自由現金流從一年前的257 億降到186 億，少了27%。營業現金流成長29%，資本支出成長得更快。

Hood 給的底線是：2027財年全年的自由現金流維持正數。守住正數，跟維持高自由現金流，是兩回事。

3.4 開始借錢了

財報隔天，微軟發行250 億美元的公司債，分成10 個年期，從2028 年到2066 年，信用評等AAA。

光是固定利率的部分，每年利息就大約12.8 億美元。

用AAA的信用借便宜的錢來蓋機房，是很合理的財務操作。

值得注意的是它釋放的訊號：微軟過去幾乎都用自己賺的錢投資，現在開始動用債市。 第二季的業外收支預估是負3 億美元，利息收入已經被利息支出等項目抵銷掉。

亞馬遜的長期借款一年內從656 億增加到1,731 億美元。微軟才剛踏出第一步，可是方向一樣。完全靠自己賺的錢來蓋AI機房，這個階段可能已經接近尾聲。

3.5 毛利率往下，營業利益率撐住

Microsoft Cloud 的毛利率降到66%。原因是產品組合：Azure長得太快，算力生意的毛利率天生比軟體低。

Jefferies 的Brent Thill 問：Azure以接近50% 的速度成長、雲端毛利率往下掉，微軟怎麼維持接近50% 的營業利益率？Hood的回答是：最好的方法就是營收成長。

用第二季指引的中間值粗算：營收965.5 億美元，營業成本成長26% 到27%，營業費用成長9%。

整體毛利率會從這季的68% 降到大約66%，營業利益率大約47%，略低於去年同期。

第二季的費用指引裡，也包含了最近宣布的員工自願離職方案。所以營業利益率能撐住，除了營收成長和工程效率，人事精簡也出了一份力。

再加上75% 的資本支出花在GPU、CPU這些壽命短的設備上，折舊年限短，未來幾年的折舊壓力只會越來越重。

微軟把50% 的營業利益率，綁在高成長和工程效率這兩顆引擎上。

只要其中一顆慢下來，下滑的雲端毛利率和快速增加的折舊，就會開始把利潤往下拉。

重點四｜市場現在到底買了什麼

4.1 市場其實很喜歡這份財報

只看微軟自己，財報後兩天跌了1.7%，很容易以為市場不買單。

把同一時間的市場放在旁邊，畫面就不一樣了：

  • Nasdaq 兩天跌了大約 4.2%，已經連續三週下跌。

  • 週五科技類股單日跌 4.2%。Nvidia 跌了 4.2%，Micron 跌了 5.3%，CoreWeave 跌了將近 10%。

  • 財報當晚，市場同時拿到微軟和 Alphabet 兩份成績單。隔天微軟幾乎持平，Alphabet 跌了大約 13%。

再看離52 週高點的距離。Meta和Alphabet 都跌了超過20%，等於進入熊市；Amazon跌了15%，Nvidia跌了12%。

微軟離551 美元的高點只差5% 左右。七巨頭裡，只有Apple 和微軟還撐得住。

還有一個細節很有意思：同一天ServiceNow 和Fortinet 被打成那樣，市場在怕AI 會把傳統軟體吃掉。

微軟也是軟體公司，股價卻幾乎沒受影響。

市場已經把微軟從可能被AI 顛覆的那一群拿出來，放進了AI 的贏家那一邊。

分析師的動作也一樣。目標價一路上修：TD Cowen 從625 調到650 美元，Citizens從550 調到625，UBS調到700，Bernstein調到722，Wells Fargo 調到750。

跟上一篇的亞馬遜對照更清楚。亞馬遜是盈餘預估往上、目標價往下，代表市場願意付的倍數在下降。微軟的盈餘預估和目標價都往上，股價在大跌的市場裡也站得住。

同一場AI 資本支出的恐慌，市場賣掉燒錢的，留下還能賺現金的。

4.2 當避風港，也有價格

資金躲進同一家公司，代表的是微軟和其他雲端巨頭的估值差距，一夜之間又拉大了。Alphabet跌了13%，微軟幾乎不動，兩家的本益比差距就在一天之內被拉開。

這讓市場現在對微軟的定價，押在一個很具體的假設上：微軟是唯一還能用自己賺的錢，撐住AI 機房建設的雲端巨頭。

問題是，這個假設這週已經出現第一道裂縫：250億美元的公司債。

市場這次很寬容。週五發債的消息出來，微軟跌了1.55%，大約只有Nasdaq 跌幅的一半。用AAA 的信用借便宜的錢，市場暫時接受。

可是避風港的價值，來自它跟其他人不一樣。如果下半年資本支出加速、自由現金流逼近零、發債變成常態，微軟就會越來越像Alphabet 和Meta，被當成避風港的理由也會跟著變弱。

4.3 OpenAI 這塊，比亞馬遜的Anthropic 小

當我們看亞馬遜時，需要把Anthropic 從亞馬遜的股價裡拆出來。

微軟也有一樣的問題，只是規模小很多。

去年10 月OpenAI 重組時，微軟持股大約27%，價值大約1,350 億美元，換算成每股大約18 美元，占股價3.5% 左右。

如果OpenAI 後來的估值更高，這塊可能接近2,000 億美元，也就是每股大約27 美元，占股價5% 左右。

微軟還有一點比亞馬遜乾淨：調整後的每股盈餘，本來就排除了OpenAI 的投資損益。這季OpenAI 的投資收益只有2.07 億美元，影響每股0.03 美元。所以微軟的本益比，大致就是本業的本益比。

對微軟來說，OpenAI影響最大的地方在營收和訂單，股權價值反而是次要的。

4.4 軟體股的價格，基建公司的花錢速度

微軟的市值大約3.88 兆美元，過去十二個月的本益比大約29 倍。如果2027 財年的每股盈餘落在20 美元左右，預估本益比大約26 倍。

在亞馬遜的一篇算過，亞馬遜扣掉Anthropic 之後，本業大約是20 到21 倍。

市場願意多付這幾倍，買的是兩件事：Microsoft 365 這種高利潤、高黏著度的軟體生意，以及正的自由現金流。

可是3.2 已經算過，微軟資本支出占營收的比例，已經比亞馬遜還高。

市場用軟體公司的價格，買下一家花錢速度像基礎建設公司的企業。

換成現金流來看更清楚。把第一季的自由現金流乘以4，一年大約745 億美元，自由現金流殖利率大約1.9%。把租賃算進去，大約只剩1.3%。而且下半年資本支出還會加速，所以這已經是偏樂觀的算法。

1% 多的現金流殖利率，代表市場已經先替未來好幾年的成長付了錢。

4.5 這個價格要求什麼

用一個粗略的反推來感受門檻：

  • 扣掉 OpenAI，本業大約值 3.7 兆美元。

  • 假設投資人要求每年 10% 的報酬，到 2030 年底，這部分要值大約 5.4 兆美元。

  • 如果到時候市場給 25 到 30 倍的自由現金流倍數，微軟在 2030 年一年需要賺進大約 1,800 到 2,200 億美元的自由現金流。

這大約是目前年化自由現金流的2.5 到3 倍。

要做到這件事，需要兩個條件同時成立：

  1. 營業現金流從現在一年大約 1,900 億美元，四年內成長到 4,000 億左右，每年大約成長 20%。這季的成長是 29%，看起來做得到。

  2. 資本支出在 2028 年前後停止成長，大約停在每年 2,000 億美元。

第一個條件，微軟比亞馬遜輕鬆很多：起點的現金流比較高，要求的成長也比較低。第二個條件，兩家一樣難，因為兩家的管理層都還沒給任何資訊。Hood只說下半年會加速。

微軟的門檻比亞馬遜低，市場也已經為它跨過門檻，先付了比較高的價錢。

在我看來，微軟的估值溢價，建立在它的資本支出會比其他人更早停下來的假設上。

一旦市場開始懷疑這件事，最先被拿掉的就是這個溢價。

4.6 已經反映了什麼，還沒反映什麼

把上面的拼圖放在一起，我們可以把市場對這份成績單與動作的態度，拆解為「已經買單的底氣」與「暫時寬容的潛在變數」：

市場已經買單 / 充分反映的預期

  • Azure 加速到 50% ➔ 相信，而且願意付錢（已反映）

    • 市場證據：官方指引比市場共識高出了整整 4 個百分點。這份底氣直接反應在股價上，兩天內表現比 Nasdaq 強了大約 2.5 個百分點。

  • 正自由現金流 ➔ 核心安全感（已反映）

    • 市場證據：這是資金將它當作避風港（Safe Haven）的最大理由。目前股價距離 52 週高點僅約 5%，對比 Alphabet 和 Meta 跌幅超過 20% 的慘狀，高下立判。

市場選擇寬容、尚未完全定價的變數

  • 開始借錢（發債）➔ 市場暫時接受（部分反映 / 觀望中）

    • 市場證據：發債消息出來當天，股價跌幅大約只有 Nasdaq 的一半。市場雖然有些許疑慮，但暫時選擇接受這個舉債擴張的動作。

Azure 衝到 50% 的超強增速，加上穩健的正自由現金流，讓它在科技股風暴中成為最堅固的避風港。

目前市場對其「開始借錢發債」的動作表現得相當寬容，跌幅僅有大盤的一半。

然而，這也意味著市場此時的定價是建立在「高成長能迅速消化債務」的完美假設上。

一旦後續的資本開支回報率（ROI）出現一絲鬆動，這個避風港的估值溢價就會面臨修正。

4.7 股價要往上，需要發生什麼

股價上漲有兩種來源：盈餘預估上修，或是市場願意給更高的倍數。

第一條路是盈餘上修，速度比較快：

  • 延後的第三方產能在下半年到位，Azure 衝過 50%。48% 是在產能不夠的情況下做到的，產能一到，還有往上的空間。

  • Microsoft Cloud 毛利率守在 65% 附近，沒有一路往下掉。

  • Copilot 和 Agent 的用量收費開始出現在營收數字裡。

第二條路是倍數撐住甚至回升，這並不容易，因為微軟的倍數已經不低：

  • 微軟揭露非 OpenAI 客戶的 Azure 成長，或是 OpenAI 占訂單的比例往下降。

  • 資本支出加速的同時，含租賃的自由現金流還是正數，也不需要持續發債。

  • 2027 年 7 月，管理層對 2028 財年資本支出的說法，出現成長放緩的訊號。

題材和資金流向決定股價能漲多快，Azure 50% 的成長就是題材；能不能長期抱住，要看第二條路。

4.8 什麼情況下，這個溢價會消失

  • 外部產能到位之後，Azure 沒有再加速。這代表效率紅利用完了，需求也沒有想像中強。

  • OpenAI 的營收占比和應收帳款繼續往上。

  • 雲端毛利率跌破 65%，營業利益率連續幾季下滑。

  • 下半年資本支出加速，自由現金流逼近零，發債變成常態。

  • 記憶體漲價推高 PC 售價，Windows OEM 和設備業務的衰退加速。

結語

過去市場問微軟的是：AI時代，你守不守得住？這一季，微軟回答得很漂亮。

現在市場問的是：你值得能比別人貴的價格嗎？在我看來，是值的，但Upside在哪裡，卻是個問題。

市場已經替微軟的穩付了錢。接下來股價能不能往上，要看微軟能不能證明，就算花得跟所有人一樣兇，它還是最穩的那一家。
