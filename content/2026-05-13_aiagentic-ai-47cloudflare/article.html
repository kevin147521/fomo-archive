你最近或許聽過，華爾街開始將 Cloudflare 稱為「邊緣 AI（Edge AI）的贏家」。

但如果你去詢問不同的人，你會得到截然不同的答案：有人說它是一家「資安公司（Cybersecurity）」，有人把它歸類為「網路基礎設施（Network Infrastructure）」，而 Cloudflare 官方則將自己定義為「連線雲（Connectivity Cloud）」。

為什麼一家公司會有這麼多種面貌，甚至這麼難被單一標籤定義？

想像一下你今天的早晨：你醒來，滑開手機看了一下新聞網站；接著打開電商 App，把一雙猶豫了很久的球鞋放進購物車；通勤時，你順手用 ChatGPT 幫忙整理了一份會議大綱。

在這短短一小時內，你可能已經與Cloudflare的伺服器交手了數十次，而你卻渾然不覺。

在當今的網際網路世界裡，Cloudflare 就像是空氣一樣，看不見，但無所不在。根據統計，全球有將近 20% 網站的流量，都必須經過這家公司的基礎設施。

如果 Cloudflare 當機半小時，全球會有數以百萬計的網站瞬間癱瘓，從華爾街的加密貨幣交易所，到你家巷口咖啡廳的線上點餐系統，無一倖免。

正因為它無所不在，當你打開 Cloudflare 的產品目錄時，會看到 CDN、WAF、DDoS 防護、Workers、Zero Trust、R2 甚至 AI 推論……一堆讓人眼花撩亂的科技名詞。

許多投資人研究到這裡就放棄了，因為它看起來就像個毫無章法的大雜燴。

但事實上，Cloudflare 的擴張邏輯極度嚴謹。要看懂這家公司，你必須回到歷史，看它「怎麼長出來的」。

這是一個關於「先鋪設全球網路基礎設施，然後在上面無極限疊加商業服務」的經典教科書案例。

他們在這十多年間所打下的基礎，正讓它順理成章地成為「AI 時代的神經網路」，這也是為什麼華爾街如今願意給予它極高估值，並將其視為 Edge AI 最大受惠者的真正原因。

第一章：第一階段（2010-2015）── 免費的「網路門神」與「地方快遞員」

Cloudflare 的誕生，源自於一個非常樸素的煩惱：垃圾郵件。

2004 年，兩位創辦人 Matthew Prince 和 Lee Holloway 搞了一個名為 “Project Honey Pot”（蜜罐計畫）的開源專案。

這個計畫的邏輯很簡單：他們在網路上設置許多陷阱（蜜罐），專門用來追蹤那些自動抓取電子郵件地址並發送垃圾信件的駭客程式。

幾年下來，這個計畫大獲成功，他們掌握了全球大量惡意 IP 的名單。這時，另一位共同創辦人 Michelle Zatlyn 加入了，她提出了一個想法：「既然我們已經知道壞人是誰、從哪裡，我們為什麼不直接幫網站擋住這些壞人，並把它變成一門生意？」

1.1 Cloudflare的初始業務

2010 年，Cloudflare 正式成立。在它發展的最初五年，它主要為市場提供兩項核心服務。為了方便理解，我們可以用兩個實體世界的職業來比喻：

1. 網路門神（WAF 與 DDoS 防護）

想像你在東區開了一家熱門的限量球鞋店。有一天，你的競爭對手雇了五千個小混混，把你的店門口擠得水洩不通。他們不買東西，就是站在那裡發呆，導致真正想買鞋的客人根本進不去。

在網路世界裡，這就叫做 DDoS 攻擊（分散式阻斷服務攻擊），駭客用巨大的垃圾流量癱瘓你的網站。

Cloudflare 提供的第一項服務，就是充當你店門口的「保鑣（網路門神）」。

當你把網站接入 Cloudflare 後，所有要造訪你網站的流量，都必須先經過 Cloudflare 的伺服器。Cloudflare 就像一個經驗豐富的保鑣，它會檢查每一個訪客的 ID。

如果是正常客人，請進；如果是那五千個小混混（惡意流量），Cloudflare 會直接在門外把他們攔下，確保你的網站安然無恙。

2. 地方快遞員（CDN 內容傳遞網路）

解決了安全問題，接下來是「速度」。

假設你的伺服器架設在美國紐約，但今天有一個台灣的讀者想看你的網站。每一次點擊，數據都要橫跨太平洋海底電纜，來回一趟可能需要幾百毫秒。在網路世界，超過三秒載入不出來的網頁，消費者就會直接關掉。

Cloudflare 的解法是 CDN（Content Delivery Network）。他們在台北、東京、倫敦等全球各大城市租用機房。

當台灣讀者第一次造訪紐約的網站時，Cloudflare 會把網站上的圖片、影片等靜態內容，順便「影印」一份，存放在台北的機房裡（這叫做快取 Cache）。

隔天，當第二個台灣讀者想看同一個網站時，他不需要再大老遠連線到紐約，Cloudflare 的台北機房（地方快遞員）會直接把備份好的圖片派送給他。網頁載入時間瞬間從幾百毫秒，縮短到幾毫秒。

1.2 用「免費」打造護城河

如果只是做保鑣和快遞員，Cloudflare 頂多只是一家普通的 IT 公司（當時市場上早已有 Akamai 這種老牌 CDN 巨頭）。

Cloudflare 特別的地方，在於它的定價策略。

Cloudflare 一開始就決定：將這套基礎服務，免費提供給全世界的小型網站和個人部落格。

在當時，許多人覺得這家公司瘋了。基礎設施（伺服器、頻寬）都是要燒錢的，你讓幾百萬個不賺錢的免費仔佔用你的資源，這生意怎麼做？

但 Cloudflare 看透了資安產業的本質：在網路安全的世界裡，數據（Data）就是最強的護城河。

那幾百萬個免費的小網站，根本不是在佔便宜，他們是 Cloudflare 佈建在全網的「早期預警雷達網」。

試想這個場景：一個位於俄羅斯的新型駭客組織，試圖用一種全新的手法，攻擊台灣某個不知名的免費美食部落格。當攻擊發生的那一瞬間，Cloudflare 的防護網立刻偵測到了這個異常行為，並記錄下這個駭客的 IP 與攻擊特徵。

在接下來的幾秒鐘內，Cloudflare 的 AI 系統會將這個駭客的特徵，同步更新到全球所有的機房。

這意味著什麼？這意味著當這個俄羅斯駭客轉過頭來，準備去攻擊 Cloudflare 真正付費的「大客戶」（例如紐約的華爾街銀行、大型跨國電商）時，他會發現自己已經被全網封殺了。

這就是 Cloudflare 最重要的「數據飛輪效應」（Data Flywheel）。免費客戶貢獻了龐大的攻擊數據，這些數據訓練了 Cloudflare 的防禦系統，讓防禦力變得極度強大；而極度強大的防禦力，吸引了願意捧著大把鈔票來買單的企業級客戶；企業級客戶帶來的營收，又讓 Cloudflare 有錢去全球擴建更多的機房。

1.3 破解 Cloudflare 的硬體擴張之謎

既然收了這麼多「免費仔」，他們是怎麼有錢去全世界買伺服器、蓋機房的？

這就帶出了 Cloudflare 擴張史上關鍵的一招：一開始，他們根本不「蓋」機房，而是「依附」在別人的機房裡。

AWS 的做法是花幾億美金買地蓋超級資料中心。但 Cloudflare 的做法是：

  1. 買便宜貨： 大量採購市面上最標準、最便宜的通用伺服器。

  2. 與當地電信商（ISP）互惠合作： 他們直接去找全球各地的電信商（例如台灣的中華電信）。Cloudflare 告訴電信商：「你看，我有幾百萬個免費網站的流量，你的用戶每天都要連到美國去看這些網站，害你要付很貴的海底電纜過路費。不如這樣，你免費在你的機房裡清出幾個櫃子給我放伺服器，我幫你把內容快取在當地，幫你省下龐大的跨國頻寬費！」

電信商一算發現太划算了，於是紛紛讓 Cloudflare 把伺服器「塞進」他們現有的機房裡。透過這個策略，Cloudflare 幾乎以「極低的資本支出」，在全球各大城市佈滿了伺服器節點。

透過這個策略，Cloudflare 在 2015 年左右，幾乎是以「極低的資本支出」，在全球各大城市佈滿了伺服器節點，手握全網最龐大的流量數據。他們就像是在全世界的高速公路上，都蓋好了自己的收費站與檢查哨。

（值得補充的是，這個「純依附」策略並非一成不變。隨著 Cloudflare 業務從單純的 CDN 轉向邊緣運算、儲存，特別是 2023 年後大規模部署 GPU 做 AI 推論，對機房的電力、冷卻、空間規格要求大幅提高，純粹塞進電信商機房已經不夠。

Cloudflare 近年也開始租用或建置規格更高的大型 PoP。但這個早年打下的「輕資產基礎」，讓他們在同樣的資本支出下，能比 AWS 在更多城市提供服務，這個結構性優勢至今仍然成立。）

第二章：第二階段（2017起）：把工廠搬到客戶家門口 ──「邊緣運算」的誕生

傳統的雲端巨頭（如 AWS、Google Cloud）就像是建在深山裡的「超級大工廠」。這種集中式的超級工廠有一個致命傷，那就是「物理距離帶來的延遲（Latency）」。

但要讓你真正感受到這個延遲為什麼是個問題，我們得先看一個 CDN 解決不了的場景。

2.1 一個 CDN 救不了的場景

想像你打開蝦皮搜尋一雙球鞋，網站秒速跳出「為你推薦」的清單，這雙鞋是你昨天看過的、那雙鞋是你朋友剛買的、價格還根據你的所在地顯示了當地幣別。這個畫面背後，藏著一個 CDN 解決不了的問題。

CDN 能把球鞋的「圖片」事先存在台北機房，讓你載入很快。但「為你推薦」這四個字背後的判斷，「這個用戶是誰？他昨天看了什麼？他在哪個城市？該推薦什麼？」，這些不能事先準備好，必須在你點開頁面的那一瞬間，根據你這個人即時計算出來。

過去，這種「即時個人化計算」只能在遠方的中央伺服器處理。當你在台北或香港點下搜尋按鈕時，請求要先跨海到美國維吉尼亞州的 AWS 伺服器，那邊算完「該推薦什麼」之後，再把結果跨海送回你的手機。

一來一回，將近 500 毫秒，你會覺得網站「卡了一下」。

到了 2017 年，Cloudflare 的高層看著自家遍布全球的機房（原本是用來做保鑣和快遞員的），突然靈機一動：

「既然我們在全世界每個客戶的家門口都有一個小機房，我們為什麼不直接讓開發者在這些小機房裡『寫程式』？」

這一個戰略轉折，催生了 Cloudflare 歷史上最具革命性的產品：Cloudflare Workers。

2.2 Workers 在做什麼？

還記得上面那個蝦皮的場景嗎？Workers 做的事就是：把「該推薦什麼」這個運算過程，從「美國維吉尼亞」搬到了「台北」或「香港」。

當你按下搜尋的瞬間，這個判斷直接在離你最近的 Cloudflare 機房算完，5 毫秒內結果就回到你手機上。

  • CDN 是「把預先做好的便當送到你家附近的便利商店」。

  • Workers 是「在便利商店現場開了一個小廚房，根據你今天的口味現炒一份」。

CDN 處理「靜態」的內容（圖片、影片這種事先做好的東西）；Workers 處理「動態」的運算（必須當下計算的東西，例如個人化推薦、即時翻譯、購物車計算、A/B 測試、身份驗證）。

這也是為什麼開頭那段「中午點外送，App 在 0.3 秒內算出 50 家餐廳的即時排序與個人化推薦」會成立，那種「根據你這個人、在你這個位置、用你的點餐歷史」即時算出來的結果，正是 Workers 最典型的應用場景。

2.3 為什麼這在 Cloudflare 之前做不到？

你可能會問：「為什麼 AWS 不能做這件事？」AWS 當然可以在維吉尼亞跑這些運算，但它沒有 Cloudflare 在全球 330 個城市鋪好的機房。

當 AWS 想要做「邊緣運算」時，它只能在十幾個區域中心提供服務。

而 Cloudflare 從第一天起就為了 CDN 蓋了 330 個城市節點，當 Workers 推出時，這 330 個節點同時變成了 330 個「小型運算中心」。

換句話說，Workers 是 Cloudflare 基於過去十年鋪設的物理網路，自然延伸出的第二種變現模式。這也帶出了 Workers 的另一個革命性特徵：「無伺服器（Serverless）」。

工程師不再需要管「伺服器在哪裡、有幾台、夠不夠用」，你只需要把程式碼上傳一次。

當東京的用戶發出請求時，Cloudflare 會自動在距離他最近的「東京機房」喚醒程式碼並執行；當倫敦的用戶發出請求時，倫敦機房接手。程式碼跟著使用者跑，而不是使用者跑去找程式碼。

2.4 從「單一功能」到「完整的開發者生態」

起初，Workers 只能處理簡單的輕量級任務。但 Cloudflare 的野心不止於此。為了讓開發者能把越來越多的應用程式直接建構在邊緣網路上，他們陸續把整套雲端基礎設施都搬到了邊緣。

用一個比喻來看清楚這個堆疊：Cloudflare 把這套「邊緣運算平台」蓋成了三層樓。

  1. 最底層的地基：Workers

    一個可以在 330 個城市同時執行程式碼的引擎。這是整套架構的心臟，跑在 CPU 上，處理通用運算。

  2. 中間層的水電管線：資料服務

    R2（對標 AWS S3）、D1（關聯式資料庫）、KV、Durable Objects。這層讓開發者寫的程式有資料可以讀寫，不用再大老遠連回 AWS 拿資料。

  3. 頂樓的招牌：Workers AI

    在 Workers 的基礎設施上裝了 GPU，讓開發者可以直接在邊緣節點呼叫 AI 模型（Llama、Stable Diffusion 等）。當別人在搶「誰能訓練最大的模型」時，Cloudflare 在搶「誰能讓 AI 推論離使用者最近」。

這三層的關係很簡單：Workers 是地基、資料服務是水電管線、Workers AI 是頂樓的招牌。

這意味著 Cloudflare 已經實質上成為了一家「真正的雲端運算公司」。開發者完全可以不依賴 AWS，直接在 Cloudflare 的平台上建構、運行完整的應用程式，而且這些程式天生就具備全球最低的延遲。

這對 AWS 來說是一個危險的訊號。Cloudflare 就像是在 AWS 的超級工廠外圍，建了一圈密密麻麻的「地方微型加工廠」。

那些需要極致速度、輕量化的運算任務，開發者不再需要大老遠跑去 AWS，直接在 Cloudflare 的邊緣網路上就能秒速解決。

第三章：第三階段（2020起）：疫情催化的質變 ── 從「保護網站」到「保護企業」

如果說邊緣運算是技術上的突破，那麼 2020 年爆發的 COVID-19 疫情，則是 Cloudflare 商業版圖（TAM，總體可用市場）產生爆發性擴張的催化劑。

在疫情之前，傳統企業的資訊安全邏輯叫做「城堡與護城河（Castle and Moat）」。

公司就像一座城堡，所有的員工都在城堡（辦公室）裡上班，公司的機密資料也鎖在城堡裡。資安長的工作很簡單：花大錢買很厚的硬體防火牆，把城堡包圍起來。

只要你在城堡內，你就是「自己人」；在城堡外，你就是「潛在威脅」。如果員工偶爾出差，就透過 VPN（虛擬私人網路）挖一條秘密地道連回城堡。

但 2020 年，疫情讓世界停擺了。

一夜之間，城堡空了。所有的員工散佈在各地的星巴克、家裡的沙發、甚至海外的渡假村工作。

幾千個員工同時試圖透過那條狹窄的 VPN 地道連回公司，結果就是系統全面崩潰、連線速度慢如牛車，而且只要一個員工的家用電腦中毒，駭客就能順著地道直接攻入公司總部。

傳統的企業資安架構，在遠距工作時代徹底失靈。這時，Cloudflare 帶著 Cloudflare One（零信任架構Zero Trust） 正式進軍該領域。

3.1 什麼是「零信任」？

它的核心邏輯是：

「絕對不信任任何人，始終進行驗證」。

在零信任的世界裡，沒有所謂的「城堡內部」。無論你是坐在公司總部大樓裡，還是坐在峇里島的海灘上，只要你想開啟一份公司機密文件，系統都會問你一次：「你是誰？你的設備安全嗎？你有權限看這份文件嗎？」

這是一個極具歷史意義的戰場轉移。Cloudflare 正式跨界，向 Zscaler（零信任架構的開拓者）與 Palo Alto Networks（傳統防火牆霸主）發起了挑戰。

這時你可能會問：「為什麼是 Cloudflare？它比那些傳統資安大廠有甚麼優勢嗎？」

要實現零信任，意味著員工的「每一次」點擊、每一次開啟檔案，都要經過一個雲端的「檢查哨」。

如果這個檢查哨建在遙遠的集中式資料中心，員工的上網速度就會產生嚴重的延遲（這在 IT 界被稱為「髮夾彎效應」，資料要繞一大圈才回來）。

但別忘了 Cloudflare 過去十年在做什麼。

  • 無所不在的檢查哨： 他們在全球近 300 個城市、幾乎每個人的家門口，都已經建好了邊緣機房。

  • 天生的保鑣基因： 他們原本就是世界上最專業的流量清洗中心，每天幫數百萬個網站檢查進出的封包，過濾惡意程式。

Cloudflare 只是做了一個「反向操作」：

過去，保鑣是站在「網站」前面，擋住外面的壞人；現在，他們讓保鑣站在「員工」前面，保護員工連線的安全。

當一個在家上班的員工想要連線到公司內網時，他不再需要大老遠連回公司總部。他的連線會先連到「離他家最近的 Cloudflare 機房」。

Cloudflare 會在這個機房裡，瞬間完成身分驗證、病毒掃描、權限控管。因為檢查哨就在家門口，加上 Cloudflare 專屬的網路快車道，員工不僅感覺不到安全檢查的延遲，上網速度甚至比以前用 VPN 時更快。

Cloudflare 告訴全世界的企業老闆：

「你們不需要再買昂貴的硬體防火牆，也不需要忍受難用的 VPN。把你們所有的員工連線都交給我的全球網路吧，我會讓他們上網更快，而且絕對安全。」

3.2 Zscaler 不是吃素的

看到這裡你可能會有一個疑問：零信任這個概念又不是 Cloudflare 發明的。早在 2008 年就創立的 Zscaler，才是這個領域公認的領先者。

他們十幾年來在財星 500 大企業裡深耕，客戶包含國防部、大型金融機構，護城河之深，豈是 Cloudflare 一個「半路出家」的 CDN 公司可以撼動的？

這個懷疑完全合理。事實上，如果你翻開 2024 年 Dell’Oro 的 SSE（安全服務邊緣）市佔報告，Zscaler 以 34% 的市佔遙遙領先，而 Cloudflare 甚至不在前六名的名單裡。

但華爾街真正看重的，從來不是「現在誰是第一名」，而是「誰的增長速度更快」。

而 Cloudflare 在做的事情，就是明目張膽地搶 Zscaler 的地盤。

他們甚至懶得掩飾。打開 Cloudflare 官網，你會找到一個名為「Cloudflare vs. Zscaler」的專屬頁面，裡面用超過 37 項指標逐條拆解兩家的架構、效能、部署難度、創新速度。這種等級的對標網頁，在 B2B 軟體業幾乎是「指名叫陣」的意思。

Cloudflare 的執行長 Matthew Prince 在法說會上也毫不客氣地說：「在我們與第一代零信任廠商的正面對決中，我們的勝率非常強勁。」所謂的「第一代廠商」，市場都知道他指的是誰。

至此，Cloudflare 已經從一個免費的防駭客小工具，長成了一隻橫跨「內容傳遞」、「邊緣運算」與「企業資安」的三頭巨獸。

而接下來，他們準備好要正面迎戰雲端世界真正的老大哥了。

第四章：第四階段（2021起）：向老大哥宣戰 ── 打破 AWS 的「資料過路費」

到了 2021 年，這家公司的戰略發生了根本性的轉變——它不再滿足於只做別人網站的保鑣，它決定建立自己的雲端生態系，向真正的雲端龍頭發起進攻。

當時的 Cloudflare 面臨一個戰略上的「斷點」。

他們已經鋪設了全球最快的網路，也推出了革命性的邊緣運算（Workers）。許多開發者非常喜歡在 Cloudflare 的平台上寫程式，但卻遇到了一個問題：「我的資料要存在哪裡？」

過去，全世界絕大多數的開發者都習慣把資料存在 AWS 的 S3（雲端儲存服務）裡。當開發者想用 Cloudflare 的 Workers 跑程式，並從 AWS 把資料叫出來時，AWS 就會按流量收取極為昂貴的「資料傳出費（Egress Fees）」。

這就像是 Cloudflare 蓋好了一條全世界最快的高速公路，但 AWS 卻在交流道口設了一個收費站。

只要資料還被鎖在 AWS 裡，開發者就無法完全擁抱 Cloudflare 的生態系。為了補上這最後一塊拼圖，打破 AWS 的資料綁架，Cloudflare 推出了 R2 雲端儲存服務。

4.1 什麼是「資料傳出費」？

在 AWS 的世界裡，把資料「存進去」（Ingress）是免費的，每個月的儲存費也很便宜。

但是，如果你今天想把資料「拿出來」傳給用戶，或者轉移到其他雲端平台處理，AWS 就會按流量向你收取極為昂貴的「資料傳出費」。

這就像是著名歌曲Hotel California的歌詞：「You can check out any time you like, but you can never leave」

AWS 透過便宜的儲存把你的資料「綁架」在他們的資料中心裡。因為把資料搬走的過路費太貴了，開發者最後只能妥協：「既然資料都在 AWS，那我乾脆連運算（EC2）、資料庫等其他服務，都繼續用 AWS 好了。」這就是雲端巨頭的護城河。

4.2 為什麼 Cloudflare 敢做到「零傳出費」？這不虧本嗎？

這正是最令人困惑的地方：頻寬難道不用錢嗎？Cloudflare 憑什麼不收費？答案要從兩個層面來看。

第一層是成本結構優勢。

Cloudflare 透過與全球電信商簽訂的「對等互連（Peering）」協議，大幅降低了頻寬成本。

傳統雲端巨頭（如 AWS）必須向全球電信商購買昂貴的跨國骨幹頻寬，並把成本轉嫁給客戶；但 Cloudflare 的機房早就在電信商內部，許多流量可以透過免付費或極低成本的 Peering 傳送。

當然，儲存伺服器、磁碟、電力與維運人力依然是實實在在的成本，R2 並不是「免費」這麼簡單。但因為頻寬這個最貴的變數被壓到極低，Cloudflare 在單位儲存上的總成本，確實比 AWS S3 有結構性優勢。

第二層是商業策略的選擇。

即使把所有成本算進去，Cloudflare 大幅犧牲 Egress 定價，本質上是一種「用短期獲利換長期生態綁定」的進攻姿態。

他們賭的是，只要資料被吸引到 R2，開發者接下來自然會把運算（Workers）、AI 推論（Workers AI）都搬過來。

換句話說，R2 的「零 egress」不完全是成本優勢自然導出的結果，更是一個有意識的戰略武器：用虧損（或微利）的儲存業務，換取開發者生態的入口。

4.3 這是直接挑戰 AWS 嗎？還是不同層級的競爭？

他們並不是完全地競爭。Cloudflare 並沒有打算成為一家「通用型」的雲端巨頭，他們完全無意去取代 AWS 在企業核心 IT 架構中的地位。

如果一家銀行要跑核心的帳務系統，或者企業要訓練龐大的 AI 模型、處理海量的大數據分析（Big Data），他們依然需要 AWS 這樣集中式的巨型運端平台。

Cloudflare 將競爭主戰場鎖定在「邊緣（Edge）」，而非傳統的「核心（Core）」運算。

當開發者發現把圖片、影片、前端應用的資料存在 Cloudflare R2 完全不用過路費時，資料就獲得了自由。

一旦資料自由了，開發者就會把那些「需要極致反應速度、靠近用戶」的任務（例如 Web API、即時互動應用、邊緣 AI 推論），從 AWS 搬到 Cloudflare 的平台上。

Cloudflare 是在告訴開發者：「把重活（大數據分析、核心資料庫）留在 AWS，但把所有跟用戶互動的、需要速度的『前端與邊緣任務』交給我。」

第五章：AI 時代的典範轉移 ── 為什麼 Cloudflare 押注「邊緣」？

隨著 Cloudflare 在 2021 年補齊了儲存與運算的拼圖，它已經變成了一家擁有網絡傳輸，資安，和雲端的一站式平台。

而時間來到 2026 年，這個平台迎來了下一個十年最大的變數，同時也是最大的機會：AI 推論的物理學瓶頸。

在 2023 年 ChatGPT 引爆全球 AI 熱潮時，所有人的目光都集中在同一件事：誰能訓練出最聰明的模型？OpenAI、Anthropic、Google、Meta 競相砸下數百億美元，購買成千上萬張 GPU，在沙漠裡蓋起一座座超級資料中心。

但到了 2026 年，故事變了。

5.1 推論成為主力

訓練一次 GPT-5 要耗時數月，但訓練完之後可以用上一年；而全世界的 AI 代理、AI 客服、AI 翻譯、AI 搜尋，每一秒都在產生數以億計的推論請求。

訓練是一次性的資本支出，推論是持續性的營運支出。

當全世界的企業都把 AI 嵌入產品時，推論市場的長期規模將遠遠超過訓練市場。而推論有一個訓練沒有的要求：它最好發生在離使用者較近的地方。

想像一個 2026 年的日常場景：你正在用 AI 視訊會議軟體與法國客戶開會，軟體主打「即時語音翻譯」。

如果 AI 模型架設在美國加州，你的語音要橫跨太平洋傳到加州，處理完再橫跨大西洋傳回巴黎，光是網路來回就要將近 230 毫秒。在真人對話裡，這已經足以讓雙方不斷搶話或陷入尷尬的沉默。

這是個物理問題，再強的 GPU 也救不了。

5.2 代理應用的普及

到這裡為止，我們談的都是「單次 AI 推論」的延遲問題。但 2026 年真正讓整個市場重新定價的，是另一個更大的典範轉移：代理式網路（Agentic Internet）的誕生。

過去網路上的請求絕大多數是「人」發出的，你點一下、滑一下、按一個按鈕。現在越來越多的請求是「AI 代理」發出的，它們會自主規劃、拆解目標、呼叫工具、做出決策、然後在迴圈中不斷觀察-推理-行動-反思。

一個人類使用者完成一次任務，可能產生 5 到 10 次網路請求。但一個 AI 代理完成同樣一次任務，可能產生 500 到 1000 次請求。

舉個具體例子。過去你要訂機票，你會：打開 App（1 次請求）、搜尋航班（1 次）、比較幾個結果（3-5 次）、選定付款（2 次）。總共大約 10 次請求，人類處理完畢。

現在如果你交給一個 AI 代理：它會同時查詢 5 個比價網站、讀取你過去的行程偏好、呼叫翻譯 API 理解日文的航空公司備註、查詢你行事曆的可行時段、用模型推論哪個組合最划算、再跟另一個代理協商付款方式……

光是這一次「幫你訂張機票」，背後可能是數百次次機器對機器（machine-to-machine）的 API 呼叫與模型推論。

再把這個放到企業規模：過去一家公司雇用一個客服專員；未來它可能部署一千個專門化的 AI 代理。每一個代理全天候 24 小時運作，不會疲倦、不會下班。

換句話說，代理式網路不僅帶來流量增長，更將流量級數從「人類尺度」徹底升級到「機器尺度」，整個網路的請求量可能在五到十年內放大 50 到 100 倍。

而這些機器流量有三個與人類流量截然不同的特性：

  1. 極度仰賴低延遲：代理的每一步思考都要等前一步的結果回來，延遲會被放大幾百倍。

  2. 極度仰賴安全防護：代理可能被惡意輸入劫持、可能被誘導做出有害行為、可能在無窮迴圈中吃光企業的 API 預算。

  3. 極度仰賴全球分散式運算：代理會在不同地點呼叫不同服務，沒有「單一總部」的概念。

把這三點放在一起看，你會發現一件事：代理式網路的三大需求，剛好精準對應 Cloudflare 過去十五年建立的三大能力：邊緣運算、資安防護、全球分散網路。

Cloudflare 花了十五年建成的邊緣網路，剛好是 AI 時代最需要的基礎設施。

但這個故事能不能兌現？Cloudflare 真的有本事從 AWS、Azure、Google 這些巨頭手中搶下這塊市場嗎？還是這只是華爾街的一場集體幻想？

在回答這個關鍵問題之前，我們必須先把 Cloudflare 的護城河與商業引擎看清楚。因為這些，才是支撐 Edge AI 賭局能否成立的真正底氣。

我們會在後面用一整章的篇幅，把這筆帳徹底算清楚。

第六章：究竟 Cloudflare 的護城河在哪裡？

前面我們分散介紹了 Cloudflare 發展史上的各種奇招與優勢，現在讓我們把它們整合起來，用「護城河」的框架重新審視：

如果今天有一家新創公司，或者像 Google、AWS 這樣財大氣粗的巨頭說：「我要打敗 Cloudflare！我也去全球 300 個城市租機房！」他們能成功嗎？

答案是：並沒有這麼容易。

因為 300 個超級機房只是 Cloudflare 展現肌肉的「結果」。他們在過去十幾年裡，早就悄悄挖好了四道任何人都難以跨越的護城河：

6.1 第一道護城河：與全球電信商的「互惠關係」（成本優勢與網路效應）

對手如果現在想進場，最大的難點是：他們沒有 Cloudflare 手上那「全球 20% 網站流量」作為談判籌碼。

沒有龐大的雙向流量作為互惠條件，電信商沒有動機和你簽署優惠的 Peering 協議。

即使新玩家願意砸錢自建機房，他們仍然必須支付顯著更高的跨網傳輸成本（transit fees），在單位頻寬成本結構上第一天就輸了。

這個劣勢，是無法靠資本支出一次性解決的，它需要時間累積流量、累積談判籌碼。

6.2 第二道護城河：自主研發的「一體化軟體架構」（全節點同構）

傳統的網路與資安巨頭（例如老牌的 Akamai 或某些大廠），他們的擴張方式通常是「併購」：買一家做 CDN 的公司、買一家做防火牆的公司、再買一家做邊緣運算的公司。

結果就是，他們的系統像是一個拼湊而成的系統，不同服務跑在不同的伺服器上（A 伺服器專門擋駭客，B 伺服器專門存圖片），彼此之間整合困難，運行起來非常笨重。

相反，Cloudflare 幾乎所有的核心技術都是「內部自主研發（Built from scratch）」的。

因為從第一天起就是同一批人、用同一套邏輯寫底層軟體，所以他們能做到極度輕量化整合。在 Cloudflare 的 300 個機房裡，「每一台伺服器，都能同時執行所有的任務」。

這種「一體化」帶來不少優勢。假設今天某個機房突然遭到駭客攻擊，傳統機房的 A 伺服器可能面臨服務過載，而 B 和 C 卻在旁邊閒著沒事幹。

但在 Cloudflare，所有的機器會瞬間全部變成「盾牌」來扛攻擊；等攻擊結束，又瞬間平滑切換回處理圖片和 AI 推論的工具。

這種「無伺服器且全能」的架構，必須從寫第一行程式碼的時候就決定好。那些靠併購拼湊起來的老牌大廠，系統已經太龐大複雜，根本無法打掉重練。

6.3 第三道護城河：全球最大的「免疫系統」（數據飛輪）

Cloudflare 目前處理了全球網際網路大約 20% 網站的流量。如同我們在前面提到的「俄羅斯駭客攻擊免費部落格」案例，Cloudflare 利用數百萬個免費小網站作為「早期預警雷達」，打造了全網最靈敏的免疫系統。

當任何一個邊緣節點偵測到新型攻擊，全球 300 個機房會在 0.1 秒內同步防禦特徵，讓付費的大型企業客戶免於威脅。競爭對手就算財大氣粗，花了一百億美金蓋出 300 個一模一樣的機房，他們也買不到全球 20% 網際網路的真實流量。

沒有這幾百萬個免費小網站當作「雷達」和「誘餌」，對手的 AI 防護系統就永遠缺乏足夠的數據來訓練，防禦力自然無法與 Cloudflare 的數據飛輪匹敵。

6.4 第四道護城河：開發者生態系（極高的轉換成本）

隨著 Workers（邊緣運算）和 R2（雲端儲存）的推出，全世界現在有數十萬名工程師，直接把他們公司的程式碼寫在 Cloudflare 的平台上。

一旦工程師習慣了「只要按一個鍵，我的程式就能瞬間部署到全球 300 個城市，而且速度超快、不用付資料傳出費」，他們的部份資料就再也回不去傳統的亞馬遜 AWS 了。這種「開發者習慣」和「程式碼綁定」，形成了極度強大的黏著度。

Cloudflare 的商業模式，是一個十分有趣的閉環：

他們利用「免費增值模式」換取了全網最大的流量；再用這些流量去向電信商換取「免費的網路頻寬」；同時用這些流量訓練出「資安防護網」；最後，在這張又快、又安全、成本又極低的網路上，疊加運算與 AI 服務，徹底綁定「開發者生態」。

第七章：深度拆解 Cloudflare 的商業引擎

看完 Cloudflare 的商業故事，我們回到投資人最關心的問題：這些優勢在財報上怎麼呈現？

如果你現在打開 Cloudflare 的財報，你會發現他們在美國證券交易委員會（SEC）的報表上，宣稱自己只有「單一營運部門（One Operating Segment）」。

這是因為 Cloudflare 採用典型的「登陸並擴張（Land-and-expand）」策略：客戶通常先為了一個簡單的 CDN 進來，然後越用越多。

雖然沒有官方的營收比例，但根據我們討論到的歷史演變過程，我們可以嘗試將Cloudflare的業務劃分為四個階段（Acts）。

透過2026年最新的市場數據，讓我們嘗試拆解這四大商業引擎的真實競爭態勢(營收佔比只是推算，公司並沒有透露具體數字)：

7.1 Act 1：核心地基 ── 應用與網路服務（約佔營收 50-55%）

穩定成長的現金牛

這是 Cloudflare 的老本行，包含CDN、WAF（網頁防火牆）與DDoS防護。

Cloudflare 整體營收年增高達34%，但我們必須誠實面對：這很大一部分是被新業務拉高的。

如果剝離資安與開發者平台，單看傳統的「純 CDN 與網路服務」，Cloudflare 的成長率大約落在15%到22%之間(估算數字)。

這意味著，在純 CDN 市場，成長速度並沒有整體財報看起來那麼誇張。但即使如此，Cloudflare 依然顯著領先與它產品線高度重疊的同業競爭者：

  • Akamai：身為老牌 CDN 巨頭，其 2026 年第一季傳統交付業務（Delivery）正在衰退，年減約7%。

  • Fastly：曾被譽為「Cloudflare 殺手」，主打高階即時動態內容（如紐約時報、Reddit），但其網路服務營收年增僅約11%。

為什麼 Cloudflare 的純 CDN 依然長得最快？儘管 Akamai 掌握大型傳統企業，Fastly 在特定高階效能有優勢，但 Cloudflare 依然靠著以下幾點持續侵蝕市場：

  1. 架構與覆蓋率：軟體定義的Anycast網路與全球330+城市節點，擴展性與新興市場觸及率遠勝 Akamai 的老舊硬體與 Fastly 的集中式節點。

  2. 易用性與性價比：免除冗長的企業銷售流程與複雜代碼，且純 CDN 客戶通常能順手獲得 DNS 與基礎資安防護（綑綁價值），對手難以招架。

  3. AI 流量紅利：隨著AI爬蟲與代理（Agentic）流量在全網暴增，Cloudflare 作為全球最大的反向代理網路直接受惠，抵銷了部分傳統網頁流量的疲軟。

絕對的統治力與戰略意義

根據 W3Techs 在 2026 年的數據，在所有使用 CDN 的網站中，接近80%依賴 Cloudflare。

這塊業務雖然已經過了爆發期，但它擁有極高的毛利與客戶留存率。它不僅是支撐創新的「現金牛」，更為 Cloudflare 帶來了龐大的底層流量，成為後續發展零信任與 Edge AI 最堅實的地基。

7.2 Act 2：企業資安新貴 ── Cloudflare One / 零信任架構（約佔營收 20-25%）

高速成長的第二引擎，進攻姿態下的苦戰

這塊業務主打替換企業老舊的 VPN 與硬體防火牆，是一個預計到 2029 年將達到170億美元、年複合成長率 12%至17% 的龐大市場。

但必須釐清一個現實：在這裡，Cloudflare 是「快速追趕者」，而非領導者。

市場格局：一場市佔率爭奪戰

根據 Dell’Oro Group 2024 年第三季的報告，SASE 市場由Zscaler領跑，前六大廠商（包含 Cisco、Palo Alto Networks、Broadcom、Fortinet、Netskope）合計吃下了超過7成的市場份額。在 SSE（安全服務邊緣）子市場，Zscaler 更是以 34% 遙遙領先。

Cloudflare 不在這前六名的名單中。但這個數字未必是全貌。因為市場研究機構 MarketsandMarkets 的另一份報告指出，在較窄定義的 ZTNA（零信任網路存取）市場裡，Cloudflare 被明確列為「強勢挑戰者」。

更關鍵的是移動方向：Cloudflare 在 2025 年的 Gartner SASE Magic Quadrant 中被評為「遠見者（Visionary）」，在 Forrester Zero Trust Platforms 報告中被評為「強力表現者（Strong Performer）」，且在「策略面」拿下高分。

Cloudflare 的三張王牌

面對 Zscaler 與 Palo Alto 這些老大哥，Cloudflare 憑什麼搶單？答案藏在三個維度的「結構性優勢」裡：

第一張牌：速度優勢

在 42% 的安全網頁閘道（SWG）測試場景中，Cloudflare 是最快的。

在 ZTNA 方面，Cloudflare 比 Zscaler，Netskope，Palo Alto等都快至少10%；在遠端瀏覽器隔離（RBI）場景更是比 Zscaler 快了超過一半。對員工而言，這意味著更快的登入體驗、更流暢的應用載入。

第二張牌：極具競爭力的定價

Cloudflare 的零信任方案提供50 人以下免費，按量付費大約每人每月 7 美元；Zscaler 的同類型方案則動輒每人每月數十美元起跳。

對於中型企業的 CISO 來說，這是一個「同樣的功能，帳單少一個零」的決策。

第三張牌：部署簡單

Zscaler 的部署通常需要 client 軟體或 VM，大型企業導入週期動輒半年。

Cloudflare 主打無client、無VM的瀏覽器原生體驗，對於資訊部門人力有限的中型企業或快速擴張的科技公司，這是關鍵誘因。

Zscaler 的反擊：深度與信任資產

但 Zscaler 也不是紙老虎。在兩個關鍵領域，Cloudflare 還追不上：

  1. 資安深度：在進階的資料外洩防護（DLP）與雲端存取安全代理（CASB）上，Zscaler 與 Netskope 的成熟度仍明顯領先。對於有嚴格合規要求的金融、醫療、政府部門，資安深度十分重要。

  2. 企業信任：Zscaler 耕耘財星 500 大超過十年，與 CISO 社群建立的信任關係，不是速度快就能輕易撬動的，企業資安採購是極度保守的行業。

此外，Cloudflare 在 SD-WAN 分支網路能力上，相較於 Palo Alto 或 Cisco 仍顯生嫩，這讓它在完整 SASE 標案中容易失分。

實際戰績：數字會說話

光講市佔沒感覺，我們直接看 2026年Q1 實際簽下的合約：

  • 財星 500 大國防/航太公司：3 年期、500萬美元的零信任合約。

  • 大型保險集團：5 年期、510萬美元的完整 SASE 平台承諾。

  • 百萬美元級客戶年增 73%，年貢獻超過 10 萬美元的客戶貢獻了約 72% 的營收。

  • 美元基礎淨收入留存率（DBNR）維持在 118%，意味著現有客戶平均每年多買 18% 的服務。

  • 財星 500 大滲透率已達約 42%——雖然不是每個客戶都買零信任，但這個名單池本身就是最有效的銷售漏斗。

為什麼這塊業務即使不是第一，也很重要？

投資人很容易陷入「不是龍頭就不值得投資」的思維陷阱。但對 Cloudflare 來說，零信任業務的戰略意義遠超過它目前佔營收的 20-25%：

第一，它是「平台化」

敘事的核心拼圖。沒有零信任，Cloudflare 只是一家「加速網站+擋駭客」的基建公司；有了零信任，Cloudflare 搖身一變成為「企業連線與資安的完整平台」。

第二，它是擴大客單價（Wallet Share）的槓桿

Cloudflare 的登陸-擴張模式裡，合約規模往往能從幾萬美元跳到百萬美元級。

第三，它是 Cloudflare 邊緣網路最有殺傷力的武器

這個業務完美槓桿了 Cloudflare 過去十五年砸下的 335個城市節點。

第四，它重新定義了 TAM（潛在市場規模）

管理層把 Cloudflare One 列為 2026 年 1,960億美元 TAM 預測中的關鍵支柱。換句話說，零信任業務推動了 Cloudflare 向全方位企業平台的價值升級。

7.3 Act 3：未來顛覆者 ── 開發者平台（約佔營收 15-20%）

目前爆發力最強、最被華爾街熱議的第三引擎

這塊業務包含 Workers（無伺服器邊緣運算）、R2（雲端儲存）以及 D1、KV 等資料服務。自 2017 年推出以來，已有超過 300萬名開發者使用。

2025 年第一季，Cloudflare 簽下了歷史上最大、價值超過 1億美元的合約，主要推手正是 Workers。

在繼續之前，先做一個重要的切割：本節討論的是 Workers 平台的「通用運算 + 資料」業務（也就是上一章提到的「地基」與「水電管線」兩層）。

Workers 平台上還有第三層——Workers AI（邊緣 AI 推論）——雖然技術上屬於同一個平台，但它的商業化階段、對手、估值邏輯都和 Workers + R2 完全不同。

Workers AI 承載了 Cloudflare 估值故事中最重的賭注，所以我們會在下一章單獨深入。

如同前面章節所述，R2 的核心武器「零資料傳出費（Zero Egress Fees）」正在打破 AWS 藉由高昂過路費建立的經濟護城河。對於高頻寬傳輸的企業而言，從 AWS S3 轉移到 R2，每年動輒能省下數萬美元的基礎設施成本。

雖然 R2 在深度企業功能（如 Intelligent-Tiering 等）上仍不及 AWS S3，並非完全的替代品，但其極致的性價比已經達成了戰略目的：解放資料，並成功將開發者的運算任務吸引到自家的 Workers 平台上。

這也是為什麼在 2025 年第一季，Cloudflare 能靠著 Workers 簽下歷史上最大、價值超過 1億美元合約的關鍵底氣。

但是，讀到這裡，讓我們暫停一下，問一個重要的問題：

Cloudflare的業務聽起來聽不錯的，但也聽起來不是太過頂尖。

如果 Cloudflare 的 CDN 業務已經吃下接近8成的市佔（天花板就在眼前），而零信任業務又只是「快速追趕者」（最樂觀情境也就是進入頭幾名），開發者平台雖然爆發力強勁但目前也只佔營收的 15-20%。

那麼，華爾街憑什麼願意給這家公司近 30倍的 EV/Revenue，是同業的四五倍？

答案不在 Act 1、Act 2、也不在 Act 3。

真正撐起 Cloudflare 估值的，是一個目前只佔營收個位數%、卻承載了整個「AI 時代神經網絡」敘事的第四塊業務：

Edge AI 的賭注。

第八章：Cloudflare 真正的估值支點 ── Edge AI 的佈局

Cloudflare之所以能獲得高估值，答案不在財報的任何一行。

答案藏在一個目前只佔營收個位數%、卻是整個估值故事最重的砝碼的業務裡：Edge AI Inference（邊緣 AI 推論）。

這一章我們要回答三個問題：這個市場有多大？Cloudflare 真的吃得到嗎？為什麼現在財報上看不出來？

8.1 先搞清楚：「邊緣」到底在哪裡？

當我們說「Cloudflare 做邊緣 AI」時，很多投資人會搞混一件事：Cloudflare 不是在你的手機裡跑 AI。

目前市場上所謂的「Edge AI」其實有四個層次，搞清楚差異非常重要：

第一層：裝置端（On-device）

運算直接發生在手機、筆電、汽車或感測器上。這層的優勢是極低延遲（小於 10 毫秒）、能離線運作且具備高度隱私保護。代表玩家包括 Apple 神經引擎與本地端的 Gemini Nano。

第二層：近邊緣 —— Cloudflare 的主戰場

運算部署於全球分散式節點（PoP）。延遲約在 10 到 50 毫秒之間，非常適合需要全球覆蓋、即時個人化體驗的網站應用。這裡的主要玩家正是 Cloudflare（Workers AI），以及 Akamai 或 Fastly 等業者。

第三層：區域雲端

運算位於雲端業者的在地小區域，延遲約 20 到 80 毫秒。這層主要由 AWS Local Zones 或 Azure Edge Zones 提供，適合用來處理混合式企業的工作負載。

第四層：集中式雲端

運算集中在大型超級資料中心（例如 AWS 的 us-east-1 區域）。雖然到用戶的延遲最長（通常在 50 到 200 毫秒以上），但具備龐大的算力，是大型 AI 模型訓練與複雜推論的專屬領域。

Cloudflare 的定位是第二層：「雲端的邊緣（Cloud at the Edge）」。

他們不跟 Apple 搶你手機裡的那顆晶片（那是裝置端的戰場），也不跟 AWS 搶訓練 GPT-6 的大型資料中心（那是集中式雲端的戰場）。

他們要搶的，是介於兩者之間那塊巨大的空白地帶，需要即時反應、需要全球分散、又需要比手機更強算力的那些工作負載。

這個定位為什麼重要？因為它決定了 Cloudflare 不需要打敗 AWS、甚至不需要打敗 Apple，他們只要把這個「中間層」做到第一名，就夠了。

8.2 市場有多大？為什麼所有人都在搶？

先看看數字：

  • 整體 AI 推論市場：2025 年約 1,060 億美元，預計 2030 年突破 2,550 億美元（年複合成長率接近20%）。

  • Edge AI 子市場：多份報告給出的年複合成長率落在 20-37% 的區間。

  • 關鍵趨勢：推論（Inference）的市場規模，正在快速超越訓練（Training）。這是 AI 產業最重要的結構性轉變。

在推論市場裡，Edge 部分很可能會是成長最快的一塊，原因很簡單：物理學。

想像 2027 年一個典型的應用場景：一個用 AI 代理幫你訂機票的語音助理。

你說「幫我訂下週三飛東京的機票」，AI 代理需要：查詢航班（0.3 秒）、理解你的偏好（0.2 秒）、生成回覆語音（0.3 秒）、確認付款（0.2 秒）……如果每一步都要跨越太平洋回到美國加州的資料中心處理，光是網路來回就要 3-4 秒。

這就是為什麼推論必須下沉到邊緣。

8.3 Cloudflare 的王牌（為什麼他們真的有機會？）

第一張牌：全球 335 個城市的 GPU 節點，無人能複製的基礎設施

這是 Cloudflare 過去十五年砸下的最大資本，現在終於要在 AI 時代收割成果。

基於前面提到的 Peering 網路，當 Cloudflare 將 GPU 部署到現有節點時，他們不僅擁有了邊緣算力，更繼承了「免費頻寬」的優勢。

AWS 要做到同樣的事，需要和全球數千家 ISP 重新談判合作、在數百個城市建立實體機房、再部署 GPU，保守估計需要 5-10 年和數百億美元的資本支出。而這段時間 Cloudflare 不會原地踏步。

第二張牌：Serverless 架構帶來的 GPU 使用率優勢

傳統雲端業者（包含 AWS）的 GPU 服務，使用率普遍只有 30-50%。

原因是客戶通常會「包下」一定數量的 GPU，即使沒用滿也要付錢，而閒置時段的算力就浪費了。

當一家企業想要跑 AI 模型時，他們通常會向 AWS 租用一整台配備 GPU 的虛擬主機（Instance）。這就像是企業包下了一台專車。

問題在於，企業的 AI 請求不是每分每秒都有的。半夜沒人使用服務時，這台專車就停在車庫裡閒置，但企業依然要付包車的錢，而 AWS 的這張 GPU 也無法拿去服務別人。

這導致傳統雲端的 GPU 實際運算時間（使用率）往往只有 30% 到 50%。 Cloudflare 的 Workers AI 採用完全無伺服器（Serverless）架構，在 Serverless 架構下，開發者根本不需要「租一台機器」，他們只需要把程式碼丟上去。

當世界各地的用戶發出 AI 推論請求時，Cloudflare 的系統會瞬間尋找全球網路中「當下最閒的那張 GPU」，把任務派給它。

這張 GPU 前一毫秒可能在幫 A 公司的電商網站生成推薦清單，下一毫秒立刻切換去幫 B 公司的視訊軟體做即時翻譯。

這意味著，Cloudflare 的 GPU 永遠都在工作。它們不需要等待某個特定企業的請求，而是像一個巨大的中央廚房，同時處理全網數百萬個不同客戶丟進來的零碎訂單。

透過這種極致的「多租戶共享（Multi-tenancy）」與動態分配，Cloudflare 才能把 GPU 的使用率推升到 70% 甚至 80% 以上。

同樣一顆 H100，如果 AWS 用到 40%、Cloudflare 用到 75%，Cloudflare 的單位算力成本可以比 AWS 低將近一半。對於需要大規模部署 AI 推論的企業，這是一個「無法忽視的數學題」。

第三張牌：內部自研的推論引擎（Infire）與模型壓縮技術

Cloudflare 開發了內部的推論引擎 Infire，以及 Unweight 無損壓縮系統（可以減少 22% 模型佔用空間）。

這些聽起來很技術的東西，翻譯成商業語言就是：同一顆 GPU，Cloudflare 能跑更多、跑更快。

當一家企業部署百萬級的 AI 推論請求時，這些優化帶來的成本差異會變得十分顯著。

第四張牌：代理化網路（Agentic Internet）的全面順風

2026 年 AI 代理（Agent）的興起，對 Cloudflare 而言不只是新業務，而是「全產品線」的結構性利多：

  • 安全層（Firewall for AI、AI Gateway）：代理自主且重度依賴 API，衍生出提示詞注入、越獄、無限迴圈耗資與跨系統資料外洩等新攻擊面。Cloudflare 透過 Firewall for AI（利用 Llama Guard 進行網路層提示詞檢測）與 AI Gateway（提供 LLM 呼叫的可觀測性、速率限制與即時審核），精準填補了這塊全新且高價值的資安缺口。

  • 效能層（CDN + 邊緣傳輸）：代理高度依賴「鏈式呼叫」，延遲會被嚴重放大（例如 50 步的任務若每步慢 100 毫秒，總延遲高達 5 秒）。Cloudflare 遍布 330 個城市的 Anycast 網路能確保每一跳走最短路徑，解決了致命的延遲複合效應。

  • 運算層（最大受惠者）：Workers 搭配 Durable Objects（持久化狀態管理）、Queues（任務排程）、Vectorize（向量搜尋）與 R2（儲存），構成了建構 AI 代理的完美技術堆疊。開發者只需幾十行程式碼即可全球部署，完全免除 GPU 與跨區同步等基建管理。

8.4 三個必須正視的挑戰

講了這麼多優勢，現在來潑冷水。Edge AI 這塊市場 Cloudflare 不是沒有風險，而是風險很大。

挑戰一：超大規模雲端業者（Hyperscaler）的反撲

不要以為 AWS、Azure、Google 看不到這個機會。他們全都在做：

  • AWS：有 Wavelength（電信商 5G 邊緣）、Local Zones、Outposts、Lambda@Edge。

  • Azure：有 Edge Zones、Operator Nexus、Stack Edge。

  • Google Cloud：有 Distributed Cloud Edge、Anthos for edge。

他們的優勢很現實：高度的供應鏈掌控力。

當 NVIDIA 的芯片缺貨時，NVIDIA 會先滿足巨頭的訂單，因為他們是 NVIDIA 最大的客戶，同時他們也有自研芯片。Cloudflare 只能排在後面。

此外，已經深度綁定在 AWS 生態系裡的大型企業（資料在 S3、應用在 EC2、資料庫在 RDS），要把推論工作搬到 Cloudflare 需要跨越很大的摩擦。

挑戰二：大部分推論其實還是在集中式雲端

2026 年的現實是：大部分 AI 推論的成本依然發生在集中式資料中心。原因有三個：

  1. 模型太大：GPT-5、Claude Opus、這類前沿模型需要極高的 GPU 記憶體和 NVLink 高速互連，只能在大型集中式叢集運行。

  2. 規模經濟：ChatGPT 這種級別的流量，集中式部署反而更便宜。

  3. 管理複雜度：管理幾個大型資料中心，遠比管理 335 個分散節點簡單。

所以老實說，Cloudflare 要搶的不是「全部的 AI 推論」，而是「適合分散部署、對延遲敏感、對成本敏感」的那一塊。

這一塊會有多大？樂觀估計可能佔總推論市場的 30-40%，悲觀估計可能只有 10-15%。

挑戰三：還沒變成別人付錢

Cloudflare 法說會上常常提到內部 AI 使用量暴增 600%、處理了 2,410 億個 token。這些數字很漂亮，但有一個問題：那是他們自己用的。

真正重要的數字是「外部客戶付費使用 Workers AI 的營收」，而這個數字目前並沒有被獨立揭露。

Q1 2026 推論請求量年增 4,000% 這個數字很震撼，但「請求量」不等於「營收」。 這是為什麼這塊業務目前在財報上只佔 3-7%，有用量、有客戶、有故事，但還沒變成實質的大額營收。

8.5 為什麼這塊業務才是 Cloudflare 真正的估值支點？

讀到這裡，你應該可以理解為什麼我說「CDN 和零信任決定了 Cloudflare 的下檔，但 Edge AI 決定了 Cloudflare 的上檔」。

讓我們用一個簡單的數學情境來說明： 假設 Edge AI 市場到 2030 年達到 1,500 億美元（取樂觀與保守預估的中位數）。

如果 Cloudflare 能拿下其中 10% 的市佔，那就是 150 億美元的年營收——比 Cloudflare 目前的總營收還要大 6 倍。

即使只拿下 5% 的市佔，也是 75 億美元的年營收，等於讓 Cloudflare 的營收規模翻三倍。 這就是市場願意給 Cloudflare 近 30 倍 EV/Revenue 的真正原因。

投資人買的不是現在的 Cloudflare，而是 2030 年那個可能成為 AI 時代核心基礎設施的 Cloudflare。

如果這個劇本兌現，目前的估值具備極大的上行空間；如果這個劇本失敗，目前的估值面臨嚴重的泡沫。

8.6 為什麼估值十分困難

雖然故事很美好，但我們必須誠實面對：Edge AI（特別是 Cloudflare 定位的全球可程式化邊緣網路與 AI 代理）目前仍處於一個極早期、極難量化的階段。

這也是為什麼市場對 Cloudflare 的估值始終存在巨大分歧。 具體來說，量化 Edge AI 潛力面臨五大阻礙：

  1. 應用場景仍在極早期： AI 代理和邊緣推論才剛起步。時至今日，絕大多數的生產級 AI 工作負載依然集中在超大規模雲端業者的資料中心裡。我們很難準確預估到 2028-2030 年時，「邊緣端」究竟能分到多大一塊餅。

  2. 缺乏市場規模共識： 關於「Edge AI 推論 + 代理平台」的市場規模，目前業界並沒有廣泛接受的數字，不同分析師的假設天差地遠。Cloudflare 自己簡報上的 TAM 更多是指引方向，而非精確預測。

  3. 商業化模式仍在演進： 未來到底是按推論使用量計費？還是透過高客單價的平台合約？抑或是微交易？每單位 AI 流量能帶來多少實質營收，目前仍是未知數。

  4. 採用曲線未知： 這取決於開發者和企業將應用程式從集中式轉向邊緣架構的速度。雖然 Cloudflare 釋出了強烈的定性訊號（如開發者暴增、大型合約提及 AI），但絕對營收佔比依然很小。

  5. 財報缺乏透明度： Cloudflare 目前並未將 Developer Platform 或 Workers AI 的營收獨立拆分出來，投資人只能依賴管理層的口頭評論，在有限的數據下自行建立財務模型。

因為上述因素，任何對於 2028-2030 年 Edge AI 能貢獻多少增量營收的預測，都包含了極為龐大的假設成分（涵蓋採用率、定價、競爭勝率與毛利率）。只要這些假設稍微調整，推導出來的估值就會出現天翻地覆的變化。

8.7 Edge AI 是 Cloudflare 估值敘事的最後一哩路

回到這一章開頭的三個問題：

  • 市場有多大？ 推論市場在 2030 年可能達到 2,500 億美元以上，其中 Edge 部分可能佔 30-40%。

  • Cloudflare 真的吃得到嗎？ 他們手握三張牌——全球 335 城市的基礎設施、Serverless 架構帶來的 GPU 使用率優勢、內部自研的推論引擎與壓縮技術。

  • 為什麼現在財報上看不出來？ 因為這塊業務還在「用量爆發但尚未大規模變現」的階段，藏在 Developer Platform 的營收池裡。

換句話說，CDN 和零信任決定了 Cloudflare 的下檔，但 Edge AI 決定了 Cloudflare 的上檔。

在那之前，我們得先回到地面，看看最新一季的財報，到底發生了什麼事。

第九章：最新財報告訴我們什麼？

2026年5月7日，Cloudflare公布2026年Q1財報。表面上這是一份漂亮的成績單：營收達6.398億美元，年增34%，超越市場預期；Non-GAAP每股盈餘0.25美元，高於市場預期的0.23美元；管理層同時上調全年營收與獲利指引。

但隔天開盤，股價從257美元一路跌到196美元，單日跌幅逼近24%。

明明財報超標，為什麼市場反應這麼激烈？

9.1 管理層說了什麼？市場又在擔心什麼？

執行長 Matthew Prince 在致股東信與法說會上用了明確的戰略定調：

「AI正在驅動網際網路的底層重構，以及軟體被建構與消費方式的典範轉移；這將是Cloudflare史上看過最大的順風。」

「我們持續看到AI與代理式（Agentic）工作負載在網路上快速成長，Workers開發者平台也正在被快速採用。」

這是 Cloudflare 高層對「代理式網路紅利已經開始兌現」最明確的公開表態。

更重要的是，這次公布的20%裁員（約1,100人），管理層明確定調為「轉向代理式AI優先的營運模式」。

這次裁員屬於進攻性的組織重構，旨在提早轉型以應對代理式 AI 重寫企業營運邏輯的趨勢，而非單純因應成長放緩的防守性成本削減。

但市場並不買帳。

答案藏在一個簡單的邏輯裡，當一檔股票的本益比已經預支了未來五年的樂觀情境，財報要做的不是「符合預期」，而是「繼續加碼預期」。

一旦管理層的語氣從「我們會超越」變成「我們會謹慎」，市場就會立刻重新定價。

這次修正主要來自三個訊號同時觸發：

第一，Q2與全年財測指引落在30%成長。從 Q1 的 34% 到指引的 30%，4個百分點的減速對動能投資者來說足以引發重新定價。

第二，宣布裁員20%。公司宣布裁員約 1,100 人（佔總員工數約 20%），跨所有職能與地區，目標是轉向「Agentic AI-first」營運模式。

市場短期內的疑慮很直接：過去的擴張是否過快？精簡 20% 人力後能否穩住高成長？

第三，毛利率掉到歷史低點。GAAP毛利率從一年前的 75.9% 降到 71.2%，Non-GAAP毛利率從 77.1% 降到 72.8%。

這是 Cloudflare 過去八個季度以來最低點，也是市場最在意、最需要被正確解讀的數字。

接下來，我們沿著 Cloudflare 財報最關鍵的五個重點，一條一條拆解。每一點都會同步回答兩個問題：這個數字代表什麼？對應的風險是什麼？

(重要提醒：Cloudflare 在財報中只揭露單一營收總數，不拆分產品線。本章後續關於各業務線成長率的具體數字，皆為根據管理層的定性描述與歷史軌跡所做的合理推估。)

9.2 營收成長率：減速是警訊還是成熟？

Q1整體營收年增34%至 6.398 億美元。我們直接回答標題的問題：從 34% 放緩到全年指引的 30%，到底該怎麼看？

結論是：這在「營運」上是必然的成熟，但在「股票估值」上卻是強烈的警訊。

我們必須看透 Cloudflare 目前的「營收結構換檔期」。根據市場推估，Cloudflare 佔營收過半的核心網路服務（CDN/WAF）已經進入成熟期，成長率大約落在 10% 多後段。受制於「大數法則（Law of Large Numbers）」，這頭現金牛已經很難再出現爆發性成長。

另一方面，被寄予厚望的第二引擎（Zero Trust，估算年增 40%+）與第三引擎（Developer Platform / AI，估算年增近三位數），雖然成長極快，但它們目前的「絕對金額佔比」還不夠大。

這就導致了一個尷尬的數學問題：新引擎的超高成長，還來不及完全抵銷舊引擎的基期拖累。

這就是為什麼整體營收成長率會從過去的 40% 以上，慢慢滑落到 34%，再到指引的 30%。

此外，Q4 2025 的大客戶營收年增為 42%，到 Q1 2026 降為 38%，這同樣是基期墊高後的自然現象。管理層給出 30% 的全年指引，很大一部分是SaaS業界慣用的「保守承諾、超額達成（Under-promise, over-deliver）」策略。

對應風險：青黃不接的換檔期，市場缺乏耐心

營運上，30% 的成長對一家營收規模近 25 億美元的公司來說絕對算得上優秀。但問題出在估值：華爾街給予的 30倍EV/Revenue，是假設 Cloudflare 能維持「超高速成長」。

如果 Zero Trust 的市佔搶奪戰不夠快，或者 AI 營收遲遲無法補上缺口，導致未來幾季的實際營收成長率真的跌破 30%，市場將會毫不留情地把它從「超級成長股」降級為「穩定成長股」，這中間的估值落差將會十分劇烈。

9.3 獲利能力：毛利率的真正故事

Q1 Non-GAAP毛利率72.8%，環比下降 210個基點、年比下降 130個基點。對一家宣稱自己是「高毛利軟體公司」的企業來說，這是個刺眼的數字。

但要看懂這個下滑，我們得把 Cloudflare 的毛利率拆成兩個完全不同的故事：

故事一（純軟體業務）：CDN、Zero Trust 等業務的增量毛利率接近 80%。邊際客戶上來幾乎不需要額外硬體投入，只吃頻寬與既有節點算力。

故事二（Workers AI 與 Developer Platform）：管理層明確指出，這塊業務目前毛利率「低於公司平均水準」，這是毛利率壓力的關鍵來源。這塊業務需要採購 H100/H200 GPU、部署到全球節點、付昂貴的電費，初期毛利率被壓縮是必然的物理定律，這和 2015年以前的AWS 幾乎一模一樣。

所以毛利率從 77% 掉到 72.8%，本質上是「營收組合變化（硬體投資增加）」造成的，而非「核心產品失去定價權」。

這裡就要回扣前面章節埋下的伏筆：GPU毛利率的V形反轉。這個 V形 的走法大致是：採購期（毛利率下降）→ 部署期（毛利率觸底）→ 使用率爬升期（毛利率回升）→ 規模經濟期（毛利率超過起點）。

一個極度關鍵的正面訊號是：管理層在 Q1 法說會明確表示，Cloudflare 的 GPU 使用率「接近CPU使用率，落在70-80%」。

如果這個數字能長期維持，V形 右半邊就有機會走得很陡，這也是「Serverless架構能極大化GPU效益」最強而有力的官方證據。

對應風險：AI投資吃掉獲利，且V形右半邊遲遲不來

如果毛利率繼續下探、跌破 70%，且連續兩到三季沒有止跌訊號，市場會開始質疑：是不是根本沒有足夠的外部客戶願意為 Workers AI 付費，導致昂貴的 GPU 淪為折舊負擔？一旦這個疑慮成真，Edge AI 的故事就會邏輯破滅。

9.4 大客戶數：Cloudflare 真正的命脈

如果只能看一個指標判斷 Cloudflare 的基本面，我會選大客戶相關的這組數字。

原因很簡單：Cloudflare 的商業模式核心是「先用便宜的CDN吸引開發者和中小企業，再往上推銷昂貴的Zero Trust和企業級產品」。

這個 Land and Expand 模式能不能運轉，完全看高價值客戶有沒有穩定成長。

Q1 2026 的官方數據喜憂參半：

  • 強勁的亮點：百萬美元以上交易年增73%（2024年以來最快）；五百萬美元以上客戶年增50%（Q1 新增數量等同於 2025 全年新增量）。這證明 Cloudflare 確實具備拿下大型企業核心預算的能力。

  • 隱憂的訊號：淨收入留存率（DBNR）降至118%（環比下降 2個百分點）。

如何解讀 118% 的 DBNR？管理層解釋，這是因為 Q1 的成長更多來自「新客戶強勁簽單」，稀釋了既有客戶的擴張比例。

頂尖 SaaS 公司（如巔峰期的 Datadog 或 Snowflake）的 DBNR 通常在 120% 甚至 130% 以上。118% 意味著既有客戶「加購」Zero Trust 或 AI 服務的力道，算是一個「不錯，但還可以更好」的數字。

對應風險：大客戶滲透踩煞車

如果 DBNR 持續下滑跌破 115%，且百萬美元交易年增率從 73% 大幅減速到 40% 以下，這將宣告 Cloudflare 從「CDN」向「全方位企業資安平台」的升級之路受阻。

9.5 現金流與資本支出：為 Edge AI 付的學費

很多投資人會被 GAAP 的虧損嚇到：Q1 GAAP營業虧損6,200萬美元，佔營收 10%。

「這家公司成立快 20 年了為什麼還在虧錢？」這個問題的答案在一個常被忽略的地方：股票薪酬（Stock-Based Compensation, SBC）。

科技公司在成長期會大量用股票留住人才，這在 GAAP 上被計為支出，但實際上沒有任何現金流出。把 SBC 加回去之後：

  • Q1 Non-GAAP淨利：9,400萬美元，每股稀釋盈餘 0.25美元。

  • Q1 自由現金流：8,410萬美元，佔營收 13%，去年同期是 5,290萬美元、11%。

  • 公司在 Q1 期末仍持有 4.2億美元 的現金、約當現金與可售證券。

Cloudflare 並非「沒賺錢」，他們是選擇「賺來的現金全部投下去買GPU和蓋基礎設施」。

關於資本支出強度，Q1網路CapEx佔營收9%，全年指引 14%-15%。這個比例不算低，意味著管理層仍在積極為 Edge AI 押注硬體。

這個選擇合不合理，取決於你怎麼看 Edge AI 豪賭。如果 Edge AI 的市佔戰在未來三年分出勝負，現在不加速押注基礎設施，就等於主動把桌上的籌碼推給競爭對手。

但如果 Edge AI 的推論根本沒有下沉到邊緣，那麼目前的 Capex 就是一筆巨大的沉沒成本。

值得一提的是，財務長 Thomas Seifert 在法說會上強調，依目前指引，公司的「Rule of 40」指標已經超過 46%，並有能見度在明年達到 50% 以上。Rule of 40 是 SaaS 業界檢驗「成長 + 獲利」綜合健康度的指標，超過 40% 就算優秀。

9.6 估值現況：30 倍 EV/Revenue 到底定價了什麼？

為什麼用 EV/Revenue 而非本益比？傳統的本益比（P/E Ratio）對 Cloudflare 派不上用場，因為公司還在 GAAP 虧損階段。

華爾街普遍使用「企業價值對營收比」（EV/Revenue）來評估這類公司：企業價值（市值 + 總負債 − 現金）除以營收。

目前的估值水位（以5月中數據推算）

以EV/Revenue約30倍左右。相比同業，Cloudflare 享有顯著的估值溢價。Zscaler約10倍、Akamai約5倍。Cloudflare 的估值倍數大約是 Zscaler 的三倍。

這個估值隱含了什麼假設？市場願意給予 30倍的EV/Revenue，背後隱含了一連串樂觀的假設：營收能維持 25-30% 以上的年複合成長率至少 3 到 5 年；毛利率能在 Workers AI 規模化後回升至 75% 以上；Zero Trust 業務能成功搶下市場份額；AI 推論市場爆發，且 Cloudflare 成為邊緣推論的首選。

為什麼 Cloudflare 特別難用傳統方法估值？

  1. 買的是未來敘事：目前的營收倍數中，有很大一部分實質上是在押注 Developer Platform + AI 的敘事會在未來變得極度龐大。

  2. 模型極度敏感：當一家公司未來的成長故事有很大一部分綁定在這種早期的「平台典範轉移」時，傳統的 DCF（現金流折現）模型，會對長期的終端成長率與利潤率變得極度敏感。

  3. 市場看法兩極化：投資人意見巨大分歧。樂觀者認為考慮到未來的選擇權，這個價格很合理；悲觀者則認為未來的利多已經被過度定價。

這也是為什麼 Cloudflare 往往是一檔「高波動性（High-volatility）」的股票：只要市場對 AI 採用的情緒，或是對其競爭地位的看法出現微小變化，就會引發估值倍數的劇烈震盪。

9.7 三個可能讓劇本失敗的風險

真正會改變 Cloudflare 投資決策的，只有三個風險。

風險一：Edge AI 「叫好不叫座」

反映在財報上，最大的風險就是 Cloudflare 砸了重金買 GPU、大力押注「代理式 AI 優先」的組織轉型，但外部客戶的付費意願跟不上流量成長。

如果未來兩三季管理層依然只能拿虛榮指標出來說嘴，卻遲遲無法將 Workers AI 的美元營收獨立揭露，那意味著 Cloudflare 沒能力把「流量」轉換成「錢」。.

一旦這個落差被市場認定為結構性問題，高昂的 GPU 折舊與電費會持續侵蝕毛利率。

風險二：大客戶滲透踩煞車（Zero Trust 擴張失利）

如果 Zero Trust 的市佔搶奪戰失利，DBNR跌破115%，且百萬美元大單成長顯著放緩，整個「次世代雲端平台」的論述就會鬆動。

市場會重新把它定價成「優質 CDN + 還不錯的 Zero Trust 業者」，對應的估值倍數將面臨腰斬以上的修正。

風險三：估值本身就是最大的風險

即使前兩個風險都沒發生，目前 30倍EV/Revenue 的估值，可能已經把好消息全部預支了。這意味著股價對任何「略低於預期」的訊號都會異常敏感。

9.8 小結：財報沒有給答案，但給了線索

Q1 2026 的財報沒有告訴我們 Cloudflare 一定會贏或一定會輸。它給我們的是一份清晰的信號清單：

  • 正面訊號：大客戶動能加速、$5M+ 級別客戶創紀錄、GPU使用率高達70-80%。

  • 警示訊號：營收成長率因基期因素降至 30%、毛利率因 AI 投資進入陣痛期、DBNR降至118%。

  • 未知數：20% 的大裁員能否真的轉換為 AI 代理時代的營運效率？

讀完這些訊號，投資人剩下最後一個問題：那我到底該不該買？什麼條件下該加碼或減碼？

第十章：投資決策框架 ── 拆解 30 倍估值的真相

在進入具體的投資情境之前，我們必須先確立一個共識：如何看待Cloudflare高達30倍的EV/Revenue估值？

如果我們只看Cloudflare的基本盤，一個持續成長的CDN龍頭，加上一個動能強勁的Zero Trust資安挑戰者（百萬美元大單年增率高達73%），這絕對是一家優質的SaaS公司。

但即使如此優質，在目前的市場環境下，純粹的「網路與資安」業務頂多只能撐起15到20倍的估值。

那麼，剩下的10到15倍溢價是哪來的？

答案是：市場把Cloudflare當作一張「Edge AI與代理人（Agentic）基礎設施的看漲買權（Call Option）」在定價。

這不是一張純粹的「2030年開獎的虛無彩券」，因為它的Developer Platform（Workers, R2等）今天就已經在產生真實營收。

但不可否認，你現在付出的極端溢價，是在押注它能吃下未來數年AI推論與邊緣運算的巨大紅利。

理解了這個「優質基本盤 ＋ AI買權」的雙層結構，我們才能精準評估以下三種情境的機率與風險。

10.1 三種情境：多頭 25% / 基準 55% / 空頭 20%

因為Edge AI的潛力（尤其在2028-2030年之後）極難量化，未來的可能結果範圍非常寬廣。目前的股價反映的與其說是當下的基本面，不如說是投資人對那個不確定未來的不同信念。

  • 多頭情境（機率 25%）：Zero Trust持續拿大單，AI營收爆發且獨立揭露，毛利率回升。市場徹底確信其「AI基礎設施」地位，估值維持30-35倍高水位。

  • 基準情境（機率 55%）：基本盤穩健（成長30%上下），但AI業務雷聲大雨點小，無法轉化為顯著的獨立營收。市場失去耐心，將其重新定價回一家「優質的傳統SaaS公司」，估值倍數壓縮抵銷營收成長，股價陷入死錢或回撤。

  • 空頭情境（機率 20%）：AI拖累毛利，且核心DBNR跌破115%。市場恐慌其雙線敗退，估值壓縮至10-12倍，股價面臨40%以上下行風險。

10.2 追蹤儀表板：如何檢驗「AI 買權」是否生效？

情境分析是一個動態更新的過程。每一季新財報出來，你都應該問自己：「這些數字是證明了AI買權的價值，還是戳破了幻象？」以下是六個最核心的檢驗指標：

  1. 指標一：AI相關營收是否獨立揭露

    這是檢驗「別人有沒有付錢」的唯一方法。如果未來幾季能看到明確的AI美元營收貢獻，代表商業化成功；若管理層持續只提虛榮指標，這將是故事無法兌現的嚴重紅燈。

  2. 指標二：Non-GAAP毛利率的V形拐點

    由於初期部署GPU的成本，毛利率被壓縮至72.8%是可預期的。但毛利率必須在一到兩年內緩步回升至75%以上。若連續多季跌破70%且毫無起色，代表硬體投資淪為負擔。

  3. 指標三：DBNR與百萬美元大單的雙指標動能

    DBNR應回升並維持在120%以上。若DBNR連續兩季跌破115%，代表基本盤的Land and Expand擴張引擎正在熄火，這會讓高估值失去最後的支撐。

  4. 指標四：RPO（合約在手金額）成長率

    只要RPO的年增率持續高於當季營收年增率，就意味著大單正在快速累積。

  5. 指標五：自由現金流（FCF）利潤率

    一家擴張期的公司可以容忍毛利率暫時壓縮，但絕不能失去現金流的健康度。一旦跌破10%甚至轉負，將是強烈警訊。

  6. 指標六：裁員後 18 個月的營運效率

    在未來幾個季度，我們必須看到「人均營收（Revenue per Employee）」顯著提升，否則這就只是一次美化財報的斷尾求生。

10.3 歷史參照：Salesforce、AWS、Datadog 給我們的線索

Cloudflare目前的處境——高估值、GAAP虧損、毛利率壓縮——在科技股歷史上並非首例：

  • Salesforce告訴我們：只要商業模式有真正的邊際遞減特性，一家持續虧損、DBNR約120%的SaaS公司，最終能把營業利益率推到20%以上。

  • AWS告訴我們：一家被市場認為「低毛利、高資本支出」的基礎設施業務，可能在10年後變成印鈔機。前提是「使用率爬升」與「規模經濟」必須同時成立。

  • Datadog是最直接的對照組：從單一產品擴張為平台，其EV/Revenue曾從50倍修正到12倍。短期估值壓縮幾乎是必然的，但長期能否回升，完全取決於平台化與AI轉型能否兌現。

這三個案例都是成功例子，但科技史上還有無數個「本來看起來像下一個AWS，結果變成下一個Rackspace」的殘酷案例。

10.4 最終判斷

寫到這裡，如果要把所有章節的判斷濃縮成一句話，那就是：

買進Cloudflare，本質上是買進一個「高勝率的優質基本盤」，並用極高的溢價，為它搭配了一張「2030年Edge AI平台主導權」的看漲選擇權。

Cloudflare 是一個典型的高風險、高報酬標的，而現在的修正價位，讓這個風險報酬比變得更值得認真評估。

我們必須先誠實面對一件事：30 倍 EV/Revenue 的估值下，沒有所謂的「下檔鎖死」。

即使基本盤再優質，只要市場對成長性或 AI 敘事的信心動搖，估值倍數從 30 倍壓縮到 15 倍就是腰斬，這是估值重設的數學現實，不是基本面能擋住的。

想投資 Cloudflare 的人，必須接受這個前提：你買的是一個波動劇烈的高成長故事，不是一個防禦性資產。

但接受這個前提之後，真正的問題是：現在這個價位，值不值得為這個故事下注？

為什麼上檔的想像空間很大？

第一，Edge AI 的市場槓桿

Edge AI 市場光是拿下 5%，就足以讓 Cloudflare 營收翻 3 倍(純粹推算，你可以不同意)。

而這不是開空頭支票，他們已經花了 15 年鋪完 335 個城市的節點網路，並透過與全球電信商的 Peering 協議取得結構性的成本優勢。競爭對手要從零複製這套基礎設施，保守估計需要 5-10 年與數百億美元的資本支出。

這個時間差，就是 Cloudflare 最硬的護城河。

再加上 Q1 法說會揭露的一個關鍵數字：GPU 使用率已經達到 70-80%，接近 CPU 使用率。這意味著「Serverless 架構能極大化 GPU 效益」這個最核心的假設，已經得到了官方驗證。毛利率 V 形反轉的右半邊，暫時條件是成立的。

第二，Usage-based 商業模式在 AI 時代的結構性紅利

過去半年，華爾街對 SaaS 產業最大的擔憂是：AI 代理正在侵蝕「以人頭計費（Seat-based）」的商業模式。

當一家公司用 10 個 AI 代理取代 100 個客服時，Salesforce、ServiceNow 這類按「每位使用者每月多少錢」收費的 SaaS 巨頭，理論上營收會被直接腰斬。這也是為什麼過去一年整個 SaaS 板塊的估值倍數被集體壓縮。

但 Cloudflare 從第一天起，就是一個純粹的「按用量計費（Usage-based）」模式。它收的是每秒鐘流過網路的請求數、每 GB 傳輸的資料量、每次 AI 推論的 token 數。

這個看似樸實的差異，在代理式網路時代會變成巨大的分水嶺。

當企業從「100 個員工」變成「1000 個 AI 代理」，對 Seat-based SaaS 是毀滅，但對 Cloudflare 是順風：每多一個代理在網路上運作，Cloudflare 的計費器就多跳一次。

換句話說，市場對 SaaS 的普遍擔憂，在 Cloudflare 身上完全不成立。反而，同樣一個 AI 代理化浪潮，正以結構性、不可逆的方式擴大它的收入基礎。

第三，創辦人主導 + 在同一張網路上反覆擴張 TAM 的能力

這家公司從 2010 年到現在，一直由創辦人 Matthew Prince 親自掌舵 15 年。

這在科技產業並不少見，但 Cloudflare 特別之處在於：他主導的每一次 TAM 擴張，都不是靠併購拼湊，而是在「同一張全球邊緣網路」上有機長出來的新業務。

讓我們重新回顧這條軌跡：

2010 年起家的 CDN + DDoS 防護，是把網路本身拿來賣；

2017 年的 Workers 邊緣運算，是在同一張網路上加一層可程式化；

2020 年切入的 Zero Trust 資安（Cloudflare One），是把同一張網路反過來服務企業員工而非網站；

2021 年推出的 R2 儲存，是在同一張網路上疊加資料層；

2023 年之後的 Workers AI，是在同一張網路上部署 GPU。

每一次進入新市場，表面上看起來是「跨界」，實質上都是同一張基礎設施的延伸變現。

這帶來兩個極稀有的特性：第一，每次擴張的邊際資本支出極低，不需要從零蓋新平台；第二，每條新業務線天生就具備前面累積的護城河（流量數據、Peering 成本優勢、開發者生態）。

這就是為什麼 Cloudflare 的 TAM 從 IPO 時的 320 億美元，一路擴張到管理層 2026 年指引的 1,960 億美元。六倍的成長，而不是靠併購堆出來的。

每一次 Matthew Prince 喊出新的戰略方向（免費增值、Workers、Zero Trust、R2、Workers AI），都被證明不是口號，而是在既有基礎設施上的自然延伸。

當這樣的創辦人說「AI 將是 Cloudflare 史上看過最大的順風」並押上 20% 的裁員重組整個公司時，這個訊號的含金量遠高於一般 CEO 的口頭指引。

為什麼現在這個時點值得多看一眼？

Cloudflare 剛剛大幅修正，但仔細看市場懲罰的理由之一：毛利率從 77% 掉到 72.8%。這個下跌的原因，恰恰是他們為 Edge AI 買 GPU 造成的。

換句話說，市場正在打折賣的，正是我們想押注的東西。這不代表股價不會繼續跌，短期動能投資者的恐慌可能還沒結束。

但從中期角度看，你是在「AI 故事開始變貴之前」的陣痛期進場，而不是在故事已經被完全定價之後才追高。

那麼，該買嗎？

誠實的答案是：這取決於你是哪一種投資人。

如果你同時滿足以下三個條件，那現在的修正價位是一個值得開始關注的時點：

  • 相信 AI 推論必然有一部分會向邊緣下沉，且 Cloudflare 是最有機會吃下這塊的玩家

  • 能忍受未來 12-18 個月可能 30-40%（甚至更多）的估值震盪，不會在低點恐慌出場

  • 願意用第 10.2 節的六項指標每季檢視論點是否還成立，一旦基本面破壞就果斷減碼

但如果你無法通過這三關中的任何一關，無論 Cloudflare 的技術故事多麼動人，無論護城河多麼堅固，這都不是你該碰的股票。

在 30 倍EV/Revenue的標的上，沒有「抱著不看」這個選項，持有一個你不真正相信、或不能忍受波動的高估值標的，結局通常是在最低點賣出，錯過後面的所有反彈。

如果真的要入場，也要明白這大概率是個左側交易，不會一買就大漲。

Cloudflare 不是一個「安全」的投資，它是一個典型的：上檔想像空間很大、下檔風險很實在、時點恰好因為 GPU 投資造成的短期陣痛而被打了折。

對於接受這個風險輪廓的投資人來說，這是目前美股市場上，少數的邊緣AI 基礎設施機會之一。
